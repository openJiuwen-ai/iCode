# 连接 MCP 服务器

模型上下文协议（Model Context Protocol，MCP）服务器可以为 iCode 智能体提供外部工具、提示词模板和使用说明。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中连接 HTTP 或 STDIO MCP 服务器、配置可调用的工具，以及控制是否加载提示词模板、是否将服务器使用说明加入模型上下文。

连接 MCP 服务器前，请确认服务器来源可信。服务器可能接收工具调用参数，并访问本机文件、网络服务或账号数据；其提供的提示词模板和使用说明也可能影响智能体的行为。

如果要为智能体提供用几个 Python 函数编写的工具，而无需运行服务器，参阅 [Python 扩展](./python-extensions.md)。

## 添加 MCP 服务器配置

在输入栏中输入 `/agents mcp`，打开当前智能体的“MCP”标签页。添加的服务器配置只对当前智能体生效，不会自动应用到其他智能体。

每个服务器对应一张卡片。已保存的服务器默认折叠，只显示名称；点击名称可展开或折叠。保存时如果发现问题，有问题的卡片会自动展开。要删除服务器，点击卡片上的“✕”并确认。

点击“+ 添加”可复用其他智能体的 MCP 配置。有可复用配置时，弹窗会显示服务器名称、来源智能体，以及可执行文件名或 URL 主机名。选择后，完整设置会复制到列表顶部的新卡片中并展开。副本相互独立：之后修改或删除任一智能体中的配置，都不会影响另一方。复制已禁用的配置时，副本也保持禁用。弹窗读取当前智能体配置窗口中的最新草稿，包含尚未保存的修改。

多个智能体中设置相同的同名配置会合并显示，并列出所有来源；同名但设置不同的配置则分别显示。可选配置排在前面，灰色不可选配置排在后面，两组内分别按名称排序。灰色项会说明无法添加的原因：当前智能体已有同名配置，或已有连接、工具名称前缀相同且允许工具范围重叠的配置。已禁用的配置也会参与检查。

弹窗不会连接服务器。如果加载智能体时报工具名冲突，请按错误提示调整相关服务器的工具名称前缀，或排除重叠工具。单个服务器测试成功不能排除它与其他服务器的工具名冲突。

要配置新的服务器，选择“+ 新建 MCP 配置…”。如果其他智能体没有有效的 MCP 配置，“+ 添加”会直接创建空白卡片。无效的来源配置不会提供为候选。取消弹窗不会修改配置。复制和新建的配置都通过配置页现有的“保存”流程生效。

在新建卡片中填写以下字段：

1. 填写“服务器名称”。名称用于在当前智能体的 MCP 配置中标识该服务器。同一个智能体的 MCP 配置中，服务器名称不能重复，且不区分大小写。
2. 可选填写“描述”，用于备注服务器的用途。该描述不会作为服务器使用说明提供给智能体。

HTTP 请求头值和 STDIO 环境变量值都可以使用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。环境变量名只能包含字母、数字和下划线，且不能以数字开头。

两者也可以用 `{{!command}}` 使用命令输出的内容，例如 `Bearer {{!tokenprovider gettoken}}`。命令需要满足的条件参阅[通过命令获取 API 密钥](../configuration/models.md#通过命令获取-api-密钥)。HTTP 服务器在 iCode 运行期间会获得新值；STDIO 服务器会一直使用启动时的值，只有 iCode 再次启动它时才会获得新值。如果命令第一次就失败，服务器连接失败。

手工编辑 YAML 时，请求头和环境变量中的数字值会作为文本读取。`timeout` 请填写不带引号的正整数；无效值需要修正后才能保存。

接下来，根据服务器的连接方式完成 HTTP 或 STDIO 设置。

### 使用 HTTP 连接

1. 将“传输方式”设为 `HTTP`。
2. 填写服务器 URL。URL 必须以 `http://` 或 `https://` 开头。
3. 如果服务器需要认证，在“请求头”中添加名称和值。可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如：

   ```text
   名称：Authorization
   值：Bearer {{MCP_API_TOKEN}}
   ```

4. 如果当前网络要求该服务器不经过系统代理，启用“绕过代理”。
5. 建议保持 TLS 证书验证开启。如果需要连接已确认可信的自签名服务器，可以启用“跳过 TLS 验证”。启用后，iCode 不会验证 HTTPS 服务器证书，无法确认连接的是预期服务器。

HTTP 重定向必须保持请求方法不变，并且目标与原地址同源（协议、主机名和端口相同）；也允许同一主机在默认端口上从 HTTP 升级到 HTTPS。对于 POST 请求，可以跟随 `307`、`308` 重定向，例如补齐 URL 末尾的斜杠。如果重定向改变主机名或端口、将 HTTPS 降级为 HTTP，或将 POST 改为 GET，连接会失败；此时请直接配置预期的最终服务器 URL。

### 使用 STDIO 连接

1. 将“传输方式”设为 `STDIO`。
2. 在“命令”中填写用于启动服务器的程序名称或路径以及所需参数。TUI 会将这行内容拆分并分别保存到智能体 YAML 的 `command` 和 `args` 字段；手工编辑 YAML 时，应将可执行文件写入 `command`，将参数逐项写入 `args`。在 Windows 上，如果 `command` 是 `python` 或 `python3`，iCode 会跳过只提示从 Microsoft Store 获取 Python 的占位程序，改用 `PATH` 中下一个同名程序。python.org 的传统安装程序不提供 `python3`，并且只有在安装时选择了加入 `PATH`，`python` 才会在 `PATH` 中；否则请填写其 `python.exe` 的完整路径。
3. “工作目录”留空时，服务器在[当前会话的工作目录](../daily-use/workspaces.md)中启动。如果服务器需要从其他文件夹查找脚本或配置，在这里填写该文件夹（智能体 YAML 中的 `cwd`）。
4. 按需添加该进程需要的环境变量。变量值可以直接填写，也可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。

STDIO 连接会在本机启动指定程序。如果启动命令会下载或运行第三方软件包或脚本，应先确认其来源可信并检查相关内容。

#### 选择工作目录

iCode 会忽略此字段首尾的空白字符，YAML 中的配置也一样；仅含空白字符时按留空处理。

| 填写内容 | 服务器启动位置 |
| --- | --- |
| 留空 | 当前会话的工作目录 |
| `tools/mcp` | 当前会话工作目录下的 `tools/mcp` 文件夹 |
| `~/mcp-server` | 用户主目录内的 `mcp-server` 文件夹 |
| 绝对路径，例如 `/opt/mcp-server` 或 `D:\mcp-server` | 指定的文件夹 |

例如，会话的工作目录为 `/project`，将服务器的“工作目录”设为 `tools/mcp`、“命令”设为 `python server.py`，就会在 `/project/tools/mcp` 中运行 `/project/tools/mcp/server.py`。该文件夹和脚本必须已存在，且 `python` 能从 `PATH` 中找到。

相对路径可以用 `..` 指向会话工作目录之外，例如 `../shared-mcp`。

用 `/chdir` 切换会话工作目录后，留空或填写相对路径的服务器会根据新的会话工作目录确定启动位置。例如，填写 `tools/mcp` 时，从项目 A 切换到项目 B 后，会使用项目 B 下的 `tools/mcp`。`~/` 和绝对路径指定的启动位置不变。

命令填写为 `./bin/server` 这样的相对路径时，会从服务器的工作目录查找程序；只填写 `python` 这样的程序名称时，会从 `PATH` 中查找。

在 Windows 上，“工作目录”和命令中的盘符后都要带斜杠：写 `D:\server` 和 `D:\server\server.exe`，不要写 `D:server` 或 `D:server\server.exe`。

“工作目录”可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如 `{{MCP_HOME}}/weather`。变量不存在或值为空时，该服务器连接失败。不支持 `{{!command}}`，也不支持 `$HOME`、`%APPDATA%` 这类 shell 写法；用户主目录可以用 `~/`。

## 从其他应用导入服务器

可以把已在 Claude Code、Codex、OpenCode 或 Pi 中使用的 MCP 服务器复制到当前智能体。这是一次性复制：之后在其他应用中修改，不会同步到 iCode。

1. 在 `/agents mcp` 中，点击“+ 添加”旁的“从其他应用导入”。
2. 在左侧选择应用。每个服务器都以导入后的卡片样式显示，点击名称可展开。
3. 勾选需要的服务器，然后点击“导入”。可以先在多个应用中勾选，再一起导入；左侧每个应用后会显示其中已勾选的数量。添加前，iCode 会按应用列出已勾选的服务器：点击“导入”确认，或点击“返回”修改勾选。
4. 检查新卡片，按其中的提醒处理，点击“测试”，再点击“保存”。仅导入不会连接服务器，也不会保存配置。

服务器名称后的标记提示需要注意的地方。“⚠”加数字表示提醒的条数。无法勾选的服务器与“+ 添加”遵循同样的规则：当前智能体已有相同的服务器时显示“已添加”，已有冲突的服务器时显示“名称已存在”或“连接已存在”（鼠标悬停在标记上可查看详情）；与已勾选的服务器冲突时显示“重复”（鼠标悬停在标记上可查看与哪个冲突）；无法导入时显示“无法导入”，原因见卡片内。无法勾选的服务器不显示勾选框，名称为灰色。

### 使用前检查

- **提醒（⚠）**：每条提醒都说明服务器可用前要做什么：未复制的设置、需要重新登录、需要设置的环境变量，或需要选择的工具。提醒显示在卡片的“描述”中，导入后也会保留，方便之后查看；处理完后可以删除。
- **启用状态**：原应用不会启动的服务器，导入后“启用”不勾选：包括在原应用中已停用的服务器，以及在 Claude Code 中拒绝过或尚未批准的项目服务器（来自 `.mcp.json`）。如需使用，请在卡片中勾选。
- **使用范围**：导入的服务器在使用当前智能体的所有项目中都可用，即使原应用只在某个项目中使用它。STDIO 的“工作目录”留空时使用当前会话目录；相对路径随会话目录变化，绝对路径保持固定。
- **凭据**：直接写在原应用配置中的令牌会复制到智能体文件中。在原应用中完成的登录（例如 OAuth）不会复制。如果服务器需要认证，请添加服务器要求的请求头，或[通过命令获取值](../configuration/models.md#通过命令获取-api-密钥)。
- **全局关闭的工具**：原应用中对所有服务器生效的工具开关（例如 OpenCode 的全局 `tools`）不会导入。请在“可用工具范围”中重新选择该服务器的工具。
- **审批**：原应用的审批规则不会迁移，请参阅[审批模式](../configuration/approval.md)。

### 检查导入的工作目录

Codex、OpenCode V1 和 Pi 的工作目录会复制到“工作目录”字段。普通相对路径仍保持相对路径，会随 iCode 当前会话目录变化。Pi 的 `~` 会展开为用户主目录。OpenCode V1 和 Codex 按字面路径处理 `~`：导入的 `~/server` 会写成 `./~/server`，让 iCode 使用会话目录内名为 `~` 的文件夹。OpenCode 的 `{env:VAR}` 会转换为 `{{VAR}}`；请在启动 iCode 前将变量设为非空值。文件引用不会导入。

**OpenCode 中引用变量的工作目录需要检查。** 如果路径还含有父目录分量（`..`），例如 `{env:ROOT}/../srv`，则无法导入，因为提前解析这种组合可能改变实际目录。其他情况下，导入会保留变量引用并显示提醒，因为变量之后的值可能改变实际目录。例如，变量值为 `~/server` 时，OpenCode 使用字面名称为 `~` 的文件夹，iCode 则会展开为用户主目录。在 POSIX 上，OpenCode 在跟随符号链接前先把 `link/..` 折叠为会话目录；iCode 则先跟随 `link`，再进入其父目录。请点击“测试”检查展开后的路径；需要保持相同目录时，使用不含 `~` 或 `..` 的完整绝对路径。在 Windows 上，变量值为 `C:tools` 这类盘符相对路径时连接会失败；直接填写的 `C:tools` 或 `C:` 无法导入，请改用 `C:\tools` 这类完整路径。

**Codex 的相对路径需要检查。** Codex 从启动 Codex 的目录计算显式相对 `cwd`（包括 `"."`），iCode 则从当前会话目录计算。例如，在 `/launch` 中运行 `codex -C /project` 时，`cwd = "tools"` 会在 `/launch/tools` 启动服务器，`cwd = "."` 会在 `/launch` 启动；不配置 `cwd` 才会在 `/project` 启动。iCode 会话位于 `/project` 时，导入的 `tools` 会使用 `/project/tools`，`.` 会使用 `/project`。导入会保留显式 `.`，并对每个显式相对 Codex 路径显示提醒。请检查该字段；需要固定在原位置时，改用绝对路径。iCode 无法恢复原 Codex 的启动目录。

导入不会检查目录是否存在或能否进入。检查卡片后，点击“测试”，再点击“保存”。遇到目录错误，请查看连接报告中 `Working directory:` 后的实际路径；加载智能体时的连接错误也可以按 **F6** 查看。详见[测试并保存](#测试并保存)。

### 读取哪些配置

| 应用 | 读取的文件 |
| --- | --- |
| Claude Code | `~/.claude.json`（或 `CLAUDE_CONFIG_DIR` 中的同名文件）中你的服务器和为当前项目添加的服务器（在 Git 工作树中，项目指仓库的主目录，与 Claude Code 一致）；当前目录及其 Git 仓库顶层的 `.mcp.json` |
| Codex | `~/.codex/config.toml`（或 `CODEX_HOME` 中的同名文件）；从 Git 仓库顶层到当前目录之间、已在 Codex 中信任的每个目录下的 `.codex/config.toml` |
| OpenCode | `~/.config/opencode` 中的 `opencode.json`、`opencode.jsonc` 或 `config.json`；`OPENCODE_CONFIG` 指定的文件；从 Git 仓库顶层（不在仓库中时为磁盘根目录）到当前目录之间每个目录及其 `.opencode` 文件夹、`~/.opencode`，以及 `OPENCODE_CONFIG_DIR` 指定目录中的 `opencode.json` 或 `opencode.jsonc` |
| Pi | `~/.pi/agent/mcp.json`（或 `PI_CODING_AGENT_DIR` 中的同名文件）；当前目录下的 `.pi/mcp.json`，前提是已在 Pi 中信任该目录 |

项目自带的文件不能自行向智能体添加服务器。与 Codex 和 Pi 一致，只有在其中信任了该目录，才会读取项目文件；在 Claude Code 中，来自 `.mcp.json` 的服务器在你批准前导入为停用，而保存在项目自身设置中的批准，只有在你信任该项目本身后才算数（仅信任其上层目录不够）。

多个文件中有同名服务器时，只列出对当前项目生效的那个。仅由云服务、插件或扩展添加的服务器不会列出，请手动添加。

### 无法导入时

“无法导入”会指出原应用配置文件中 iCode 无法按原样使用的配置项。常见原因：

| 原因 | 处理方法 |
| --- | --- |
| 服务器使用 SSE 或 WebSocket，或在 Codex 远程环境中运行 | 如果它也提供 Streamable HTTP，或可在本机用 STDIO 命令启动，请按该方式手动添加。 |
| URL、命令或参数中引用了环境变量 | 手动添加服务器，填写完整的 URL 或实际的值。 |
| 值从文件读取，例如 OpenCode 的 `{file:...}` | 手动添加服务器，填写实际的值，或引用环境变量。 |
| 值由 Pi 运行命令获取（以 `!` 开头） | 手动添加服务器，在 iCode 中[通过命令获取值](../configuration/models.md#通过命令获取-api-密钥)，或直接填写。 |
| 值为空，或首尾有空格 | 手动添加服务器，并填写所需的值。 |
| Codex 显式配置了空的 `cwd = ""` | 删除该配置项以使用会话目录，或填写有效目录。空字符串不会按未配置处理。 |
| OpenCode 的 `cwd` 同时含有变量和 `..` 路径分量，例如 `{env:ROOT}/../srv` | 手动添加服务器，填写不含 `~` 或 `..` 的完整绝对路径。导入无法保留变量展开与路径规范化的先后顺序。 |
| Windows 上的 `cwd` 是 `C:tools` 或 `C:` 这类盘符相对路径 | 改用 `C:\tools` 这类完整绝对路径。盘符相对路径依赖该盘符的当前目录，无法在 iCode 中启动。 |
| `cwd` 含有控制字符、换行或双向文本格式控制符 | 修正原配置中的路径，或手动添加服务器并填写可在单行字段中显示的路径。导入会拒绝这些字符，避免静默改变目录。 |
| 请求头名称无效，请求头的值含非 ASCII 文本或控制字符，或有两个请求头名称仅大小写不同 | 手动添加服务器，填写服务器接受的请求头。 |

如果某个文件无法读取，错误会显示在列表上方，其他文件中的服务器仍会列出。修正文件后重新打开导入即可。

如果重新打开导入后仍提示无法搜索或加载 MCP 配置，原因记录在 iCode 配置目录的 `logs/debug.log` 中：macOS 和 Linux 为 `~/.chrys/`，Windows 为 `%APPDATA%\chrys\`。

## 配置说明、工具和请求选项

以下设置同时适用于 HTTP 和 STDIO 服务器。

### 服务器说明与提示词模板

- **将服务器使用说明加入模型上下文（如有）**：新建配置默认启用。启用后，服务器说明会加入模型上下文，并可能影响智能体的行为。
- **将服务器提示词模板加载为工具（如有）**：新建配置默认启用。启用后，服务器提供的提示词模板会作为可调用工具加入模型工具列表。

### 工具访问

- **可用工具范围**：控制允许智能体使用的服务器工具。可以选择“全部服务器工具”、“仅选定工具”或“无工具”。

选择“仅选定工具”时，填写以 `,` 分隔的工具名称列表。如果还不清楚服务器提供的工具名称，可以先选择“全部服务器工具”，再按照[测试并保存](#测试并保存)中的步骤从连接报告查看工具名称。

### 工具加载

- **加载策略**：控制工具何时提供给智能体。选择“全部加载 — 一开始就加载全部可用工具”时，“可用工具范围”内的所有工具在任务开始时即可使用。选择“按需加载 — 需要时再加载工具”时，任务开始时仅提供“初始可见工具（可选）”中的工具，智能体可在需要时加载“可用工具范围”内的其他工具。服务器提供的工具较多、常用工具较少时，按需加载可以减少任务开始时发送给模型的工具信息。
- **初始可见工具（可选）**：使用“按需加载 — 需要时再加载工具”时，可以填写以 `,` 分隔的工具名称列表。填写的工具必须包含在“可用工具范围”中。

例如：

- 服务器只提供 `search` 和 `read_file`，并且两者经常使用，可以选择“全部加载 — 一开始就加载全部可用工具”。
- 服务器提供几十个工具，但通常只使用 `search` 和 `read_file`，可以选择“按需加载 — 需要时再加载工具”，并将这两个工具填入“初始可见工具（可选）”。

使用 Claude Opus 5.5、Fable 5.1 或 Sonnet 5.5 时，按需加载有额外代价。这些模型会把返回的思考内容与它之前的对话绑定，包括智能体当时可用的工具。智能体加载或卸载工具，或下一个任务重新只从初始可见工具开始时，这部分对话就会变化，模型服务可能略去早先的思考内容，或拒绝读回这些内容。如果服务拒绝，iCode 会去掉早先的思考内容，再发送一次请求，这会多发一次请求。无论是服务略去，还是 iCode 去掉后重发，模型都不再看到那部分早先的推理。设为 `thinking_block_binding: error` 时，iCode 会直接报告这次拒绝，不会重发。相关设置详见 [Claude 思考设置](../configuration/models.md#claude-思考设置)。

### 命名与限制

- **工具名称前缀**：为该服务器的工具名称添加前缀，并使用 `_` 连接前缀与原名称。例如，前缀 `github` 会将工具 `search` 显示为 `github_search`。不同服务器或内置工具存在同名工具时，可以用前缀避免冲突。
- **MCP 请求超时（秒）**：限制单次 MCP 请求等待时间；留空时使用界面显示的默认值。

## 测试并保存

1. **启用/停用服务器**：如需启用 MCP 服务器，保持勾选配置卡片左下角的“启用”选项。如需保留配置但暂时停用服务器，取消勾选该选项。停用后，服务器不会向智能体提供工具、提示词模板或使用说明。
2. **测试服务器连接**：点击服务器配置卡片右下角的“测试”。iCode 会尝试连接服务器，并在连接报告中显示服务器身份、声明的能力和使用说明，以及当前配置下可用的工具和提示词模板。
3. **保存配置**：点击“保存”。如果修改的是当前会话正在使用的智能体，保存后的 MCP 配置会用于后续请求。

如果测试失败：

- HTTP 服务器应检查 URL、认证请求头、环境变量以及代理和 TLS 设置。
- STDIO 工作目录错误：查看 `Working directory:` 后的实际路径，确认它是已存在且有权限进入的文件夹；字段留空时检查当前会话的工作目录。修正路径或权限后重试。
- 对于其他 STDIO 连接错误，请查看错误中提供的可执行文件、进程退出码和标准错误输出，核对命令、参数和环境变量，并确认命令能在所示工作目录中运行。

加载智能体时连接失败，可以按 **F6** 查看 iCode 的连接错误日志。iCode 只保留有限长度的服务器标准错误输出；需要完整服务器日志时，请按照服务器自身的文档启用日志记录。分享诊断信息前，请移除令牌、凭据等敏感信息。

## 用 /reload 重新连接

`/reload` 会为当前智能体及其子智能体使用的每个已启用 MCP 服务器尝试建立新连接，其间原有连接保持打开。下一次请求使用各服务器当前提供的工具、提示词模板和使用说明。每台服务器的结果相互独立，一台失败不影响其他服务器：

| 新连接 | 结果 | 摘要中的内容 |
| --- | --- | --- |
| 成功 | iCode 改用新连接并关闭旧连接 | 不显示该服务器 |
| 失败，服务器配置未变，且旧连接仍有响应 | iCode 继续使用旧连接 | “重连失败，沿用旧连接”及原因 |
| 失败，且配置有变化，例如地址、令牌或“可用工具范围” | 服务器不可用，即使旧连接仍然正常，也不会继续保留旧令牌或旧工具范围的访问权限 | “不可用”及原因 |
| 失败，且旧连接没有响应或原本没有连接 | 服务器不可用 | “不可用”及原因 |

原因只说明失败的类型，例如连接被拒绝或凭据被拒绝，不会转述服务器返回的内容，因为其中可能包含凭据；详细信息请查看服务器自身的日志。

不可用服务器的工具会从智能体中撤下；解决问题后再次执行 `/reload`。已删除或已停用的服务器不会尝试重连，其工具被撤下，连接随之关闭。

以下两种结果属于正常情况：

- 重连成功会在服务器上开始新的会话，浏览器页面、登录状态等远端状态可能被重置。
- 独占端口或文件的 STDIO 服务器可能无法与旧实例同时运行，因此每次重连都可能失败。只要配置未变且旧连接仍有响应，摘要会持续提示沿用旧连接。

在设置或智能体配置窗口中保存不会强制重连：配置未变的服务器继续使用原有连接。

## 验证 MCP 工具调用

关闭智能体配置窗口，提交一项需要使用该服务器工具的低风险任务。例如，如果服务器提供只读搜索工具，可以要求智能体搜索一条明确的数据。

对话中应显示对应的 MCP 工具调用卡片，并返回服务器提供的数据。若弹出“工具审批”对话框，请先核对工具名称和调用参数，再决定是否批准。有关审批方式，请参阅[配置审批模式](../configuration/approval.md)。

如果工具返回的图像、音频或文件无法解码，智能体会收到一条简短说明代替该项，结果的其余内容照常送达。工具返回的链接会以文字（名称、地址和描述）交给智能体。

如果连接测试成功，但对话中工具不可用，请检查服务器是否已启用、工具是否出现在连接报告中，以及是否包含在“可用工具范围”中。
