# 连接 MCP 服务器

模型上下文协议（Model Context Protocol，MCP）服务器可以为 iCode 智能体提供外部工具、提示词模板和使用说明。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中连接 HTTP 或 STDIO MCP 服务器、配置可调用的工具，以及控制是否加载提示词模板、是否将服务器使用说明加入模型上下文。

连接 MCP 服务器前，请确认服务器来源可信。服务器可能接收工具调用参数，并访问本机文件、网络服务或账号数据；其提供的提示词模板和使用说明也可能影响智能体的行为。

如果要为智能体提供用几个 Python 函数编写的工具，而无需运行服务器，参阅 [Python 扩展](./python-extensions.md)。

## 添加 MCP 服务器配置

在输入栏中输入 `/agents mcp`，打开当前智能体的“MCP”标签页。添加的服务器配置只对当前智能体生效，不会自动应用到其他智能体。

每个服务器对应一张卡片。已保存的服务器默认折叠，只显示名称；点击名称可展开或折叠。保存时如果发现问题，有问题的卡片会自动展开。要删除服务器，点击卡片上的“✕”并确认。

点击“+ 添加”可复用其他智能体的 MCP 配置。有可复用配置时，弹窗会显示服务器名称、来源智能体，以及可执行文件名或 URL 主机名。选择后，完整设置会复制到列表顶部的新卡片中并展开。副本相互独立：之后修改或删除任一智能体中的配置，都不会影响另一方。复制已禁用的配置时，副本也保持禁用。弹窗读取当前智能体配置窗口中的最新草稿，包含尚未保存的修改。

多个智能体中设置相同的同名配置会合并显示，并列出所有来源；同名但设置不同的配置则分别显示。可选配置排在前面，灰色不可选配置排在后面，两组内分别按名称排序。灰色项会说明无法添加的原因：当前智能体已有同名配置，或已有连接、工具名称前缀相同且允许工具范围重叠的配置。已禁用的配置也会参与检查。

弹窗不会连接服务器。如果加载智能体时报工具名冲突，请按错误提示调整相关服务器的工具名称前缀，或排除重叠工具。单个服务器测试成功不能排除它与其他服务器的工具名冲突。

要配置新的服务器，选择“+ 新建 MCP 配置…”。如果其他智能体没有有效的 MCP 配置，“+ 添加”会直接创建空白卡片。无效的来源配置不会提供为候选。取消弹窗不会修改配置。复制和新建的配置都通过配置页现有的“保存”流程生效。

在新建卡片中填写以下字段：

1. 填写“服务器名称”。名称用于在当前智能体的 MCP 配置中标识该服务器。同一个智能体的 MCP 配置中，服务器名称不能重复，且不区分大小写。
2. 可选填写“描述”，用于备注服务器的用途。该描述不会作为服务器使用说明提供给智能体。

HTTP 请求头值和 STDIO 环境变量值都可以使用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。环境变量名只能包含字母、数字和下划线，且不能以数字开头。

两者也可以用 `{{!command}}` 使用命令输出的内容，例如 `Bearer {{!tokenprovider gettoken}}`。命令需要满足的条件参阅[通过命令获取 API 密钥](../configuration/models.md#通过命令获取-api-密钥)。HTTP 服务器在 iCode 运行期间会获得新值；STDIO 服务器会一直使用启动时的值，只有 iCode 再次启动它时才会获得新值。如果命令第一次就失败，服务器连接失败。

手工编辑 YAML 时，请求头和环境变量中的数字值会作为文本读取。`timeout` 请填写不带引号的正整数；无效值需要修正后才能保存。

接下来，根据服务器的连接方式完成 HTTP 或 STDIO 设置。

### 使用 HTTP 连接

1. 将“传输方式”设为 `HTTP`。
2. 填写服务器 URL。URL 必须以 `http://` 或 `https://` 开头。
3. 如果服务器需要认证，在“请求头”中添加名称和值。可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如：

   ```text
   名称：Authorization
   值：Bearer {{MCP_API_TOKEN}}
   ```

4. 如果当前网络要求该服务器不经过系统代理，启用“绕过代理”。
5. 建议保持 TLS 证书验证开启。如果需要连接已确认可信的自签名服务器，可以启用“跳过 TLS 验证”。启用后，iCode 不会验证 HTTPS 服务器证书，无法确认连接的是预期服务器。

HTTP 重定向必须保持请求方法不变，并且目标与原地址同源（协议、主机名和端口相同）；也允许同一主机在默认端口上从 HTTP 升级到 HTTPS。对于 POST 请求，可以跟随 `307`、`308` 重定向，例如补齐 URL 末尾的斜杠。如果重定向改变主机名或端口、将 HTTPS 降级为 HTTP，或将 POST 改为 GET，连接会失败；此时请直接配置预期的最终服务器 URL。

### 使用 STDIO 连接

1. 将“传输方式”设为 `STDIO`。
2. 在“命令”中填写用于启动服务器的程序名称或路径以及所需参数。TUI 会将这行内容拆分并分别保存到智能体 YAML 的 `command` 和 `args` 字段；手工编辑 YAML 时，应将可执行文件写入 `command`，将参数逐项写入 `args`。在 Windows 上，如果 `command` 是 `python` 或 `python3`，iCode 会跳过只提示从 Microsoft Store 获取 Python 的占位程序，改用 `PATH` 中下一个同名程序。python.org 的传统安装程序不提供 `python3`，并且只有在安装时选择了加入 `PATH`，`python` 才会在 `PATH` 中；否则请填写其 `python.exe` 的完整路径。
3. “工作目录”留空时，服务器在[当前会话的工作目录](../daily-use/workspaces.md)中启动。具名工作区的会话使用工作区的主文件夹。如果服务器需要从其他文件夹查找脚本或配置，在这里填写该文件夹（智能体 YAML 中的 `cwd`）。
4. 按需添加该进程需要的环境变量。变量值可以直接填写，也可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。

STDIO 连接会在本机启动指定程序。如果启动命令会下载或运行第三方软件包或脚本，应先确认其来源可信并检查相关内容。

该程序还会获得启动 iCode 时的大部分环境变量，例如 `PATH`、代理设置，以及在该终端中设置的令牌。如果某个服务器不应看到某项凭据，请在启动 iCode 时不要设置该变量。

#### 选择工作目录

iCode 会忽略此字段首尾的空白字符，YAML 中的配置也一样；仅含空白字符时按留空处理。

| 填写内容 | 服务器启动位置 |
| --- | --- |
| 留空 | 当前会话的工作目录 |
| `tools/mcp` | 当前会话工作目录下的 `tools/mcp` 文件夹 |
| `~/mcp-server` | 用户主目录内的 `mcp-server` 文件夹 |
| 绝对路径，例如 `/opt/mcp-server` 或 `D:\mcp-server` | 指定的文件夹 |

例如，会话的工作目录为 `/work/demo`，将服务器的“工作目录”设为 `tools/mcp`、“命令”设为 `python server.py`，就会在 `/work/demo/tools/mcp` 中运行 `/work/demo/tools/mcp/server.py`。该文件夹和脚本必须已存在，且 `python` 能从 `PATH` 中找到。

相对路径可以用 `..` 指向会话工作目录之外，例如 `../shared-mcp`。

用 `/chdir` 切换会话工作目录后，留空或填写相对路径的服务器会根据新的会话工作目录确定启动位置。例如，填写 `tools/mcp` 时，从目录 A 切换到目录 B 后，会使用目录 B 下的 `tools/mcp`。`~/` 和绝对路径指定的启动位置不变。

命令填写为 `./bin/server` 这样的相对路径时，会从服务器的工作目录查找程序；只填写 `python` 这样的程序名称时，会从 `PATH` 中查找。

在 Windows 上，“工作目录”和命令中的盘符后都要带斜杠：写 `D:\server` 和 `D:\server\server.exe`，不要写 `D:server` 或 `D:server\server.exe`。

“工作目录”可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如 `{{MCP_HOME}}/weather`。变量不存在或值为空时，该服务器连接失败。不支持 `{{!command}}`，也不支持 `$HOME`、`%APPDATA%` 这类 shell 写法；用户主目录可以用 `~/`。

## 从其他应用导入服务器

可以把 Claude Code、ChatGPT、OpenCode 或 Pi 的 MCP 服务器配置复制到当前智能体。导入是一次性复制，之后对原配置的修改不会同步到 iCode。

“ChatGPT”入口读取 ChatGPT 桌面应用、Codex CLI 和 Codex IDE 扩展共用的本地 MCP 配置，不包括在 ChatGPT 网页版中配置的连接。

1. 在 `/agents mcp` 中，点击“+ 添加”旁的“从其他应用导入”。
2. 在左侧选择应用，点击服务器名称展开卡片，查看设置和提醒。
3. 勾选需要的服务器，然后点击“导入”。可以在多个应用中分别勾选后一起导入，左侧会显示每个应用中已勾选的数量。
4. 在确认窗口中核对服务器列表，点击“导入”确认，或点击“返回”修改勾选。确认后会生成待保存的卡片。
5. 导入后，新配置会出现在“MCP”标签页中。按提醒补充或调整设置，再按[测试并保存](#测试并保存)中的步骤操作。

服务器名称后的标记表示当前状态。无法勾选的服务器不显示勾选框，但仍可点击名称展开卡片查看详情。

| 标记 | 含义与处理 |
| --- | --- |
| ⚠ 加数字 | 有相应数量的提醒，展开卡片查看。 |
| 已添加 | 当前智能体已有相同配置，无需再次导入。 |
| 重复 | 与已勾选的服务器同名，或符合下文的连接冲突条件。将鼠标悬停在标记上可查看冲突项。要改选这一项，先取消勾选另一项。 |
| 无法导入 | 展开卡片查看原因，并参见[无法导入时](#无法导入时)。 |
| 名称已存在 | 当前智能体已有同名但设置不同的配置。导入窗口中不能改名。如需同时保留两者，可以先在“MCP”标签页中修改已有卡片的“服务器名称”，或在原应用的配置中修改该服务器的名称，再重新打开导入窗口。 |
| 连接已存在 | 当前智能体中已有使用相同连接的配置，工具可能重复。将鼠标悬停在标记上可查看该配置的名称，再按下文核对。 |

两份配置的 HTTP 地址相同，或 STDIO 命令和参数相同，且“工具名称前缀”相同、“可用工具范围”有重叠时，会显示“连接已存在”。任一方设为“无工具”时不算重叠。工作目录、环境变量和请求头不参与比较，因此显示该标记的两份配置也可能连接不同的服务器，请对照已有卡片判断。如果要保留使用同一连接的两份配置，请为它们使用不同的服务器名称，并设置不同的工具名称前缀或互不重叠的工具范围。

### 使用前检查

导入窗口会标出已识别的设置差异。导入后，可在卡片的“描述”中查看提醒和来源文件路径。即使没有提醒，也请测试所需功能。处理完提醒后，可以从“描述”中删除它们。

Codex 管理员策略、OpenCode 启动时的覆盖设置（`OPENCODE_CONFIG_CONTENT` 和 `OPENCODE_PERMISSION`），以及特定 OpenCode 智能体的权限只在原应用中生效。如果你依赖这些限制，请在测试或保存前核对启用的服务器和可用工具。

- **启用状态**：导入的配置文件中已停用的服务器，以及在 Claude Code 中被拒绝或尚未批准的项目服务器，导入后“启用”仍未勾选。核对设置后勾选“启用”并保存，即可使用。
- **凭据**：直接写在原配置中的令牌会随配置复制到智能体文件中。在原应用中完成的登录不会复制；从 Claude Code 导入时，引用 Claude Code 认证变量的请求头也不会复制。如果服务器支持令牌认证，请按服务器说明填写“请求头”，请求头的值也可以[通过命令获取](../configuration/models.md#通过命令获取-api-密钥)。允许匿名访问的公开 HTTP 服务器无需填写“请求头”。仅支持 OAuth 登录的服务器暂时无法在 iCode 中使用。
- **环境变量**：导入后的 `{{ENV_VAR}}` 引用在测试或加载服务器时读取，原配置中为变量设置的默认值不会保留；变量未设置或为空时，连接会失败并给出变量名。请设置这些变量后重新启动 iCode，或在引用变量的字段中改填固定值。配置引用了 Claude Code 自动提供的 `CLAUDE_PROJECT_DIR` 时，同样需要自行设置。从 ChatGPT 导入的本地服务器在 iCode 中可能比在 Codex 中读到更多环境变量，包括凭据。请先移除不希望服务器读取的凭据，再启动 iCode 并测试连接。`PYTHONPATH` 和 `PYTHONHOME` 例外：iCode 不会把它们传给本地服务器，因此 ChatGPT 中的服务器若传递其中任一变量，导入时不会复制，并会显示警告。如果服务器需要，请在卡片的“环境变量”中添加，可以填固定值，也可以填 `{{PYTHONPATH}}` 这样的引用。详见[使用 STDIO 连接](#使用-stdio-连接)。
- **工具**：检查“可用工具范围”，只保留需要的工具。如果导入后服务器显示为“无工具”，请按[工具访问](#工具访问)选择要启用的工具。例如，在 Claude Code 中禁止某台 MCP 服务器的一项工具，导入后这台服务器可能会显示为“无工具”。导入通常会根据服务器名称填写“工具名称前缀”。例如，服务器 `github` 的工具 `search` 会显示为 `github_search`。如果已选工具的名称太长，前缀可能留空。你可以按需调整前缀，参见[命名与限制](#命名与限制)。从 Pi 导入时，如果服务器默认隐藏工具，只会保留按具体名称开放的工具，通过 `read_*` 等通配规则开放的工具需要在“可用工具范围”中补上；如提示工具加载规则未复制，请按[工具加载](#工具加载)检查“加载策略”和“初始可见工具（可选）”。
- **超时**：从 ChatGPT 导入时，“MCP 请求超时（秒）”沿用原来的工具超时，未设置时填入 300 秒，原值为 `0` 时使用 iCode 默认值。测试提示连接超时时，可增大该值后重试。
- **审批**：原应用的审批规则不会导入。导入的工具按 iCode 当前的审批模式和智能体的审批规则处理。输入 `/approval` 可切换审批模式，详见[审批模式](../configuration/approval.md)。

### 检查导入的工作目录

启用并保存后，所有使用当前智能体的会话都可以使用导入的服务器。STDIO 卡片的“工作目录”留空或填写相对路径时，服务器的启动位置随会话目录变化。要固定启动位置，请填写绝对路径或以 `~/` 开头的路径。详见[选择工作目录](#选择工作目录)。

如果卡片上的路径和原配置不同，或测试显示的启动位置不符合预期，请检查以下几种情况。

- **从 ChatGPT 或 OpenCode 导入的 `~` 路径**：Codex 和 OpenCode 不会把工作目录中的 `~` 展开为用户主目录，而是将其视为名为 `~` 的文件夹。iCode 会展开开头的 `~`，所以导入时将 `~/server` 写为 `./~/server`，以保留原配置的含义。如果原本想使用主目录下的文件夹，请改为 `~/server` 或完整路径。
- **从 ChatGPT 导入的相对工作目录**：Codex 从启动 Codex 的目录解析显式填写的相对工作目录，iCode 从会话工作目录解析。要固定启动位置，请填写绝对路径。
- **OpenCode 中引用环境变量的路径**：`{env:VAR}` 会变为 `{{VAR}}`，在测试或加载服务器时读取变量值。变量值中的 `~` 等写法在 iCode 中的解析方式可能与 OpenCode 不同，导入时会对此给出提醒。请在启动 iCode 前设置该变量，并确保其值是完整路径。

测试 STDIO 服务器时，可在连接报告中核对“工作目录”。

### 读取哪些配置

如果列表中找不到某个服务器，请确认该服务器保存在下表所列位置，并检查表格下方的信任设置。项目配置从当前会话的工作目录开始查找；[具名工作区](../daily-use/workspaces.md#工作区)的会话从工作区的主文件夹开始，不查找参考文件夹。如需导入参考文件夹中的项目配置，请以该文件夹为工作目录打开会话（例如 `icode -C <目录>`），或在会话中用 `/chdir` 切换到该文件夹（会离开工作区），再进行导入。

| 应用 | 读取的文件 |
| --- | --- |
| Claude Code | `~/.claude.json`（或 `CLAUDE_CONFIG_DIR` 中的同名文件）中的用户级服务器和为当前项目添加的服务器（在 Git 工作树中工作时，为仓库主文件夹添加的服务器）；会话目录及各级上层目录中的 `.mcp.json`。多个文件定义了同名服务器时，以最靠近会话目录的文件为准 |
| ChatGPT | `~/.codex/config.toml`（或 `CODEX_HOME` 中的同名文件）；从项目根目录（默认为 Git 仓库顶层）到会话目录之间，每个已信任目录下的 `.codex/config.toml` |
| OpenCode | `~/.config/opencode`（或 `XDG_CONFIG_HOME/opencode`）中的 `opencode.json`、`opencode.jsonc` 或 `config.json`；`OPENCODE_CONFIG` 指定的文件；从 Git 仓库顶层（不在仓库中时为磁盘根目录）到会话目录之间每个目录及其 `.opencode` 子目录、`~/.opencode`，以及 `OPENCODE_CONFIG_DIR` 指定目录中的 `opencode.json` 或 `opencode.jsonc` |
| Pi | `~/.pi/agent/mcp.json`（或 `PI_CODING_AGENT_DIR` 中的同名文件）；会话目录下的 `.pi/mcp.json`，前提是已在 Pi 中信任该目录 |

项目配置能否列出，还取决于在原应用中的设置：

- 如果左侧没有 **ChatGPT**，请检查用户级 `config.toml` 是否存在。如果只有项目服务器缺失，请在 Codex 中确认已信任项目文件夹（在 Git 工作树中为仓库主文件夹）。
- 如果 **Pi** 的项目服务器缺失，请检查当前目录或上级目录的信任设置。没有适用的信任记录时，只有将 `defaultProjectTrust` 设为 `"always"` 才会读取项目配置。
- 如果 **OpenCode** 的项目服务器缺失，请检查 OpenCode 是否设置为跳过项目配置。如果服务器名称中含有变量，请在 OpenCode 配置中填入实际名称，再重新打开导入窗口。
- **Claude Code**：尚未批准的 `.mcp.json` 服务器也会列出，导入后处于停用状态。是否已批准，以 Claude Code 当前对该项目生效的设置为准。如果批准记录保存在项目自己的设置中，还需要在 Claude Code 中信任该项目本身，仅信任其上层目录不够。

同一应用的多个配置文件中有同名服务器时，只列出一条，即对当前项目生效的设置。“描述”中记录的来源文件可能不是唯一设置它的文件：如果在其中找不到提醒提到的配置项，请检查该应用的其他配置文件。不同应用中的同名服务器仍会分别列出。

仅由云服务、插件或扩展动态提供、未保存在上述文件中的服务器不会列出。如果有可用的 Streamable HTTP 地址或本地启动命令，可以在 `/agents mcp` 中点击“+ 添加”手动添加，步骤参见[添加 MCP 服务器配置](#添加-mcp-服务器配置)。

### 无法导入时

展开标有“无法导入”的服务器，查看“说明”中的原因和处理方法。常见情况包括以下几种。

- **连接方式不受支持**：例如 SSE、WebSocket，或需要通过远程环境访问。如果有本机可访问的 Streamable HTTP 地址，或可在本机运行的 STDIO 命令，请[手动添加](#添加-mcp-服务器配置)。
- **URL、命令或参数中引用了变量**：iCode 不在这些字段中展开变量。手动添加时，请将引用替换为变量的实际值。例如 `MCP_HOST` 为 `https://example.com` 时，将 `{env:MCP_HOST}/mcp` 写为 `https://example.com/mcp`。
- **值来自文件或命令**：例如 OpenCode 的 `{file:...}`，或 Pi 中以 `!` 开头的值。请手动添加服务器并填写所需内容；环境变量值和请求头值也可以用 `{{ENV_VAR}}` 引用环境变量，或[通过命令获取](../configuration/models.md#通过命令获取-api-密钥)。
- **值缺失或无法原样保留**：例如首尾含空白、含不可见的控制字符、请求头名称或值含不支持的字符，或 Windows 路径写成 `C:tools`。按“说明”处理即可：多数情况在原配置文件中修正后重新打开导入窗口，少数情况需要手动添加服务器。

服务器未列出时，也请检查原配置的必填项。例如，ChatGPT 服务器必须在 `command` 和 `url` 中二选一，Claude Code 的 HTTP 服务器需要提供有效的 `url`。

如果列表上方显示文件错误，请检查文件访问权限或修正提示中的配置项、语法错误，然后重新打开导入窗口。项目配置出错时，该应用的服务器可能都不会列出，包括全局配置的服务器。

- **Claude Code**：名为 `connector-downloads` 的文件夹（Claude Code 在这里保存从连接器下载的文件）及其子文件夹中的 `.mcp.json` 不会读取，列表上方会列出这些文件。如需导入其中的服务器，请移动该文件或重命名该文件夹。无法读取、无法解析或大于 2 MB 的 `.mcp.json` 也会列为文件错误，其他文件中的服务器照常列出。但如果 iCode 无法读取的文件 Claude Code 可能仍能使用（例如不是 UTF-8 文本），在修复该文件之前，其他文件中的部分服务器（包括用户级服务器）不会列出。
- **ChatGPT**：如果服务器没有列出，且 iCode 提示无法读取项目的 `config.toml`，除访问权限外，也请检查文件大小。每个文件的导入上限为 16 MiB。
- **OpenCode**：如果项目服务器没有列出，请检查全局配置文件是否报错。这个文件可以限制项目服务器的可用工具。
- **Pi**：如果全局服务器没有列出，请检查受信任项目的 `.pi/mcp.json` 是否报错。这个文件可以停用或替换全局服务器。如果你想导入项目服务器，列表中却显示同名的全局服务器，请检查项目文件里的服务器地址和 OAuth 回调地址。

如果重新打开导入窗口后仍提示未能查找或加载 MCP 配置，原因会记录在 iCode 配置目录的日志中：macOS 和 Linux 为 `~/.chrys/logs/debug.log`，Windows 为 `%APPDATA%\chrys\logs\debug.log`。

## 配置说明、工具和请求选项

以下设置同时适用于 HTTP 和 STDIO 服务器。

### 服务器说明与提示词模板

- **将服务器使用说明加入模型上下文（如有）**：新建配置默认启用。启用后，服务器说明会加入模型上下文，并可能影响智能体的行为。
- **将服务器提示词模板加载为工具（如有）**：新建配置默认启用。启用后，服务器提供的提示词模板会作为可调用工具加入模型工具列表。

### 工具访问

- **可用工具范围**：控制允许智能体使用的服务器工具。可以选择“全部服务器工具”、“仅选定工具”或“无工具”。

选择“仅选定工具”时，填写以 `,` 分隔的工具名称列表。如果还不清楚服务器提供的工具名称，可以先选择“全部服务器工具”，再按照[测试并保存](#测试并保存)中的步骤从连接报告查看工具名称。

### 工具加载

- **加载策略**：控制工具何时提供给智能体。选择“全部加载 — 一开始就加载全部可用工具”时，“可用工具范围”内的所有工具在任务开始时即可使用。选择“按需加载 — 需要时再加载工具”时，任务开始时仅提供“初始可见工具（可选）”中的工具，智能体可在需要时加载“可用工具范围”内的其他工具。服务器提供的工具较多、常用工具较少时，按需加载可以减少任务开始时发送给模型的工具信息。
- **初始可见工具（可选）**：使用“按需加载 — 需要时再加载工具”时，可以填写以 `,` 分隔的工具名称列表。填写的工具必须包含在“可用工具范围”中。

例如：

- 服务器只提供 `search` 和 `read_file`，并且两者经常使用，可以选择“全部加载 — 一开始就加载全部可用工具”。
- 服务器提供几十个工具，但通常只使用 `search` 和 `read_file`，可以选择“按需加载 — 需要时再加载工具”，并将这两个工具填入“初始可见工具（可选）”。

使用 Claude Opus 5.5、Fable 5.1 或 Sonnet 5.5 时，按需加载有额外代价。这些模型会把返回的思考内容与它之前的对话绑定，包括智能体当时可用的工具。智能体加载或卸载工具，或下一个任务重新只从初始可见工具开始时，这部分对话就会变化，模型服务可能略去早先的思考内容，或拒绝读回这些内容。如果服务拒绝，iCode 会去掉早先的思考内容，再发送一次请求，这会多发一次请求。无论是服务略去，还是 iCode 去掉后重发，模型都不再看到那部分早先的推理。设为 `thinking_block_binding: error` 时，iCode 会直接报告这次拒绝，不会重发。相关设置详见 [Claude 思考设置](../configuration/models.md#claude-思考设置)。

### 命名与限制

- **工具名称前缀**：为该服务器的工具名称添加前缀，并使用 `_` 连接前缀与原名称。例如，前缀 `github` 会将工具 `search` 显示为 `github_search`。不同服务器或内置工具存在同名工具时，可以用前缀避免冲突。
- **MCP 请求超时（秒）**：限制单次 MCP 请求等待时间；留空时使用界面显示的默认值。

## 测试并保存

1. **启用/停用服务器**：如需启用 MCP 服务器，保持勾选配置卡片左下角的“启用”选项。如需保留配置但暂时停用服务器，取消勾选该选项。停用后，服务器不会向智能体提供工具、提示词模板或使用说明。
2. **测试服务器连接**：点击服务器配置卡片右下角的“测试”。iCode 会尝试连接服务器，并在连接报告中显示服务器身份、声明的能力和使用说明，以及当前配置下可用的工具和提示词模板。
3. **保存配置**：点击“保存”。如果修改的是当前会话正在使用的智能体，保存后的 MCP 配置会用于后续请求。

STDIO 测试成功后，报告会在连接命令下方显示“工作目录”，即本次测试传给服务器进程的启动文件夹；“工作目录”留空时显示当前会话目录。其中的环境变量和 `~` 已经展开，相对路径已接在会话目录之后，可直接与预期的文件夹比对；符号链接不会解析，`..` 也可能保留。HTTP 报告不显示工作目录。

如果测试失败：

- HTTP 服务器应检查 URL、认证请求头、环境变量以及代理和 TLS 设置。
- STDIO 工作目录错误：查看 `Working directory:` 后的实际路径，确认它是已存在且有权限进入的文件夹；字段留空时检查当前会话的工作目录。修正路径或权限后重试。
- 对于其他 STDIO 连接错误，请查看错误中提供的可执行文件、进程退出码和标准错误输出，核对命令、参数和环境变量，并确认命令能在所示工作目录中运行。

加载智能体时连接失败，可以按 **F6** 查看 iCode 的连接错误日志。iCode 只保留有限长度的服务器标准错误输出；需要完整服务器日志时，请按照服务器自身的文档启用日志记录。分享诊断信息前，请移除令牌、凭据等敏感信息。

## 用 /reload 重新连接

加载智能体及其普通子智能体时，相同的 MCP 配置共享一次连接尝试，包括失败结果。加载窗口会显示正在准备的子智能体及 MCP 服务器。服务器连接失败后，本次加载不会为每个子智能体重复尝试；修复服务器后执行 `/reload` 即可重试。共享要求服务器名称及连接设置一致，仅地址相同并不足够。

`/reload` 会为当前智能体及其子智能体使用的每个已启用 MCP 服务器尝试建立新连接，其间原有连接保持打开。下一次请求使用各服务器当前提供的工具、提示词模板和使用说明。每台服务器的结果相互独立，一台失败不影响其他服务器：

| 新连接 | 结果 | 摘要中的内容 |
| --- | --- | --- |
| 成功 | iCode 改用新连接并关闭旧连接 | 不显示该服务器 |
| 失败，服务器配置未变，且旧连接仍有响应 | iCode 继续使用旧连接 | “重连失败，沿用旧连接”及原因 |
| 失败，且配置有变化，例如地址、令牌或“可用工具范围” | 服务器不可用，即使旧连接仍然正常，也不会继续保留旧令牌或旧工具范围的访问权限 | “不可用”及原因 |
| 失败，且旧连接没有响应或原本没有连接 | 服务器不可用 | “不可用”及原因 |

原因只说明失败的类型，例如连接被拒绝或凭据被拒绝，不会转述服务器返回的内容，因为其中可能包含凭据；详细信息请查看服务器自身的日志。

不可用服务器的工具会从智能体中撤下；解决问题后再次执行 `/reload`。已删除或已停用的服务器不会尝试重连，其工具被撤下，连接随之关闭。

以下两种结果属于正常情况：

- 重连成功会在服务器上开始新的会话，浏览器页面、登录状态等远端状态可能被重置。
- 独占端口或文件的 STDIO 服务器可能无法与旧实例同时运行，因此每次重连都可能失败。只要配置未变且旧连接仍有响应，摘要会持续提示沿用旧连接。

在设置或智能体配置窗口中保存不会强制重连：配置未变的服务器继续使用原有连接。

## 验证 MCP 工具调用

关闭智能体配置窗口，提交一项需要使用该服务器工具的低风险任务。例如，如果服务器提供只读搜索工具，可以要求智能体搜索一条明确的数据。

对话中应显示对应的 MCP 工具调用卡片，并返回服务器提供的数据。若弹出“工具审批”对话框，请先核对工具名称和调用参数，再决定是否批准。有关审批方式，请参阅[配置审批模式](../configuration/approval.md)。

如果工具返回的图像、音频或文件无法解码，智能体会收到一条简短说明代替该项，结果的其余内容照常送达。工具返回的链接会以文字（名称、地址和描述）交给智能体。

如果连接测试成功，但对话中工具不可用，请检查服务器是否已启用、工具是否出现在连接报告中，以及是否包含在“可用工具范围”中。
