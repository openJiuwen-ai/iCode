# 配置外部 ACP 智能体

本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中接入支持智能体客户端协议（Agent Client Protocol，ACP）的外部智能体，并将其添加为主智能体的子智能体。

**外部 ACP 智能体可以作为子智能体或工作流节点使用，不能作为聊天主智能体**。每次调用外部 ACP 智能体时，iCode 都会为本次调用启动外部智能体进程，并通过 ACP 与其通信。任务处理和工具调用由外部智能体负责，审批请求、执行状态、进度更新和最终结果通过 ACP 连接传递。调用结束后，iCode 会关闭连接并终止该进程。

## 准备外部智能体

配置外部智能体前，请确认其满足以下条件：

- 已安装在运行 iCode 的设备上；
- 支持通过标准输入输出（stdio）运行 ACP 服务；
- 已完成必要的登录或认证，或已准备好认证所需的环境变量；
- 可以通过可执行文件及参数启动 ACP 模式。

无需提前启动 ACP 服务。测试连接或调用子智能体时，iCode 会根据配置自动启动外部智能体进程，并通过 stdio 建立 ACP 连接。

首次配置前，建议参考外部智能体的文档，准备以下信息：

- 启动 ACP 模式所需的可执行文件和参数；
- 所需的认证信息；
- 可选的会话模式、模型和其他配置项。

其中，会话模式、模型和其他配置项可以在首次配置时填写，也可以在连接成功后根据测试结果补充。

## 创建配置并测试连接

### 创建外部 ACP 智能体配置

1. 打开“智能体配置”窗口。
2. 点击“新建”，填写名称、显示名称和描述。
3. 将“智能体类型”改为“外部 ACP”。iCode 会自动将其设置为“仅用作子智能体”。
4. 打开“ACP 设置”标签页，在“可执行文件”中填写程序名称或路径，并逐项添加启动参数。
5. 按需添加认证所需的环境变量。外部智能体不会继承 iCode 的环境变量，需要在此添加，详见[使用环境变量](#使用环境变量)。
6. “会话模式”“模型 ID”和“配置选项”可以暂时留空，完成基础配置后点击“测试”。

“可执行文件”和“参数”需要分开填写。例如，若启动命令为：

```text
example-agent acp --model example-model
```

应将 `example-agent` 填入“可执行文件”，并分别将 `acp`、`--model` 和 `example-model` 添加为启动参数。不要将整条命令填写到“可执行文件”中。

> **注意**
>
> 将自定义智能体的“智能体类型”从“内置”改为“外部 ACP”时，除名称、显示名称和描述等基本信息外，原有配置会被清除。若需要保留原配置，请新建外部 ACP 智能体。

### 测试连接

测试连接时，iCode 会启动一个临时外部智能体进程，检查能否建立 ACP 会话，但不会发送任务。连接成功后，报告会显示身份、能力、模式、模型、配置选项和认证方式等栏目，并列出外部智能体提供的信息；未提供的信息可能显示“未声明。”“智能体未报告其身份信息。”或留空，这不表示连接失败。

测试结束后，iCode 会关闭该临时进程。

如果连接失败，请依次检查：

- 错误信息和标准错误输出末尾是否说明缺少依赖、参数错误或认证失败；
- 可执行文件和启动参数是否正确；
- 认证信息或环境变量是否有效；
- 配置的工作目录是否存在且允许访问。

### 示例：将 iCode 配置为外部 ACP 智能体

iCode 自身也可以通过 stdio 提供 ACP 服务。可以使用以下配置：

- “可执行文件”：`icode`
- “参数”：添加 `acp`

以上配置对应启动命令：

```bash
icode acp
```

该命令会启动 iCode ACP 服务，默认提供 `Code` 智能体，并使用 `manual` 审批模式。有关 iCode ACP 服务的更多配置和使用说明，请参阅[使用 iCode ACP 服务](../running/icode-acp.md)。

## 使用环境变量

外部智能体不会继承 iCode 运行环境中的环境变量。它启动时只带有一组基本变量（macOS 和 Linux 上为 `HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM` 和 `USER`；Windows 上为 `APPDATA`、`HOMEDRIVE`、`HOMEPATH`、`LOCALAPPDATA`、`PATH`、`PATHEXT`、`PROCESSOR_ARCHITECTURE`、`SYSTEMDRIVE`、`SYSTEMROOT`、`TEMP`、`USERNAME` 和 `USERPROFILE`），以及智能体配置中设置的环境变量。智能体所需的其他变量，例如 API 密钥或 `HTTPS_PROXY` 等代理设置，请在配置中作为环境变量添加。

在可执行文件、参数、环境变量值和工作目录中，可以使用 `{{ENV_VAR}}` 引用 iCode 运行环境中的环境变量，从而复用已有配置值，避免在智能体配置中直接填写固定值或敏感信息。环境变量名只能包含字母、数字和下划线，且不能以数字开头。

例如，若 API 密钥保存在 `EXTERNAL_AGENT_API_KEY` 环境变量中，可以将外部智能体所需环境变量的值设置为：

```text
{{EXTERNAL_AGENT_API_KEY}}
```

保存配置、测试连接以及每次启动外部智能体时，iCode 都会解析引用的环境变量。若对应环境变量不存在或值为空，配置将无法保存，测试连接或调用也会失败。

参数和环境变量值也可以用 `{{!command}}` 使用命令输出的内容，例如 `{{!tokenprovider gettoken}}`。命令需要满足的条件参阅[通过命令获取 API 密钥](../configuration/models.md#通过命令获取-api-密钥)。每次 iCode 启动外部智能体时都会运行命令，运行中的智能体会一直使用启动时的值。如果命令第一次就失败，外部智能体不会启动。可执行文件和工作目录不能使用命令。

智能体运行期间，这台电脑的其他用户可能看到它的启动参数。如果智能体可以从环境变量读取敏感信息，请放在环境变量中。

## 设置工作目录

“工作目录”留空时，外部智能体使用 iCode 当前会话的工作目录。

“工作目录”可以填写相对路径或绝对路径；相对路径以当前会话的工作目录为基准。

默认情况下，外部智能体的工作目录必须位于当前会话的主工作目录或任一附加工作目录内。若要使用上述目录范围之外的目录，请勾选“允许 cwd 位于工作区外”。此选项只放宽目录校验，不会改变外部智能体的文件权限。启用前，请确认外部智能体程序可信，并检查目标目录是否包含敏感文件。

## 调整外部智能体配置

首次测试连接成功后，可以根据测试报告进一步完善外部智能体配置：

- **会话模式**：设置外部智能体的会话模式。填写测试报告中列出的模式 ID。
- **模型 ID**：指定外部智能体使用的模型。填写测试报告中列出的模型 ID。此设置不影响主智能体使用的模型。
- **配置选项**：设置外部智能体提供的其他配置项。填写测试报告中对应的配置项 ID 和值。

以上配置项均可留空。留空时，iCode 将使用外部智能体的默认配置。修改配置后，请重新测试连接。

默认情况下，如果外部智能体不支持指定的会话模式或配置选项，连接测试会失败。若希望忽略不支持的设置并继续连接，请启用“尽力应用模式和配置选项”。

“模型 ID”按尽力方式应用。如果外部智能体未列出指定模型，或以“不支持的方法”或“参数无效”错误拒绝切换，iCode 会继续使用外部智能体的默认模型；切换模型时出现其他错误则连接失败。

## 设置结果和超时

“结果”决定主智能体收到的内容：

- **最后一个消息片段**：只返回外部智能体最后一段回复，适合大多数任务。
- **完整记录**：返回外部智能体在本次调用中发送的所有消息片段，适合需要查看完整回复过程的任务。

“握手超时（秒）”限制启动进程、完成 ACP 初始化和打开会话所等待的时间。“空闲超时（秒；0 表示禁用）”限制调用期间未收到任何活动时的等待时间；设为 `0` 时不限制空闲等待时间。“测试”按钮不使用“握手超时（秒）”，始终最多等待 15 秒；启动较慢的智能体可能测试失败，但实际调用时仍可正常工作。

## 将外部 ACP 智能体添加到主智能体

保存外部智能体配置后，按照[为智能体配置子智能体](../configuration/agents.md#为智能体配置子智能体)中的步骤，将其添加到主智能体。

在“配置”下拉列表中，外部 ACP 智能体的名称带有 `(ACP)` 标记。选择对应的配置并保存即可。
