# 管理与恢复会话

会话包含对话历史及相关数据，例如回滚快照、诊断日志等。iCode 会自动保存会话，以便稍后恢复对话或查询历史任务。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中切换、命名、查找、恢复和删除会话，以及更换存储位置时如何迁移已有会话。

## 切换到新会话

智能体空闲时，根据是否需要保留当前会话的记录，在输入栏中使用对应命令：

| 目的 | 命令 | 对当前会话的影响 |
| --- | --- | --- |
| 开始新会话，稍后仍可恢复当前会话 | `/new` | 保留，可从会话列表恢复 |
| 开始新会话，不再保留当前会话 | `/clear` | 显示确认对话框，确认后永久删除，无法恢复 |

离开会话时（使用以上任一命令，或切换到其他会话），该会话在后台运行的 Shell 命令都会停止。详见[在后台继续运行的命令](../configuration/tools.md#在后台继续运行的命令)。

## 修改会话标题

可以通过以下任一方式修改当前会话的标题：

- 点击主界面左上角的“会话：…”区域，打开“会话标题”窗口，输入标题并点击“保存”。
- 在输入栏中输入 `/rename`，打开“会话标题”窗口，输入标题并点击“保存”。
- 在 `/rename` 后直接输入标题，例如 `/rename 修复登录问题`。

“会话标题”窗口顶部还会显示会话 ID。点击“复制 ID”可复制该 ID，例如之后用 `icode -s <会话 ID>` 恢复这个会话；点击“打开文件夹”可在文件管理器中打开保存该会话数据的文件夹。在 iCode 无法打开文件管理器的环境中（例如通过 SSH 连接时），不显示“打开文件夹”。

手动设置标题后，新标题会显示在会话列表和主界面中，iCode 将不再自动更新该会话的标题。若已开启[自动生成会话标题](../configuration/settings.md#会话)，清空“会话标题”窗口中的内容并保存后，iCode 会恢复已有的自动标题，并在后续任务中继续自动更新。

## 在终端标签页查看任务进度

终端标签页显示你最近发送的消息，iCode 更新会话标题后改为显示标题；你手动设置的标题会一直显示。标题前的标记表示当前任务的进展，在其他标签页工作时也能随时查看：

| 标记 | 含义 |
| --- | --- |
| 转动的点，例如 `⠋` | 智能体正在工作。 |
| `?` | 智能体在等你批准工具调用或回答问题。 |
| `!` | 子智能体运行失败，等你点击“重试”或“中止”。 |
| `✓` | 任务已完成。 |
| `✗` | 任务失败。 |

手动停止的任务不显示标记；开始下一个任务时，标记会清除。部分终端不显示标签页标题。

任务被停止或失败时，回复中已显示的部分会保留在对话和保存的会话中，发送下一条消息时智能体也会读到这部分内容。若改为不输入任何内容直接点击 **重试** 或 **继续**，智能体会重新撰写这条回复：开始重写时，要重写的文字会被移除，工具调用保留。

## 恢复已有会话

智能体空闲时，在输入栏中输入 `/resume`，可恢复最近的聊天会话。

需要查找和恢复其他会话时，按 **F1**、点击 `f1 会话` 或在输入栏中输入 `/sessions`，打开“聊天会话”窗口。窗口会列出会话 ID、标题、目录、最近活跃时间、对话轮次数和会话数据大小。每页最多显示 100 个会话，最近活跃的排在前面。

- **按最后使用位置筛选**：搜索框上方的“TUI”“CLI”“ACP”复选框分别对应最后在 TUI 中、通过 [`icode run`](../running/icode-run.md)，或在通过 [`icode acp`](../running/icode-acp.md) 连接的编辑器等客户端中使用的会话。默认只勾选“TUI”。旧版本 iCode 保存的会话按 TUI 处理。所做选择在退出 iCode 前一直保留。将鼠标悬停在会话上，可查看它最后在哪里使用。
- **翻页**：点击复选框右侧的“上一页”或“下一页”。
- **会话排序**：会话默认按最近活跃时间从新到旧排列。点击列标题可按该列对当前页排序：“最近活跃”“轮次”和“大小”首次点击时降序排列，其他列首次点击时升序排列。再次点击同一列标题可反转顺序。
- **搜索会话**：要查找会话，可在底部搜索框中输入会话 ID、标题、目录或曾经输入的提示词。搜索只在当前页中进行。
- **恢复会话**：选择目标会话后点击“恢复”；也可以双击目标会话，或使用上下方向键选择后按回车。iCode 会关闭当前对话视图，加载所选会话，并将工作目录切换到该会话保存时的主工作目录；当前会话仍会保存在列表中。恢复前可通过列表中的“目录”列核对将要恢复的工作目录。如果该目录已不存在，iCode 会请你选择另一个文件夹，详见[工作目录被删除或移动时](workspaces.md#工作目录被删除或移动时)。

恢复的会话沿用它保存时的智能体和模型。这不会改变新建会话（`/new`）使用的智能体和模型：你最近用 `#` 选择（或启动时使用）的智能体，以及你的默认模型。

恢复较长的对话时，iCode 会先显示最近的内容，可立即继续操作；更早的消息会在随后几秒内陆续加载到上方。

恢复的对话会在回复上方把保存下来的模型思考折叠为一行：**思考：**后接思考的开头；点击这一行可将其展开。回复被中断或失败时，被打断的那次请求中显示过的思考不会保存，因此不会出现。

成功完成的轮次默认还会收起中间执行过程。中途补充的用户消息和轮次中途压缩产生的压缩卡片始终可见，并将过程分成独立的片段。片段标题统计其中的工具调用次数和类别，例如 `12 次工具调用 · 8 次读取 · 4 条命令`，如有失败或中断的调用，末尾会标出次数；没有工具调用或属于压缩历史的片段显示**执行过程**。点击标题可查看对应片段，内层详情保持原来的开合状态。片段中只有一个思考块，或只有一段工具调用之间的文字时，直接折叠成它自己的那一行。只用键盘时，可用 `/fold` 统一切换过程块、工具组、思考和工具调用之间的文字：有展开的内容就全部收起，否则全部展开；仍在写出的思考和等待你输入的控件除外。复制命令仍包含中间回复，消息计数保持原有规则。如需让之后完成的轮次及之后打开的会话保持展开，可在[设置](../configuration/settings.md#显示偏好)中关闭**自动折叠已完成轮次**。崩溃恢复的最后一轮保持展开。

点击过程标题不会移走输入框焦点。恢复后仍在等待子 Agent 的轮次保持展开。压缩历史只显示部分工具详情，所以这些片段统一显示**执行过程**。

如果恢复的对话改用了与之前不同的模型服务，部分早先的推理内容可能会被略去，详见[切换当前模型配置](../configuration/models.md#切换当前模型配置)。

## 删除旧会话

打开“聊天会话”窗口，先核对会话 ID、目录和最近活跃时间。不确定时，可以先恢复会话确认内容，再返回“聊天会话”窗口。选择不再需要的会话，点击“删除”。

确认删除后，该会话的对话历史、回滚快照和会话内诊断数据等内容会被永久删除，无法恢复。删除会话不会撤销智能体已对工作目录文件做出的修改。

删除当前会话时，iCode 会同时开始新会话，与 `/clear` 类似。其他 iCode 实例正在使用的会话无法删除，请先关闭该实例。如果 iCode 无法删除会话的全部文件，会提示错误；请关闭可能正在使用这些文件的程序后重试。

## 查找会话 ID 和会话保存位置

当前会话 ID 显示在主界面左上角的“会话：…”区域；历史会话 ID 显示在“聊天会话”窗口的列表中。点击“会话：…”区域可打开“会话标题”窗口，在其中[复制会话 ID 或打开会话文件夹](#修改会话标题)。

输入 `/settings sessions`，或按 **F10** 后选择“会话”标签页，“会话存储根目录”下方的“使用中”会显示当前实际使用的 `sessions` 目录。每个会话保存在该目录下以会话 ID 命名的子目录中。

未自定义会话存储根目录时，macOS 和 Linux 的 `sessions` 目录默认为 `~/.chrys/sessions`，Windows 默认为 `%APPDATA%\chrys\sessions`。

根目录设置填写的是 `sessions` 所在的文件夹。如果配置目录、会话存储根目录或 `sessions` 本身是符号链接（或 Windows 目录联接），“使用中”会显示它实际指向的文件夹，该文件夹可以使用其他名称。存放在那里的会话照常使用。

在 macOS 上，这些目录也可以放在 exFAT 磁盘上。exFAT 磁盘不区分各用户的权限；在 Finder 的“显示简介”窗口中勾选了“忽略此宗卷上的所有权”的磁盘也是如此。在这样的磁盘上，这台 Mac 上的其他账户可以读取和修改 iCode 存放在其中的配置、会话和密钥。如需与其他账户隔离，请将这些目录放在 Mac 的内置磁盘上，或放在不是 exFAT 格式且未勾选该选项的磁盘上。

备份或迁移配置时，请复制整个配置目录。

## 迁移会话存储位置

更换会话存储位置时，需要设置新的会话存储根目录，并将已有会话迁移到新位置。新位置在重启后生效；仅修改存储位置不会自动迁移已有会话。

开始前，结束当前任务并关闭其他 iCode 实例，然后执行以下操作：

1. 输入 `/settings sessions`，或按 **F10** 后选择“会话”标签页，然后在“会话存储根目录”中选择新的根目录。
2. 点击“迁移会话”。确认“从”是当前使用的 `sessions` 目录，“到”是新根目录下的 `sessions` 目录，然后点击“迁移”。
3. 等待迁移完成，并根据结果处理未复制的会话：

   | 结果 | 说明 | 后续操作 |
   | --- | --- | --- |
   | 已复制 | 会话已复制到目标目录。 | 无需处理。 |
   | 已存在 | 目标中已有同一会话 ID，因此跳过。iCode 不会比较或更新目标内容。 | 无法确认目标版本时，建议更换空的目标目录重新迁移，或保留源数据。 |
   | 使用中 | 会话正在某个 iCode 实例中打开，因此跳过。 | 关闭其他实例后重试。若是当前会话，关闭设置窗口并执行 `/new`；不要在新会话中发送消息，然后再次迁移。 |
   | 忙碌 | 会话正在保存或被其他操作占用，因此跳过。 | 等待相关操作结束后重试。 |
   | 失败 | 会话复制失败。 | 根据窗口列出的路径和原因处理权限或路径问题后重试。 |

4. 处理“使用中”“忙碌”或“失败”的会话后，点击“关闭”，再点击“迁移会话”重新迁移（每次迁移完成后“迁移”按钮会被禁用），直到需要保留的会话均已复制。
5. 关闭所有 iCode 实例并重新启动，再按 **F1** 打开“聊天会话”窗口，确认重要会话已经出现并可以恢复。

迁移完成后，源目录会保留原数据，不会自动删除。确认迁移完整后，如需释放空间，关闭 iCode，再归档或删除迁移窗口中“从”所显示的旧 `sessions` 目录。手工删除无法撤销。

## 查看 token 用量和速度

智能体回复期间，输入栏上方的状态栏会显示文字到达的速度，例如 `92 tok/s`。如果几秒内没有新文字（例如正在运行工具），这个数字就会消失。它是根据屏幕上的文字估算的大致数值。

要查看所有会话的用量，输入 `/usage`。窗口有两个标签页，点击标签页或按 **Tab** 即可切换。窗口下边框会列出当前标签页可用的按键，按 **Esc** 关闭。数字是打开窗口时读取的；要看更新的数字，再次输入 `/usage` 即可。

**总览**每次显示一个日期范围。点击顶部的范围，或按左右方向键切换：

- **新增**：这段时间新增的 token，即没有命中提供商缓存的输入，加上输出（含思考）。这是最值得关注的数字；缓存读取单独列出，因为它通常大得多，费用也低得多。
- **命中**：输入中有多少来自提供商的缓存。
- **趋势**：所选范围内的新增 token：**今天**按小时显示，**本周**按天显示；更长的范围可点击**按日**或**按周**，或按 **t** 切换。只有淡色底纹的列，表示那段时间没有新增 token。
- **分组**：按模型、来源（主智能体、子智能体、工作流节点，以及生成会话标题等后台任务）或项目汇总的表格。点击表格上方的按钮或按 **g** 切换。用上下方向键或鼠标点击选择一行。窗口较窄时，表格显示的列会少一些。
- **速率**：模型产生输出的速度，从收到第一个数据块到响应结束计算，统计所有流式请求。它受提供商和网络影响，可能与提供商公布的速度不同。

**日历**显示一个月的新增 token，用量越多的日子颜色越深，日历下方的一行说明每种颜色的含义；窗口较窄时只标出最低和最高两端。窗口空间足够时，每天还会显示当天的 token 数。点击某天或用方向键选择日期，旁边会显示当天的数字和主要模型；窗口很窄时不显示这个面板。点击月份两侧的箭头，或按 **[** 和 **]** 切换月份。

请注意：

- 日期按电脑的时区计算，每周从周一开始。
- 在提供商报告用量之前就结束的请求会计入调用次数，但不增加 token。**总览**底部一行会说明所选范围内有多少这样的请求，日期面板底部会说明当天有多少。
- 已删除的会话和外部 ACP 智能体不计入。
- 旧版本保存的会话，DeepSeek 的缓存读取可能偏少，中途失败的请求可能没有用量。

## 查看会话耗时

按 **F12** 打开轨迹面板。**概览**汇总耗时和用量，**时间线**展示各轮对话与操作，**洞察**帮助分析等待原因，**会话数据**展示已保存的会话。长会话会在后台分析，期间显示加载指示器。耗时分析保留操作之间的重叠关系，因此关键路径不会重复计算并行工作的时间。

如果 iCode 无法记录某个会话的轨迹，会显示警告，提示此会话的轨迹记录已关闭。你可以照常继续工作，只是轨迹面板和导出不会再得到这个会话的新数据。工作流运行不会显示此警告。常见原因包括：该会话之前的记录尚未停止（关闭曾打开该会话的 iCode 窗口即可结束）；会话 `trajectory` 文件夹中的文件可被其他用户读取，或属于其他用户；`trajectory` 文件夹是一个链接；iCode 无法读取轨迹密钥（iCode 配置目录中的 `trajectory-hmac.key`）；轨迹无法安全地继续写入，例如由更新版本的 iCode 写入的轨迹。

如果 Shell 命令的文件内容比较因无法读取文件而未能完成，文件变更概览会标记检测不完整。已记录的变更列表可能存在遗漏；依据它回滚前，请先检查相关文件或 Git diff。因文件大小或二进制文件限制而跳过内容比较，本身不会触发此提示。

## 在会话数据中关联文件变更与模型请求

如果要根据会话文件统计数据，请用下面的 ID 关联记录，不要按时间或工具调用顺序推测。旧版本 iCode 写入的记录没有这些 ID，有些记录也始终不会有；缺少 ID 时，应把关联视为未知。

**哪次工具调用改动了文件。** `session.json` 中记录的每条文件变更都有 `tool_operation_id`。在 `trajectory/events.jsonl` 中，该工具调用的 `tool.operation.started` 和 `tool.operation.finished` 事件的 `operation_id` 与它相同，子智能体运行的工具也是如此。对于主智能体的工具调用，回复消息 `contents` 中的工具调用条目，以及其后工具消息中对应的结果条目，也以 `_chrys_operation_id` 记录同一个值。回复消息本身的 `_chrys_operation_id` 是另一个值，用于标识模型请求（见下文）。一次工具调用可能改动多个文件。

**哪次请求返回了模型回复。** `session.json` 中每条模型回复消息都带有 `_chrys_request_attempt_id`，即返回这条回复的 HTTP 请求的 ID；消息的 `_chrys_operation_id` 与这条回复的 `model.request.*` 和 `model.exchange.finished` 事件的 `operation_id` 相同。在 `trajectory/events.jsonl` 中：

- `model.request.prepared` 表示 iCode 即将发送的一次请求，`model.request.headers_received` 表示提供商对该请求的响应。两者带有相同的 `request_attempt_id`。后者还记录 HTTP 状态码，以及提供商返回的请求 ID（`provider_request_id`，提供商未返回时没有）。
- 每次自动重试或重定向都是一次单独的请求，各有自己的 ID。没有 `model.request.headers_received` 事件的请求，可能在到达提供商之前就失败了。
- 收到响应不代表回复已经完成。要了解回复如何结束，请查看 `operation_id` 相同的 `model.exchange.finished` 事件。

iCode 还会通过 `Chrys-Request-Attempt-Id` 请求头把这个 ID 发给提供商，便于在网关或代理日志中查找对应请求。如果开启了原始 HTTP 日志，日志中每次请求的 `exchange_id` 也是这个 ID。

这些 ID 只用于关联记录。Shell 命令执行后检测到的文件变更保留原有的可信度，这个 ID 并不能证明变更一定由该命令造成。这些 ID 也不统计改动行数。

## 导出会话的回合与模型请求

需要排查请求失败或分析 token 用量时，可以将会话的回合、模型请求和重试记录导出为 JSON 文件。将 `<id>` 替换为你的会话 ID：

```bash
icode trajectory export --session <id> --format turns --out turns.json
```
