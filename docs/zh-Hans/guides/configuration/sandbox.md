# 配置 Shell 沙箱

iCode 可以把智能体的 Shell 命令放进沙箱里运行。沙箱限制的是这条命令的进程能做什么。本指南说明如何在用户设置里打开沙箱、打开之后你会看到什么，以及哪些行为保持不变。

这项设置只作用于 Shell 命令，其他工具不变。

## 打开沙箱

沙箱默认关闭。要打开它，编辑用户设置文件 `~/.chrys/settings.yaml`。在 Windows 上，这个文件是 `%APPDATA%\chrys\settings.yaml`。

把 `sandbox.enabled` 设为 `true`：

```yaml
sandbox:
  enabled: true
  url: ""
  token: ""
```

- `sandbox.enabled`：`true` 表示打开沙箱。`false` 表示关闭。
- `sandbox.url`：留空，让 iCode 在这台计算机上启动自带的沙箱。只有当你已经有一个沙箱服务、希望 iCode 连过去时，才填写地址。填写地址后，iCode 连接该服务，不再自己启动沙箱。
- `sandbox.token`：可选。`sandbox.url` 留空时，这里也留空。这时 iCode 会启动自带的沙箱，并发送一个由 iCode 为该沙箱生成的令牌。只有当 `sandbox.url` 指向的沙箱服务要求令牌时，才填写 `sandbox.token`。iCode 会把这个令牌发给该服务。

请把这些键写在用户设置文件里。项目中的 `.chrys/settings.yaml` 不能打开沙箱，也不能修改地址或令牌。

## 沙箱关闭时

默认是关闭的。关闭时，Shell 命令的行为和现在一样。iCode 在这台计算机上运行命令，运行过程中显示输出，也可以把命令转到后台。详见[在后台继续运行的命令](./tools.md#在后台继续运行的命令)。

## 仅在 Linux 上运行，以及 iCode 启动的沙箱

沙箱只在 Linux 上运行。这台计算机必须是 Linux，并且必须已安装 bubblewrap 和 python3。沙箱会运行 python3。iCode 不会替你安装 bubblewrap 或 python3。

iCode 不会以 root 启动这个沙箱。如果以 root 启动 iCode，沙箱会拒绝运行命令。

打开沙箱后，iCode 会启动随 iCode 一起提供的沙箱引擎。你不需要单独安装或部署另一套产品，也不需要自己启动这个引擎。此时请把 `sandbox.url` 留空。如果这个沙箱启动失败，错误信息会包含沙箱引擎自己的报错。

## 沙箱无法运行命令时

打开沙箱之后，iCode 在沙箱里运行这条 Shell 命令。如果沙箱无法运行该命令，工具会返回一条错误，iCode 不会改为在这台计算机上运行这条命令。你会在工具结果里看到这条错误。该命令不会在沙箱以外启动。

## 审批仍然生效

命令运行之前，审批仍然生效。如果这条命令需要审批，iCode 会先询问你，或按你正在使用的审批模式处理，然后才在沙箱里运行。你拒绝后，命令不会运行。详见[配置审批模式](./approval.md)。

## 输出与后台命令

沙箱模式不会实时显示终端输出。命令结束后，工具结果才会显示输出和退出码。

沙箱模式不会把命令转到后台。命令到达时间上限后会在沙箱中结束，不会变成后台任务。按 **Ctrl+T** 也不会把它转到后台，它也不会出现在**后台任务**中。

## 命令写入的文件

工作区会以可写方式挂载到沙箱内，命令可以读取和修改其中的文件。这些修改写在你计算机上的工作区里。停止沙箱不会撤销命令已经写在那里的文件。

沙箱限制的是命令的进程，不是工作区的还原点。

## 网络访问

iCode 自带的策略允许主机网络。沙箱里的命令可以使用这台计算机的网络。这不是一个断开网络的沙箱。

## 设置何时生效

修改这些设置后，要到下一次重新加载智能体时才会生效，不会在一轮进行到一半时生效。

保存用户设置文件，然后退出 iCode 再启动，让智能体重新加载。重新加载之后的 Shell 命令使用新设置。已经在进行的这一轮仍使用原来的设置：iCode 不会在这一轮进行到一半时，把命令改到沙箱里或改回沙箱外运行。

## Windows 和 macOS

在 Windows 和 macOS 上，打开沙箱会使 Shell 命令失败。工具返回的错误会说明沙箱只支持 Linux，iCode 不会运行这条命令。

保持关闭则没有任何变化，Shell 命令的行为与现在相同。
