# 配置审批模式

智能体执行工具调用（例如运行 Shell 命令、写入文件）时，iCode 可能要求先经过审批。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中选择审批模式、处理审批请求，以及不同运行方式下的审批设置。

## 了解三种审批模式

审批模式决定 iCode 如何处理需要审批的工具调用。具体哪些调用需要审批，由智能体配置文件中的 `approval` 审批策略和 iCode 的安全规则共同决定，详见[智能体配置文件参考中的 approval 字段](../../reference/agent-profile.md#approval)。

三种审批模式的行为如下：

| 模式 | 行为 |
| --- | --- |
| 手动 | 需要审批的工具调用会弹出对话框，等待人工批准或拒绝。 |
| 自动 | 由审批裁判模型评估工具调用；判定为安全的调用自动批准，可疑的调用标记出来，等待人工决定。 |
| 绕过 | 即使智能体配置或安全规则判定需要审批，工具调用也会不经询问直接执行。 |

**审批裁判模型**：“自动”模式会调用审批裁判模型，并将当前时间、工作区目录、本轮全部用户提示及其中最新一条、工具名称、工具类别及参数发送给该模型。审批裁判模型默认使用当前会话的模型。如需修改，按 **F10** 打开“设置”窗口，选择“模型与智能体”标签页，然后在“模型角色”区域修改“审批裁判模型”。

> **提示**
>
> **手动模式不代表每次工具调用都会弹窗**。手动模式只表示需要审批的调用由用户决定；不需要审批或符合自动放行条件的调用会直接执行，详见[了解自动放行与安全保护](#了解自动放行与安全保护)。

## 在 TUI 中切换审批模式

在 TUI 中可以使用以下任一方式切换当前使用的审批模式：

- 在输入栏中输入 `/approval`，按空格键或 **Enter** 打开审批模式列表，然后选择模式。也可以直接指定模式，例如 `/approval auto`。
- 点击界面右上角的审批模式标签，在“审批模式”窗口中选择。

任务运行期间也可以切换模式。已弹出的审批请求不受影响，后续工具调用将使用新模式。

### 设置默认审批模式

未更改默认设置时，首次启动 TUI 默认使用“手动”审批模式。切换当前审批模式时，iCode 也会更新下次启动的默认模式：选择“手动”或“自动”会将所选模式保存为默认值；选择“绕过”只对当前运行生效，为避免重启后继续绕过审批保护，此时下次启动的默认模式会保存为“自动”。

若只需修改下次启动的默认模式，而不改变当前使用的审批模式，请按 **F10** 打开“设置”窗口，在“安全”标签页中修改“默认审批模式”。“设置”窗口不提供“绕过”模式作为可保存的默认值。

## 在 TUI 中处理审批请求

需要审批的工具调用会弹出“工具审批”对话框，显示工具名称和调用参数；编辑文件时还会显示计划差异，便于执行前检查改动。

- 按 **Y** 批准，或按 **N** 拒绝，也可以点击对应按钮。对话框无法用 **Esc** 关闭，必须明确批准或拒绝。
- 拒绝时可以填写原因，原因会发送给智能体，帮助其调整后续行为。填写原因后，批准按钮不可用。
- 自动模式下，对话框先显示“正在评估”。模型判定安全后，对话框自动关闭；模型判定可疑时，标题变为“自动审查已标记”并展示理由，等待人工决定。评估期间也可以直接批准或拒绝。如果审批裁判模型不可用或评估失败，iCode 不会自动批准工具调用，而是保留审批对话框，等待人工决定。

## 了解自动放行与安全保护

通过 `CHRYS_DAA_MINIMAL=1` 或在[用户设置](../../reference/settings.md)中将 `approval.daa_minimal` 设为 `true` 启用 minimal DAA。符合条件的审批对话框可选择会话或项目范围的精确复用，或字面命令前缀复用；默认仍为仅批准一次。

DAA 目前只接入主 agent。子代理和工作流节点不会复用或保存 DAA 授权，仍按原有审批策略和模式处理，包括适用时的自动批准和绕过审批。

启用 minimal DAA 时，编辑审批请求只对本次编辑生效，不会把原请求保存为可复用授权。编辑后的参数会经过 `before_tool_call` hooks；如果 hook 进一步改写参数，iCode 会请求确认改写后的调用，而不会重复执行同一次改写。超出 DAA 支持的 JSON 身份格式的参数，只有在确认快照支持其类型时才能走普通逐次审批（见下文），不能复用或创建 DAA 授权。

SESSION 授权绑定会话 ID，在同一会话的 agent 重建或恢复后仍可复用；新会话不会继承它们。目前历史会话授权仍保留在 DAA 存储中，关闭审批对话框或重建 agent 不会删除这些记录。

文件授权绑定解析目录符号链接后的物理目标。链接改向后需要重新审批；write/edit 工作线程会再次核对目标，并使用已确认的物理路径执行。路径末尾的文件本身是符号链接时，仍走普通审批，因为原子替换会替换链接本身。此时逐次审批仍跟踪物理父目录、末尾目录项及链接当前指向的目标：审批等待中任一目标变化都需重新确认，交给工作线程后才发生的变化则被拒绝。无法解析目标也不会关闭这项检查。没有物理路径版本标记的旧文件授权将被忽略，需要重新批准；命令授权不变。这些检查不等同于文件系统沙箱，不能隔离其他进程在操作系统写入期间并发替换目录项的行为。

逐次审批使用独立、保留类型的参数快照，支持内置的 str、bool、int、float（包括非有限值）、None、bytes、bytearray、dict、list、tuple、set 和 frozenset，以及 PurePath/Path 和枚举；嵌套值也须属于这些支持的类型。枚举快照保留枚举类、成员名和冻结后的值；有效的 StrEnum、IntEnum 和普通 Enum 参数均可进入正常审批。支持的参数即使不能生成可复用 DAA 授权，在等待审批时发生变化仍须重新确认。

启用 DAA 后，到达此确认步骤的调用若包含 date/datetime、UUID、Decimal、Pydantic 模型实例、其他不支持的宿主对象或循环引用，会在弹窗前被拒绝，并返回 `Tool arguments cannot be safely compared for approval.`。需要这些类型的自定义工具须关闭最小 DAA，或使用支持的参数类型。未启用 DAA 时不受此限制。

以下操作通常会自动放行，不弹出审批对话框：

- 不访问敏感目标的安全只读 Shell 命令，例如 `ls`、`cat`、`grep`。
- 工作目录 Git 仓库内、且不访问敏感目标的文件写入。

Shell 命令和文件读写访问 `.env`、凭据、私钥等敏感目标时，即使操作只读取文件或写入 Git 工作目录，也仍会进入审批流程。该保护适用于“手动”和“自动”模式；“绕过”模式会跳过这些审批保护。

技能脚本以当前用户权限在本机运行，不受沙箱隔离，因此默认会请求审批。会话使用绕过模式时，技能脚本会不经询问直接运行。安装或运行第三方技能前，应先检查其 `SKILL.md`、脚本和相关文件，确保可信。

网络工具会向外部服务发送请求，因此 `web_search` 和 `web_fetch` 类别默认也会请求审批，即使智能体的 `approval.default` 为 `auto`。针对这些类别或工具名称的显式 `approval.overrides` 规则仍然优先。“自动”模式下审批裁判模型可以批准这些调用，“绕过”模式下它们会不经询问直接执行。参阅[配置网络工具](./web-tools.md#审批网络工具调用)。

## 在 TUI 中验证审批模式

选择内置的 Code Agent，然后提交以下请求：

```text
使用 Shell 工具运行 icode --version
```

该命令只显示版本，不修改文件，但不属于自动放行的只读 Shell 命令。预期结果如下：

- 手动模式下，弹出“工具审批”对话框；批准后显示 iCode 版本。
- 自动模式下，审批裁判模型通常会判定该命令安全并自动批准；若模型将其标记为可疑，则对话框会显示评估理由并等待决定。
- 绕过模式下，不显示审批对话框，直接运行命令并显示 iCode 版本。

## 其他运行方式的审批模式

其他运行方式使用以下审批模式和切换方式：

- **无界面命令行（`icode run`）**：始终绕过审批，不提供审批相关参数。
- **iCode ACP 服务**：默认手动，可用 `icode acp --approval manual|auto|bypass` 指定初始模式；支持该能力的 ACP 客户端也可以切换当前会话的模式。
- **浏览器托管的 TUI（`icode serve`）**：可按照前文介绍的 TUI 操作切换审批模式和处理审批请求。
