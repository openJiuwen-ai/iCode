# 配置审批模式

智能体执行工具调用（例如运行 Shell 命令、写入文件）时，iCode 可能要求先经过审批。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中选择审批模式、处理审批请求，以及不同运行方式下的审批设置。

## 了解三种审批模式

审批模式决定 iCode 如何处理需要审批的工具调用。具体哪些调用需要审批，由智能体配置文件中的 `approval` 审批策略和 iCode 的安全规则共同决定，详见[智能体配置文件参考中的 approval 字段](../../reference/agent-profile.md#approval)。

三种审批模式的行为如下：

| 模式 | 行为 |
| --- | --- |
| 手动 | 需要审批的工具调用会弹出对话框，等待人工批准或拒绝。 |
| 自动 | 由审批裁判模型评估工具调用；判定为安全的调用自动批准，可疑的调用标记出来，等待人工决定。 |
| 绕过 | 即使智能体配置或安全规则判定需要审批，工具调用也会不经询问直接执行。 |

**审批裁判模型**：“自动”模式会调用审批裁判模型，并将当前时间、工作区目录、本轮全部用户提示及其中最新一条、工具名称、工具类别及参数发送给该模型。审批裁判模型默认使用当前会话的模型。如需修改，按 **F10** 打开“设置”窗口，选择“模型与智能体”标签页，然后在“模型角色”区域修改“审批裁判模型”。

> **提示**
>
> **手动模式不代表每次工具调用都会弹窗**。手动模式只表示需要审批的调用由用户决定；不需要审批或符合自动放行条件的调用会直接执行，详见[了解自动放行与安全保护](#了解自动放行与安全保护)。

## 在 TUI 中切换审批模式

在 TUI 中可以使用以下任一方式切换当前使用的审批模式：

- 在输入栏中输入 `/approval`，按空格键或 **Enter** 打开审批模式列表，然后选择模式。也可以直接指定模式，例如 `/approval auto`。
- 点击界面右上角的审批模式标签，在“审批模式”窗口中选择。

任务运行期间也可以切换模式。已弹出的审批请求不受影响，后续工具调用将使用新模式。

### 设置默认审批模式

未更改默认设置时，首次启动 TUI 默认使用“手动”审批模式。切换当前审批模式时，iCode 也会更新下次启动的默认模式：选择“手动”或“自动”会将所选模式保存为默认值；选择“绕过”只对当前运行生效，为避免重启后继续绕过审批保护，此时下次启动的默认模式会保存为“自动”。

若只需修改下次启动的默认模式，而不改变当前使用的审批模式，请按 **F10** 打开“设置”窗口，在“安全”标签页中修改“默认审批模式”。“设置”窗口不提供“绕过”模式作为可保存的默认值。

## 在 TUI 中处理审批请求

需要审批的工具调用会弹出“工具审批”对话框，显示工具名称和调用参数；编辑文件时还会显示计划差异，便于执行前检查改动。参数过长、无法一次显示时（例如整个文件的内容），会放在带滚动条的框里：在框上滚动鼠标滚轮，或点击该框后用方向键、**Page Up**、**Page Down**、**Home** 和 **End** 查看到末尾。可能隐藏文字或打乱其显示顺序的字符（如终端控制码）显示为 **�**；复制参数时仍得到原文。

- 按 **Y** 批准，或按 **N** 拒绝，也可以点击对应按钮。对话框无法用 **Esc** 关闭。如果设置了[人工审批超时](#设置人工审批超时)，到时仍未答复的请求会被自动拒绝。
- 拒绝时可以填写原因，原因会发送给智能体，帮助其调整后续行为。填写原因后，批准按钮不可用。
- 自动模式下，审批裁判模型评估调用期间不弹出对话框，界面右上角审批模式标签的左侧会显示“审查中”，前面带一个转动的图标。模型判定安全的调用直接执行，不弹对话框；模型判定可疑时，弹出标题为“自动审查已标记”的对话框，展示理由并等待人工决定。为避免误按按键直接批准，光标先停在原因输入框：可以填写原因后拒绝，也可以按 **Tab** 移到按钮上。如果审批裁判模型不可用、评估失败或超时，iCode 不会自动批准工具调用，而是弹出审批对话框，等待人工决定。
- 如果想在评估期间就看到每个调用，按 **F10** 打开“设置”窗口，在“安全”标签页中关闭“仅在自动审查标记后弹出审批对话框”。之后对话框会立即弹出并显示“正在评估”：模型判定安全后自动关闭，评估完成前也可以直接批准或拒绝。

## 记住审批

你可以让 iCode 记住你批准过的 Shell 命令或文件修改，之后智能体发出相同请求时不再询问。Shell 命令和文件写入、编辑的审批窗口中会出现“记住审批”框：

1. 勾选“相同命令不再询问”（文件为“修改这些文件不再询问”）。
2. 选择“本会话”或“本项目”。“本会话”在恢复该会话后仍然有效；“本项目”在同一项目的其他会话中也有效。
3. 选择“批准”。

之后智能体再发出相同请求时会直接运行，不再弹出审批窗口。只会记住这条命令或这些文件，其他操作仍会询问。不勾选直接批准，只批准本次调用。以下情况不会被记住：

- 自动模式下由审批裁判模型批准的调用。被自动审查标记的调用仍会显示“记住审批”框，你批准时可以选择记住。
- 在审批窗口中编辑过的请求：编辑后的调用只运行一次。
- 智能体指定了运行文件夹的命令，以及涉及凭据、SSH 密钥等敏感文件的请求。
- 子智能体、工作流、MCP 工具和其他工具。

如果在你批准之后、实际运行之前，文件夹或文件链接发生变化，使调用会作用到其他位置，该调用会报错停止，而不会在新位置运行。

对于简单命令，“高级选项”中还有“允许在命令末尾添加参数”。勾选后，智能体在该命令末尾添加更多参数时也不再询问。例如这样记住 `git push origin main` 后，`git push origin main --force` 也会直接运行，因此窗口会显示警告。除非你信任所有可能被添加的参数，否则请不要勾选。

如果 iCode 无法保存你的选择，本次调用仍会运行，并提示未能记住该审批。

### 管理已记住的审批

使用 `icode approvals` 命令查看和删除已记住的审批：

```bash
icode approvals list                         # 列出所有已记住的审批
icode approvals list --project /work/demo    # 只看某个项目
icode approvals list --session SESSION_ID --json
icode approvals revoke GRANT_ID              # 按列表中的 ID 删除一条
icode approvals clear --project /work/demo   # 删除某个项目的全部审批
icode approvals clear --session SESSION_ID   # 删除某个会话的全部审批
icode approvals clear --all                  # 全部删除
```

会话的审批会随该会话一起删除，用 `/fork` 创建分支时不会被复制到分支。项目的审批会一直保留，直到你删除。

## 了解自动放行与安全保护

以下操作通常会自动放行，不弹出审批对话框：

- 不访问敏感目标的安全只读 Shell 命令，例如 `ls`、`cat`、`grep`。
- 工作目录 Git 仓库内、且不访问敏感目标的文件写入。

Shell 命令和文件读写访问 `.env`、凭据、私钥等敏感目标时，即使操作只读取文件或写入 Git 工作目录，也仍会进入审批流程。该保护适用于“手动”和“自动”模式；“绕过”模式会跳过这些审批保护。

Skill 脚本以当前用户权限在本机运行，不受沙箱隔离，因此默认会请求审批。会话使用绕过模式时，Skill 脚本会不经询问直接运行。安装或运行第三方 Skill 前，应先检查其 `SKILL.md`、脚本和相关文件，确保可信。

网络工具会向外部服务发送请求，因此 `web_search` 和 `web_fetch` 类别默认也会请求审批，即使智能体的 `approval.default` 为 `auto`。针对这些类别或工具名称的显式 `approval.overrides` 规则仍然优先。“自动”模式下审批裁判模型可以批准这些调用，“绕过”模式下它们会不经询问直接执行。参阅[配置网络工具](./web-tools.md#审批网络工具调用)。

## 在 TUI 中验证审批模式

选择内置的 Code Agent，然后提交以下请求：

```text
使用 Shell 工具运行 icode --version
```

该命令只显示版本，不修改文件，但不属于自动放行的只读 Shell 命令。预期结果如下：

- 手动模式下，弹出“工具审批”对话框；批准后显示 iCode 版本。
- 自动模式下，审批裁判模型评估命令期间，审批模式标签左侧显示“审查中”。模型通常会判定该命令安全，不弹出审批对话框就显示 iCode 版本；若模型将其标记为可疑，则对话框会显示评估理由并等待决定。
- 绕过模式下，不显示审批对话框，直接运行命令并显示 iCode 版本。

## 其他运行方式的审批模式

其他运行方式使用以下审批模式和切换方式：

- **无界面命令行（`icode run`）**：始终绕过审批，不提供审批相关参数。
- **iCode ACP 服务**：默认手动，可用 `icode acp --approval manual|auto|bypass` 指定初始模式；支持该能力的 ACP 客户端也可以切换当前会话的模式。
- **浏览器托管的 TUI（`icode serve`）**：可按照前文介绍的 TUI 操作切换审批模式和处理审批请求。

## 设置人工审批超时

按 **F10** → **设置** → **安全**，在**审批**区域修改**人工审批超时（秒）**。此设置同时适用于 TUI 和 ACP 接入，默认值为 **0（不超时）**，正数表示等待的秒数，负数会调整为 **0**。保存后重启 iCode（TUI 或 ACP 服务）生效。

配置正数超时后，TUI 中当审批对话框显示且进入等待人工决定的阶段时开始计时；排队等待其他审批对话框结束，以及准备对话框内容（包括文件差异预览），都不会消耗这段时间。ACP 中，从服务发出人工审批请求时开始计时。超过等待时间仍未收到答复，iCode 会拒绝本次工具调用。

不设超时时，请求会一直等待，直到你批准或拒绝、请求被取消或会话关闭。停止 ACP 服务也会结束仍在等待的审批。
