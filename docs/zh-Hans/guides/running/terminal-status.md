# 在终端中显示 iCode 的状态

当 iCode 的终端界面运行在一个支持 Program Status Protocol(OSC 7501)的终端里时,iCode 会持续告诉终端自己正在做什么:空闲、工作中、等待你、已完成或已失败。终端可以随意选择展示方式——标签页上的旋转图标或徽标、状态列表、回复就绪时的通知。你可以去别的窗口干活,仍然一眼看到 iCode 的进展。

这一切自动发生:无需开启,也没有配置项。iCode 一启动就开始上报,并在每个回合中持续刷新终端里显示的状态。

## iCode 上报的内容

| iCode 时刻 | 上报的状态 |
| --- | --- |
| iCode 启动,或正在进行的回合被中断 | `idle`——等待你的下一条消息 |
| 一条回复或一个工作流运行正在进行 | `working` |
| iCode 在等你决定:工具审批,或回答一个问题 | `blocked`——消息为工具名加简短摘要,或问题内容 |
| 一条回复已完成且你还没有查看 | `done`——消息为回复的第一行 |
| 回合失败并停止 | `error`——消息为错误信息的第一行 |

你回应审批或问题后,状态回到 `working` 继续本回合,随后落到 `done` 或 `error`。

## 在哪里能看到

协议的效果由终端自己决定如何呈现。Ghostty 和 Rex 目前支持该协议:例如在 Ghostty 里,一个非聚焦的 iCode 标签页会在 agent 工作时显示旋转图标,完成或失败时显示标记;终端还可以在任务完成时提供通知。

不支持该协议的终端会完全忽略它,因此 iCode 的上报不会带来任何干扰。如果把 iCode 跑在终端多路复用器里,那么 iCode 直接面对的"终端"就是多路复用器——状态只有在该多路复用器把协议透传给外层终端时才会到达外层,请查阅它的文档。

两种情况不会上报:浏览器里运行的 iCode(`icode serve`,因为浏览器页面不是终端),以及无界面的 `icode run`(它以纯文本汇报进度)。
