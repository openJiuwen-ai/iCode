# 独立通道数据观察（tool-detail / 输入触发 / ai-code）

- 日期：2026-10-09
- 关联实现：[../实现方案/02-tool-detail上报实现.md](../实现方案/02-tool-detail上报实现.md)、[../实现方案/03-ai-code上报实现.md](../实现方案/03-ai-code上报实现.md)

## 一、通道特点

这三类上报走统一 HTTP 出口（`aixcoding/http.py`），POST 到 csas 后端——`telemetry-mock` **能收到**，可直接查库观测（与 llm-call 搭车通道相反）。

## 二、前置准备

### 1. 起 mock

```cmd
uv run python aixcoding/telemetry-mock/server.py
:: 默认 127.0.0.1:4321，SQLite :memory:
:: 可选：--port N / --db mock.db（落文件便于 sqlite3 直查）/ --require-token secret / --quiet
```

启动后观察页：http://127.0.0.1:4321/debug/view

### 2. 让 iCode 指向 mock（LOCAL profile）

`config.py` 的 LOCAL profile 的 base_url = `http://127.0.0.1:4321/csas`，report 基址 = `.../csas/telemetry/api/v1`。二选一：

- 环境变量：`set AIXCODING_EXTENSION_PROFILE=LOCAL`
- 或 `%USERPROFILE%\.chrys\aixcoding.yaml` 里写 `profile: LOCAL`

（若 mock 加了 `--require-token`，需同步配 `AIXCODING_TOKEN` 环境变量或 yaml 的 `token`，请求头为裸名 `token` 而非 Bearer。）

### 3. 跑引擎触发上报

```cmd
uv run icode run "帮我读一下 README.md"    :: 触发 read_file → tool-detail save + update
```

## 三、观察手段

| 手段 | 说明 |
|---|---|
| `/debug/view`（浏览器） | HTML 观察页：6 区块列表、sessionId/funcId 过滤、点击展开原文、2s 自动刷新、清空 |
| `GET /debug/reports?interface=&sessionId=&funcId=&limit=` | 按接口查询（`interface` 必填，可取 `rejected`；`limit` 1..500 默认 100） |
| `GET /debug/dump` | 全表导出（六键，每表 ≤500 条） |
| `POST /debug/clear` | 清空全部表 |
| 直接查 SQLite | 用 `--db mock.db` 启动时，可用 sqlite3 直接查表 |

## 四、各类上报核对要点

| 上报 | 落库表 | 关键字段核对 |
|---|---|---|
| tool-detail save | `tool_detail_saves` | `funcId`/`funcName`/`funcType`(skill=0/MCP=1/内置=3)/`sessionId`/`requestId`/`value`(白名单) |
| tool-detail update | `tool_detail_updates` | `funcId`/`codeStatus`(1成功/2失败/3 PENDING/4拒绝)/`originalLines`/`addedLines`/`deletedLines`/`funcErrorMessage` |
| 输入触发（skill） | `tool_detail_saves` | `funcType=0`、`funcName`=skill 名（单条 save，无 update） |
| ai-code | `ai_code_saves` | `reportId`/`filepath`/`block_count`/`codeStatus`(1/5)/`sourceType`/`sessionId`/`requestId` |

> 表名见 `aixcoding/telemetry-mock/store.py::INTERFACE_TABLES`；每表均存 `body_json` 原文，可核对完整报文。

## 五、故障注入验证吞错

`POST /debug/faults` 运行期切换故障模式，验证 iCode 上报"只记日志绝不抛出"：

| 模式 | 行为 | 用途 |
|---|---|---|
| `http500` / `http503` | **先落库**再回 500/503 | 验证网络错误下吞错 + 报文已发出 |
| `slow` | 延迟 `slowMs` 后正常响应 | 验证超时/慢后端 |
| `envelope_reject` | **先落库**再回业务失败 envelope | 验证业务失败吞错 |
| `drop_body` | 不落库直接断连 | 验证连接重置下吞错 |

```cmd
curl -X POST http://127.0.0.1:4321/debug/faults -H "Content-Type: application/json" -d "{\"mode\":\"http500\",\"rate\":1.0}"
:: {"mode":"none"} 复位
```
