# ADR-0001：手册定制落位 fork 命名空间并切换 wheel 捆绑源

- 责任人：赵阔
- 状态：已确认
- 确认日期：2026-11-10
- 确认意见：同意。
- 批次：batches/user-manual
- 生效条件：随 design.md 签认一并确认（R10）

## 背景

0.33 期用户手册定制直接改上游 `docs/{en,zh-Hans}/` 树，0.35.1 升级时整树冲突实际发生；
同时内网客户安装版 F8 只能读 wheel 捆绑副本（源 = `docs/`），定制内容到不了客户侧。
手册更新进入常态（版本同步、去链、措辞统一），需要一次性的落位与构建契约决策。

## 决策

1. 定制手册落位 `aixcoding/manual/`（fork 专属命名空间，双语树 + `index.yaml`）；
   仓库 `docs/` 保持上游项目版本**零定制**，作为每次升级的对齐基准。
2. wheel 捆绑源切换：`pyproject.toml` force-include 源键 `"docs"` → `"aixcoding/manual"`
   （定制点 C145）；`scripts/check_wheel.py` 捆绑完整性比对源同步切换（C146，与 C145
   同生共死）。安装版 F8 由此展示定制手册。
3. 开发态指向经 `CHRYS_DOCS_ROOT`（上游 `resolve_docs_root()` 第一优先级扩展点）实现，
   由本地启动器设置；**不改 `src/chrys/foundation/documentation.py`**。
4. F8 三形态指向体系（终态契约）：
   开发机（启动器）→ `CHRYS_DOCS_ROOT` → `aixcoding/manual/`；
   内网客户安装版 → wheel 捆绑副本（源 = `aixcoding/manual/`）；
   源码直跑（无启动器）→ 兜底 `docs/`（项目版本，已知限制，登记于 requirements 非目标）。
5. 配套治理：`[tool.ruff] extend-exclude = ["aixcoding/manual"]`（C148）——手册是交付
   内容，围栏代码示例中的对齐注释是有意排版，不参与格式化器重排；契约测试断言键随
   捆绑源跟改（C147，评审 F1 增补）。

## 理由（否决备选）

- **否决 A（直接定制 docs/）**：升级冲突面高（整树 50+ 文件），0.33→0.35.1 实际发生；
  且定制散落"上游的文件"，定位失焦。
- **否决 B（改解析代码默认值）**：动上游核心模块，R2 报批重、升级冲突面上移代码层；
  上游已有 env 扩展点，无需此改。
- **采用 C（数据源切换）**：上游接触面收敛到 2 个低频声明式文件（pyproject/check_wheel）；
  手册定制全部收敛进 fork 命名空间，上游 `docs/` 整树拉取零冲突；三形态指向体系成立。

## 影响

- 后续所有手册定制**必须且只能**改 `aixcoding/manual/`（回改 `docs/` 即违反本决策）；
- 每次升级批次新增固定步骤：`git diff <旧tag> <新tag> -- docs` 对齐评估 → 定制重放 →
  manual 提交 → 重出 wheel/桌面 PDF；
- 升级检查点：force-include 目标键 / `BUNDLED_DOCS_PATH` / `BUNDLED_DOCS_PREFIX`
  三方一致（design 假设 2），失效则 C145/C146 跟改并重报 R2；
- 回滚路径：两处上游文件回退键名/前缀 + 删除 `aixcoding/manual/` 即完全还原，无 `src/` 纠缠。
