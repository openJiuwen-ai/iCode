## 背景

catalog-sync 批次将 `model.catalog.base_url` 挂入上游 foundation Settings，获得统一的加载、
类型转换、重启语义和 `ProjectMerge.DENY`。其代价是 fork 私有配置进入上游
`settings.py`、`process_settings.py`、settings UI 与 i18n，并形成唯一保留 `CHRYS_` 前缀的
定制环境变量 `CHRYS_MODEL_CATALOG_BASE_URL`。

与此同时，`AIXCODING_AUTH_ENVIRONMENT` 实际承担 auth 与模型目录（model catalog）共同的部署环境选择。
未来内部 update 与 telemetry 已确定需要同一部署语义。若等到这些批次再处理，模型目录将先
迁一次，后续服务再迁一次，并可能形成多套端点配置。

架构约束：上游 tier DAG 为 foundation → kernel → service → orchestration → app；kernel 内
跨子包绝对导入被 `test_layering` 禁止，父级相对导入被 ruff TID252 禁止。因此不能简单新建
`kernel/aixcoding/config.py` 让 auth/diagnostics 直接引用。把内部部署配置放入 foundation 虽可满足
导入方向，却违反 ADR-0011 的定制 tier 放置原则，并把内部产品语义渗入通用基础层。

## 决策

1. **部署环境统一命名为 `AIXCODING_ENVIRONMENT`**，取值 `local/dev/prod`，默认 `prod`。
   它表示 AIxCoding 内网服务部署环境，供 auth、模型目录、未来 update/telemetry 共用。
   不使用 `PLATFORM`、`BACKEND` 或 `PROFILE` 命名，不引入 `AIXCODING_PLATFORM_ORIGIN`。
2. **定制层共享配置文件为 `~/.chrys/aixcoding.toml`**。顶层 `environment` 表示部署环境；
   `[model_catalog].base_url` 承载模型目录服务基址；现有 `[logging]` 继续服务 diagnostics。
   环境变量优先于 TOML，TOML 缺省时使用 prod。配置重启生效，不支持项目级覆盖或会话中热切换。
3. **采用 service 共享读取器 + app 组合注入**：
   `service/aixcoding/config/` 子包提供唯一进程内缓存快照；`app/aixcoding/startup/` 子包在默认
   `LoginSession` 构造前向 auth 注入环境并向 diagnostics 传递日志配置；模型目录直接读取同一快照。
   两个子包均通过 `__init__.py` 保持 `chrys.service.aixcoding.config` 与
   `chrys.app.aixcoding.startup` 公开 import 路径。跨层向 auth 传字符串，auth 自己映射为其
   `Environment` 类型。不得把该共享模块迁入 foundation，不得为本批次放宽 kernel 同层导入规则。
4. **模型目录私有配置退出上游 Settings**：删除 `model.catalog.base_url` 的字段、label、
   process projection、UI 隐藏处理及 i18n/oracle 登记。模型目录端点优先级为
   `AIXCODING_MODEL_CATALOG_URL` 完整端点 > TOML base_url > environment tier base。
5. **服务专用覆盖保持独立**：`AIXCODING_AUTH_SERVER_URL` 继续只覆盖 auth/user-data origin；
   `AIXCODING_MODEL_CATALOG_URL/TOKEN/SYNC_INTERVAL` 保持原义。不提供全局 origin/base_url。
   auth 与模型目录各自保留 tier 地址表及 drift test，本决策不建立统一地址注册表。
6. **零向后兼容**：`AIXCODING_AUTH_ENVIRONMENT`、`CHRYS_AUTH_ENVIRONMENT`、
   `CHRYS_MODEL_CATALOG_BASE_URL` 直接失效，不读取、不检测、不告警。旧 Settings YAML 键随声明
   删除而失效，交由上游既有 unknown-key 机制处理，定制层不增加检测。
  模型目录既有 `RETIRED_ENV_NAMES`、`_warn_retired_env()` 及其调用和测试一并删除，不再保留
   `CHRYS_MODEL_CATALOG_*` / `CHRYS_REMOTE_MODEL_CONFIG_URL` 的退役 WARNING。
7. **未来配置契约只定方向、不提前实现**：update 使用 `[update].base_url`，telemetry 使用
   `[telemetry].base_url/enabled/tool_param_mode`；两者复用顶层 environment，服务路径由各自客户端
   持有，token/userId 继续由 auth session 提供。字段只有在对应消费批次才实现；若需求推翻预留键名，
   须以新 ADR 取代本条。
8. **本批次不实施 ROADMAP F 类公共层大提取**：只落地共享配置与环境解析子集，不抽网络访问、
   通用工具、共享常量层或 tier 地址注册表。

本 ADR 不取代 ADR-0009 的一般命名规则；它终结该规则中 settings 例外在模型目录的实例，并规定
内部 update/telemetry 不再以该例外为由进入上游 Settings。本 ADR 不修改 ADR-0011，所选
service + app 组合方式正是其 tier 与依赖方向约束下的实现。

## 理由

- 现在统一只做一次迁移，避免模型目录与后续 update/telemetry 分批重复改造。
- 上游 Settings 中 fork 私有键归零，消除 `CHRYS_MODEL_CATALOG_BASE_URL` 的唯一例外实例。
- `AIXCODING_ENVIRONMENT` 直接命名实际概念，避免未来服务继续依赖 auth 语义。
- service + app 组合满足现有架构门禁，无需把定制代码放入 foundation 或修改分层不变量。
- 服务专用覆盖符合 local mock 中 auth/模型目录/update 使用不同端口的现实；全局 origin/base_url
  会扩大误配置影响面，并引入路径前缀歧义。
- 内部产品无需旧变量双读或退役警告；删除既有检测符合责任人的零兼容裁决，并减少维护面。

## 被否决的备选

1. **保留模型目录在上游 Settings**：当前改动最小，但后续 update/telemetry 会继续扩大上游配置面。
2. **继续使用 `AIXCODING_AUTH_ENVIRONMENT`**：无需 auth 改名，但把共同部署语义长期绑定到 auth。
3. **恢复 `AIXCODING_EXTENSION_*` / 0.28 `aixcoding.yaml`**：旧 base_url 与 customServerUrl
   语义不同，且主要服务 update/telemetry，不能准确覆盖当前 auth/模型目录。
4. **共享模块放 foundation**：导入方向可行，但违反 ADR-0011 并增加上游树内定制面。
5. **放宽 kernel 同层导入规则**：可实现直接引用，但需修改架构不变量，代价超出本批次需求。
6. **统一 tier 地址注册表/全局 origin/base_url**：当前服务端点、路径与本地端口不同构，暂无真实
   需求证明收益；全局覆盖会误伤其他服务。
7. **旧变量双读或只 WARNING 不读取**：均被零兼容决策否决。

## 后果

- 旧脚本若仍只设置 `AIXCODING_AUTH_ENVIRONMENT=local`，程序会按未设置处理并可能落到 prod，
  且没有运行时提示；发布与支持文档必须给出新配方。
- app 启动顺序成为配置正确性的明确前提，需要测试防止默认登录会话提前构造。
- service 的配置缓存是 auth/模型目录一致性的来源；禁止各特性自行重复读取 TOML。
- 上游 Settings 相关 C032/C033/C039/C042/C043 退役；原 catalog-sync design 与新批次 design
  均需按 R10 重签，最终严格登记对账必须全绿。
- update/telemetry 批次可以复用本契约，但仍须完成各自端点、错误语义与测试设计，不得把本 ADR
  视为其功能实施授权。
