## 背景

catalog-sync 批次（PR #85）引入模型目录 tier 基址表（`_CATALOG_BASES`：local mock /
dev / prod 均为 `http://` 明文 + 硬编码 IP），请求头携带登录 token。peer review 提出
传输安全候选（明文 HTTP 中间人可截获 token）；归属核实：基线 `fad4866` 的 auth
`environments.py`（`_BASE_PATHS`）已是同款明文 HTTP + IP——catalog 与 auth 通道同源
对齐（drift test 锚定），非该批新引入的风险面。

## 决策

**内网部署形态明确使用明文 HTTP 传输**（2026-11-03 责任人裁决）：现有内网
条件下**无法也不需要**支持 HTTPS——无内网证书基础设施（CA/签发/分发），部署环境为
受控内网人工分发，无中间人威胁模型诉求。该决策**适用于所有服务器地址**，不限于
某一服务或通道；现有服务地址（auth 登录与 model catalog 的 tier 基址表
`_BASE_PATHS` / `_CATALOG_BASES`）以硬编码 IP 直连形态维护，二者由 drift test 锚定
对齐。

## 理由

- **无 HTTPS 需求**：内网受控环境，终端用户与服务器间无可插入中间人的网络路径
  诉求场景；token 截获威胁在内网边界外不可达；
- **无法支持**：内网无证书签发与分发基础设施，自签证书的分发/信任链维护成本
  远超收益；
- **一致性**：整体决策覆盖全部服务端连接，不为任何单一通道引入例外形态；现有
  auth 登录与 model catalog 通道恰好同形态（存量基线），与本决策自然对齐。

## 后果

- **所有服务器地址（现有与新增）一律明文 HTTP + IP 直连**；端点表成对出现时须有
  drift test 锚定；
- 评审中"明文 HTTP / token 明文传输"类候选按本 ADR 口径**排除**（既定部署形态，
  非缺陷、非待办、不登记后续批次）；
- 部署形态变化（公网暴露、跨不可信网段、等保合规要求等）构成重新评估的正当
  需求前提——按 ADR 决策更新处理新建 ADR 取代本文，不回改本文。
