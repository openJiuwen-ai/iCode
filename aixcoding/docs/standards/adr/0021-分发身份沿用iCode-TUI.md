## 背景

ADR-0019 将品牌定制拆为三个工作项，并把"`iCode-TUI` 分发身份保留还是更名"预留为
独立裁决。internal-installer 批次已落地内网安装器、镜像约定与分发物料目录
（ADR-0020），本 ADR 只处理剩余的分发身份裁决。

考古事实（2026-11-05 核正）：

- 上游 v0.28.0 的分发名是 `chrys`；0.28 定制版与上游原版一致，从未品牌化包名；
- 上游 `943142e4`（2026-10-08）将分发名改为 `iCode-TUI`，首个包含该改动的标签为
  `v0.29.1`；
- 新基线自 0.31.0 起继承 `iCode-TUI`。它是新基线从上游带来的现状，不是 0.28
  定制遗产。

可见性事实（0.33.0 代码核查，0.34.0 复核无语义漂移）：

- 内网离线包用户的正常交互路径不暴露 `iCode-TUI`；OFFLINE flavor 的更新检查仍外呼
  GitHub，该更新链内部化归版本更新检测批次处理；
- 仅 pip/uv/pipx 场景可见：Python 运行时 3 处（`update_check.py` 升级命令、
  `install_flavor.py` 卸载提示、`installer.py` 误用提示）加安装脚本至少 1 处；
  这些字符串是真实可执行命令的组成部分，不是可随意替换的品牌文案；
  `pyapp/icode-tui/` 只在 pip/uv flavor 场景出现，非内网离线用户固有可见路径。

`versioning.md` §2 已预定"分发名/wheel 名保持上游、四段版本号即身份标识"。

## 决策

1. **分发身份沿用上游 `iCode-TUI` / `icode_tui`**：不改 `pyproject.toml` 的
   `project.name`、`DISTRIBUTION_NAME`、wheel 前缀及 build/CD/PyApp 相关引用。
2. **接受 pip/uv/pipx 场景的包名可见性**：升级、卸载与误用提示继续输出真实包管理器
   身份；禁止为品牌统一把这些命令中的 `iCode-TUI` 替换成 `aixcoding-cli` 或其他
   名称。
3. **边界划分**：版本更新检测批次只负责更新检测与升级链内部化，不处理卸载提示和 `install`
   误用提示；内网安装体系按 internal-installer 批次已定契约执行，本决策不重开其
   设计。
4. **重开条件**（任一出现时须重开裁决，且先定义内部索引、公共源隔离与防同名跨源
   误升级策略）：
   - 内网将来提供 pip/uv 安装路径或内部 PyPI 源；
   - 对外发布或开源；
   - 品牌合规要求覆盖分发层；
   - 出现同名包跨源误升级的实际风险（上游更高三段版本在版本比较上会胜过内部
     四段版本）。
5. **重开后的迁移义务**：若将来裁决更名，必须完整处理 wheel 元数据与文件名、
   uv/pipx/pip 新旧包身份迁移、更新检查、PyApp/build/CD 引用及发布说明，不能只改
   `pyproject.toml` 名称字段。

## 理由

- **B1 沿用上游**：分发层最接近"上游对接层"，沿用可保持零分叉、零持续合并维护；
  内网典型用户走离线分发，正常路径无包名可见，改名收益趋近零。
- **B2 改回 `chrys` 被否决**：与上游形成永久分叉，每次升级都要维护分发名引用；
  仅换来与内部 `chrys` 名一致，而品牌与命令切换批次已裁决内部名保留，无法达到全名统一。
- **B3 改 aixcoding 系名被否决**：分叉代价同 B2，还需完整迁移包管理器身份、wheel
  前缀、更新检查与构建发布链；且与"内部层保留 `chrys`"的既有裁决形成新的不一致。
- **命令与包名差异可控**：`uv tool install iCode-TUI` 提供 `aixcoding-cli` 是 Python
  生态常见形态；用户指南和技术支持文档可明确"安装/升级/卸载用分发名，启动用命令名"。
- **同名跨源风险以前置条件控制**：当前不存在 pip/uv 分发路径；一旦启用，须先建立
  源隔离与防误升级策略，满足重开条件时再裁决。

## 后果

- 现有 `DISTRIBUTION_NAME = "iCode-TUI"`、`icode_tui-*` wheel 前缀及相关契约测试
  保持不变；本决策本身零代码改动。
- `versioning.md` §2 的分发名口径由本 ADR 正式确认；后续版本策略修订须回指本文。
- 版本更新检测、用户指南文档批次以此身份为输入：版本更新检测批次不做包名品牌替换；用户指南在涉及 pip/uv
  场景时须同时说明分发名与启动命令的对应关系。
- 任何批次不得以品牌统一为由改动分发身份；确需更名时，新建 ADR 取代本文并履行
  第 5 条迁移义务。
