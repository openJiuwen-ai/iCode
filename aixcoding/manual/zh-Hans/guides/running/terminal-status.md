# 在终端中显示 iCode 的状态

当 iCode 的终端界面运行在一个支持 Program Status Protocol(OSC 7501)的终端里时,iCode 会持续告诉终端自己正在做什么:空闲、工作中、等待你、已完成或已失败。终端可以随意选择展示方式——标签页上的徽标、状态列表、回复就绪时的通知。你可以去别的窗口干活,仍然一眼看到 iCode 的进展。

这一切自动发生:无需开启,也没有配置项。iCode 一启动就开始上报,并在每个回合中持续刷新终端里显示的状态。

## iCode 上报的内容

| iCode 时刻 | 上报的状态 |
| --- | --- |
| iCode 启动、正在进行的回合被中断,或工作流运行被取消 | `idle`——等待你的下一条消息 |
| 一条回复或一个工作流运行正在进行 | `working` |
| iCode 在等你:工具审批、回答问题(含工作流节点的问题),或对失败的子任务/工作流节点做出重试还是终止的决定 | `blocked`——消息为工具名、问题内容,或失败任务的名称 |
| 回合正常结束,或工作流运行完成 | `done`——消息为回复开头的第一行(如有) |
| 回合或工作流运行失败 | `error`——消息为错误信息的第一行 |

多个决定同时待处理时——两个审批、或一个审批加一个问题——状态会保持 `blocked`,直到你答完最后一个。你回应审批或问题后,状态回到 `working` 继续本次运行,随后落到 `done` 或 `error`。

`done` 在回复可以阅读的那一刻就会出现;此时会话保存和回合结束的 hook 可能仍在执行。

继续被中断的回合时,重试一接手就会上报 `working`,即使上一轮尚在完成取消处理。新建或恢复聊天/工作流会话,以及切换聊天与工作流模式,都会清除上一轮的结果。

## 在哪里能看到

协议的效果由终端自己决定如何呈现;你的终端是否消费 OSC 7501、会怎么展示,请查阅它自己的文档。不支持该协议的终端会完全忽略它,因此 iCode 的上报不会带来任何干扰。如果把 iCode 跑在终端多路复用器里,那么 iCode 直接面对的"终端"就是多路复用器——状态只有在该多路复用器把协议透传给外层终端时才会到达外层。

iCode 发送的内容是状态、固定的程序标识 `iCode`(`app=iCode`),以及(如上所述)一小段单行文本(工具名、问题、回复或错误的开头)。退出 iCode 时,它会最后上报一次 `idle`:主动退出即视为已查看结果,已完成的运行不会在你离开后继续提醒。即使退出时工作流的错误提示仍然打开,也会这样处理。

只有原生 TUI 会上报,包括其中的聊天和工作流模式。浏览器会话(`icode serve`)、无界面命令(`icode run` 和 `icode workflow run`)以及 ACP 服务(`icode acp`)均不发送 OSC 7501 报告。
