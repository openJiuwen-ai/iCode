# AGENTS.md

Chrys is a Python 3.14+ agent platform: Textual TUI, headless CLI and ACP server. Users see it as **iCode** / `icode` (`foundation/branding.py`; `msg()` fallbacks write `{app}`, bound with `app=APP_DISPLAY_NAME`); the PyPI distribution is **iCode-TUI** (`__init__.py::DISTRIBUTION_NAME`, wheel `icode_tui-*.whl`), whose only command is `icode`; the import package, `~/.chrys`, `CHRYS_*`, wire/header names and data keys keep `chrys`. `pyproject.toml` is the source of truth for version and deps. Paths are under `src/chrys/` unless they start with `tests/`, `scripts/`, `docs/`, `locales/`, `.github/` or name a root file; a bare file name continues the directory named just before it.

## Commands
```bash
uv sync                              # setup, as CI; also installs the dev group (tests, ruff, ty)
./scripts/fetch_rg.sh                # vendored ripgrep, gitignored (Windows: .ps1); search falls back to rg on PATH
uv run icode                         # TUI (-s session, -a agent, -m model, -C workdir)
uv run icode run "<prompt>" -a Code  # headless, approval BYPASS (as `icode workflow run`)
uv run icode acp                     # ACP stdio server; also: serve, agent, model, approval, hook, workflow, trajectory, install, uninstall
uv run python scripts/chrys_test.py --smart --paths <changed files...>   # default verification; both modes run below normal CPU priority
uv run python scripts/chrys_test.py --full        # complete non-integration suite; only when asked
uv run pytest tests/x/test_y.py::test_fn -n0      # debugging only
uv run ruff check src/ tests/ scripts/chrys_test.py scripts/check_wheel.py scripts/calibrate_gc_freeze.py scripts/gc_freeze_calibration_math.py scripts/chat_panel_workloads.py hatch_build.py scripts/i18n_mo.py   # pyproject's fix = true EDITS files (--no-fix inspects); CI auto-fixes too, so only unfixable errors fail there
uv run ruff format --check src/ tests/ scripts/chrys_test.py scripts/check_wheel.py scripts/calibrate_gc_freeze.py scripts/gc_freeze_calibration_math.py scripts/chat_panel_workloads.py hatch_build.py scripts/i18n_mo.py
uv run ty check --error-on-warning --python-platform linux src/chrys   # repeat for darwin and win32; the src/chrys argument is required
uv run python scripts/i18n.py extract   # then update, translate, check (see i18n)
```
- Run every project tool through `uv run`; global installs are other versions than the pins.
- Direct pytest also collects `integration` and `gc_calibration` tests (add `-m "not integration and not gc_calibration"` for directory runs), and under the default `-n 8` a mistyped path exits 5 "no tests ran" instead of erroring: `ls` it first.

## Verification, gates & commits
- Verify with Smart Test, passing `--paths` = only the files this task changed (include deleted paths and both sides of a rename); without `--paths` it also picks up every branch and dirty-tree change. Don't hand-compute the affected scope. It escalates to the full suite by itself on `pyproject.toml`, `uv.lock`, `.python-version`, root/`tests/` conftest or pytest-config changes; otherwise run `--full` only when asked. Both modes end with a `Summary:` block (exit code, each suite's counts): read it instead of `tail`-ing the output.
- Smart Test is a local optimization only: ≤2 import hops, fixture consumers and explicit watches; distant consumers are left to CI. CI/CD keeps its direct complete PR gates and must never use Smart Test to select or skip tests.
- A test that reads repo files without importing them (subprocess fixture, file scan) needs a `REGULAR_RULES`/`ARCHITECTURE_RULES` watch in `scripts/chrys_test.py`; otherwise edits to those files select it only by the nearby-directory fallback, if at all.
- Ruff, format, ty, i18n and `uv build` are separate gates; packaging changes also run `uv run python scripts/check_wheel.py dist/icode_tui-*.whl`, which installs the wheel into a fresh `uv tool` environment from the index, as PyPI users get it, and probes it (CI's Build and Install wheel jobs, CD before release). Say which suite ran; a Smart Test pass is never a full-suite pass. Python-3.9 workflow-worker cases skip without a 3.9 interpreter (`CHRYS_PY39_INTERPRETER`, PATH or Homebrew keg); Linux/Windows CI runs them.
- CI (`.github/workflows/ci.yml`; partitions pinned by `tests/architecture/test_ci_test_partitions.py`) runs `-m "not integration and not gc_calibration"` in per-OS core/TUI shards and `tests/architecture` alone at `-n 0`. Decorate OS-independent whole-repo scans with `@CI_LINUX_ONLY` (`tests/support/ci.py`).
- Refresh generated artifacts in the same change: i18n catalogs (see i18n); after editing a builtin workflow template, `uv run python -m tests.support.workflow_builtins`; when an async wait (`await`, `async with`/`for`) under foundation/kernel/service/orchestration is added, removed, reordered or edited (line moves alone don't count), `uv run python -m tests.support.trajectory_wait_inventory` for `tests/architecture/trajectory_wait_manifest.json` (a rules table plus one row per wait, grouped by module and function; no checksum) — a row keeps its reviewed rule only while its `module:qualname:ordinal`, expression and primitive match and its function's wait count is unchanged, so adding or removing a wait reopens every wait in that function; the refresh lists every reopened row with the rule it had, and the row falls back to its default rule (fail-closed `unresolved` unless it is a `sleep(0)` yield) — review them.
- User-visible change → update the affected `docs/en/` and `docs/zh-Hans/` pages in the same change (see User guide).
- Other agents may be editing this tree. Pre-commit (`ruff-check --fix`, format) stashes unstaged edits and can lose theirs: run both ruff commands yourself, stage explicit paths (never `git add -A`), commit with `--no-verify`. Undo a probe with an inverse edit — never `git checkout -- <file>`/`git restore` (wipes the file's unstaged edits), `git stash` or a whole-file snapshot restore; to run HEAD, `git archive HEAD src/chrys | tar -x -C <scratch>` + `PYTHONPATH`. In `a && gate | tail` the exit status is tail's.

## Supply chain & version pinning
Pin third-party code to immutable ids so every bump is a reviewed diff; never loosen a pin to unblock something.
- **Actions**: every third-party `uses:` is a 40-char SHA plus a `# <version>` comment; `docker://` pins `@sha256:` (comment too); every workflow declares `permissions:` and write scopes are allowlisted (guard `tests/architecture/test_workflow_action_pins.py`). Selector-branch actions (`dtolnay/rust-toolchain@stable`, `taiki-e/install-action@cross`) default an input to the ref name: after pinning, pass it explicitly (`toolchain: stable`, `tool: cross`) or `cd.yml`'s build-binaries job fails.
- **Python**: `[project]` deps use exact `==` (ranges re-resolve for wheel installers, where our lock doesn't apply). The in-file-commented exceptions are `pyjwt[crypto]` and the four `opentelemetry-*` packages (bumped together); the Linux offline binaries take `pillow` from a glibc 2.17 build listed in `scripts/offline_wheel_overrides.txt` (`.github/workflows/pillow-manylinux2014.yml`): bump the pin and that file together. That workflow's publish run creates the release tag on GitHub only: create the same tag on GitCode right after, or the GitCode→GitHub sync deletes it and the release reverts to a draft whose wheels 404 (recovery steps in the workflow's header). `[dependency-groups]` may use ranges. `[build-system].requires` pins `babel` for the catalog build hook: bump it with the dev group's `babel`.
- **Interpreter**: `.python-version` pins the full CPython version (guard `tests/architecture/test_python_pin.py`): uv runs it locally, every workflow's `setup-python` reads it (`python-version-file`), and the release binaries ship it from the python-build-standalone release `PYTHON_BUILD_STANDALONE_RELEASE` in `cd.yml` (mirrored in `scripts/build.sh`/`build.ps1`), not the one PyApp's `build.rs` names. Bump both together; that release must carry the version for every CD target.
- `uv.lock` pins and hashes the whole closure: commit it in the same commit as any dep change. PR CI's `uv sync` isn't `--locked` (drift re-resolves silently) but the offline-dist export is (`uv export --locked`) — check with `uv lock --check`.
- Ruff's version lives in `pyproject.toml` and `.pre-commit-config.yaml` (`rev:`); bump both. Version bump: `pyproject.toml` → `uv sync` (rewrites chrys's own version in `uv.lock`; commit both) → full i18n pipeline (stamps the installed `__version__` into `Project-Id-Version`).

## Architecture & control flow
- **Bootstrap**: every runtime entrypoint calls `orchestration/startup.py::bootstrap_runtime()` (guard `tests/architecture/test_entrypoint_bootstrap.py`; `serve`/`install`/`uninstall` exempt); never duplicate its steps. Production reads settings via `load_settings()`; `Settings.from_env()` is a compat shim.
- **CLI**: `app/cli/app.py::main` is a hand-written if-chain on `argv[0]` (no argparse subparsers); unmatched argv → TUI. Noun commands are shown singular (`agent`, `workflow`, …) and their plurals are mapped to them first (`_PLURAL_ALIASES`); `agent`, `model`, `approval`, `hook` and `workflow` given no subcommand run `list` (an optional action defaulting to `list`; subparser groups pass argv through `app/parsing.py::default_to_list`).
- **EventBus** (`foundation/events/bus.py`), the only frontend↔backend channel: `publish()` awaits `subscribe()` handlers inline (exact-type match; backpressure — never fire-and-forget), logs and swallows their errors unless `raise_handler_errors=True`, then feeds `stream(*types)` (isinstance match; a stream sees only events published after its `async with` is entered). Stream queues are unbounded on purpose: dropping would truncate streamed LLM output on headless/ACP.
- **AgentEngine** (`orchestration/engine/engine.py`) is built only by `orchestration/engine/assembly.py::assemble_agent_engine` (tests: `agent_engine` fixture), which wires its component attributes (`engine.current`, `engine.turns`, …). Components never get the engine as a host, and build code returns values instead of writing engine state (guards in `tests/architecture/test_layering.py`). Handlers subscribe before the first build so settings/profile events can recover a failed start. Every rebuild replaces `engine.current.loaded` (`LoadedAgent`; None after shutdown): call `current.require_loaded()` per use, never hold it across an `await`.
- **Invoker** (`orchestration/invoker/`): one contract, `contracts.py::InvocationConversation.run(RunRequest) → Ok | Failed | Aborted`; two backends, `kernel.py::KernelConversation` and `acp.py::AcpConversation` (which alone owns ACP transport attempts and teardown); three caller shells: the main turn (`orchestration/engine/run/`), `orchestration/sub_agents/shell.py::SubAgentToolShell`, `orchestration/workflows/agent_node.py::WorkflowAgentShell`. Backends never validate structured output: the kernel's `Ok.backend_payload` is the raw response and `structured_output` stays None for caller policy.
- **Three build paths** — main `orchestration/engine/build/builder.py::build_agent`, sub-agent `orchestration/sub_agents/tools.py`, workflow node `orchestration/workflows/agent_node_build.py::build_kernel_node` (mirrors `build_agent`). Tool, MCP, skill, memory, web and start-hook wiring must land in all three. Local tools come only from `service/tools/packs.py`: `assemble_tools` (the pack catalog; tests replace its `create_packs` step via `tests/support/tool_packs.py::install_tools`), then, after the sub-agent and MCP tools, `assemble_extension_tools` for the Python extensions the profile's top-level `extensions` lists, whose tools yield every name already taken (MCP's via `MCPAdapter.tool_namespace`): `service/extensions.py` finds them without running their code, imports each off the event loop once per process, and binds its tools as kind `extension.<id>`; an extension that cannot load, or takes a name already in use, is left out whole with an `extension_unavailable` warning. A first-party pack's `create` takes the host objects its tools need (todo tracker, event bus, background tasks) from `ToolBuild`; a tool does its own work (`todo_write` validates, replaces and publishes) — don't add a function middleware that intercepts a tool by kind to do it.
- **ExecutionLease** (`orchestration/engine/execution.py`) owns a turn's run task from admission to final save. A workflow run holds it exclusively (at most one run, admitted only while no turn is live); turn admission and rebuilds are refused meanwhile.
- **Turn pass** (`orchestration/engine/run/`: `coordinator.py`, `bindings.py::TurnBindings`, `resume.py::TurnResumePolicy`): retry reuses a `Failed` result's continuation ticket only while `KernelConversation.continuation_is_live()` confirms the backend state is unchanged since that pass (same ticket, generation and invocation); otherwise the turn continues from history. Replace backend history only via `KernelConversation.history_state = …` or `restore()`, which invalidate tickets. Admission errors fail the turn through normal finalize/save/release and never replay.
- **Retry lanes** (N = effective `CHRYS_MAX_TRANSIENT_RETRIES`: 10 interactive / 18 headless, max 50; backoff 3/7/15/30/60/120/240/600 s, capped at 600; commit-point rules under LLM wire & retry):
  - main turn, local storage: the kernel `WireRetryPolicy` retries each wire call in place; after stream-stall exhaustion the same `agent.run()` falls back to a non-streaming request with a fresh N; a context overflow (see Compaction) and a response that showed nothing (see Response validation) each add one resend outside N and the stall budget — up to 3N+4 provider calls per logical call (3N+2 pinned in `tests/kernel/test_wire_retry.py`; the two resends in `test_loop_context_overflow_recovery.py` and `test_loop_blank_response_resend.py`).
  - main turn, service-side storage: no wire policy; `AttemptRunner` runs the whole-run `StreamRetryLoop`, and only on stall exhaustion ONE non-streaming `agent.run()` attempt with no new budget (its tool loop may still make several provider calls). Whole-run semantics own this path — don't add a wire lane.
  - sub-agents raise on stall exhaustion (no non-streaming fallback) into the shell's pause/abort path. Kernel workflow nodes take the main turn's lanes (wire policy with non-streaming fallback, or whole-run under service-side storage; `orchestration/workflows/agent_node_build.py`); what escapes becomes the attempt's `FailureReport`, and the scheduler's next attempt resumes a failed or timed-out pass from its repaired history (ACP: a new session); after a successful agent run it starts from the prompt.
  - every lane: an Anthropic thinking-binding refusal (`is_thinking_binding_rejection`; never an overflow note) is resent once inside the adapter without the replayed thinking, which is then marked `ANTHROPIC_THINKING_STRIPPED_KEY` and never replayed — outside N, no retry event, not under `prefix_mismatch_behavior: error`; each provider call the lanes count can thus be two requests.
  - every lane: once a pass has shown answer text, nothing sends it again (reasoning may stream again) — wire retry, stall fallback, overflow and blank resends (the kernel's `delivered_text` veto) and whole-run retry (`ContentProjector.exposed`) all stop; the shown text is kept and the error reported. A main turn's text counts as shown only where its frontend streams it (TUI, ACP); `icode run` holds it until it knows what it is, so there it never vetoes (`TurnBindings(shows_answer_text=)`, from `ActiveSession.surface`; text a hosted card already printed mid-stream prints again after the retry notice). A workflow node's own text keeps the `delivered_text` veto on every surface. A kernel sub-agent's views show each answer segment whole, so its text counts as shown only once its segment completes (`shows_whole_segments`; the wire veto reads `WireRetryPolicy.answer_shown` for the current response, whole-run retry `exposed` for the pass): a segment cut off before then is retried unseen, and a pause or cancel keeps only completed segments. Only the TUI chat shows a sub-agent's text, so only there does it veto (`SubAgentTools(shows_answer_text=)`, from `ActiveSession.surface`); `icode run`, ACP and workflow-node children retry as if nothing showed, and a retry boundary drops the given-up attempt's text. A workflow node's next attempt is no resend (its own origin): a resumed kernel attempt asks again for the trailing answer (`ChildHistory.retry_input`), and node details, carried on from the earlier attempt (`AgentTranscriptJournal.continue_from`), drop it on the attempt's `InvocationAnswerWithdrawn`.
- **Sub-agent shell**: `SubAgentToolShell` is the child's sole `OperationBinding` and the only pause/Retry/Abort loop, with no dependency on ACP protocol code; `KernelSubAgentPolicy`/`AcpSubAgentPolicy` add only result, audit and cancel policy. The tool recipe keeps quota, writer, hooks and live approvals alive until the operation drains; pending records are removed only after the parent save succeeds. With `human_failure_decisions=False` (headless chat, every workflow node) a failed child ends at once, returning `Error: sub-agent 'X' failed — …` to the caller's model with no pending record; only TUI/ACP chat pauses for the Retry/Abort card. Kernel children return only the text after their last tool/hosted output (`service/agent_middleware/events/hosted_tools.py::FinalSegment.of`; all text if that is empty) — a settled decision; don't return `response.text`.
- **Invocation events**: execution/presentation facts are `Invocation*` events with a required `InvocationOrigin` (`turn | sub_agent | workflow_node` plus parent chain), immutable once built; a workflow node's origin also carries its `attempt`, which counts for equality, so backend admission and continuation tickets compare with `same_invocation`. Bind a `BoundEmitter` (`orchestration/invoker/origin.py`) before the first `await`; shared-client callbacks only look it up via `invocation_routing_key`. Never derive origin from ambient context. Chat/ACP/headless consumers skip workflow traffic with `origin.root.kind == "workflow_node"`.
- **Model text** reaches frontends only as `InvocationContentDelta`/`InvocationContentFinished` (`answer | reasoning | reasoning_summary` channels, keyed by `segment_id`), published by the caller's per-pass `orchestration/invoker/content_projection.py::ContentProjector`: kernel paths feed it streamed updates (`AttemptRunner` `stream_observer`) and landed responses (`RESPONSE_READY_KWARG`, awaited before the response's tools run, so a non-streamed response shows before its tool cards, and the bridge holds its hosted cards until the text before them shows: `shown`); external ACP agents through `AcpUpdateTranslator`. A retry boundary (`on_retry_boundary`) gives up the response being streamed: `InvocationContentAbandoned` names its segments before the open one finishes `failed`; `icode run` progress drops their held text, the TUI main chat removes their thinking, other frontends ignore it. The final `InvocationMessage(is_final=True)` is a completion snapshot that frontends never append. The TUI renders the answer, and in the main chat also readable reasoning (`ThinkingMessage`, read as each segment opens, or once per replay, from `ui.chat.show_thinking`; replayed folded): the main chat streams both, and nested views (sub-agent cards and details, workflow node transcripts) show each answer segment whole once it completes (`AnswerSegments`); the ACP server maps answer → `agent_message_chunk` and reasoning and its summaries → `agent_thought_chunk`.
- **ChrysSessionHost** (`orchestration/session_host.py`): one bus + engine + session per `icode run`, `icode workflow run` or ACP session. Headless: `ApprovalMode.BYPASS` (every tool runs unasked) and `allow_user_interaction=False`, which drops `ask_user` from the tool list (a stray `QuestionToUser` fails fast); ACP passes True. Headless/ACP streams forward only `_HEADLESS_RUN_EVENT_TYPES` events carrying a `session_id`: register a new turn event there and publish it with `session_id=`, or only the TUI sees it.
- **ACP server** (`app/acp/server.py`; non-standard caps via `ext_method`; spec and gaps in `app/acp/doc/frontend-api.md`): stdout is JSON-RPC only, logs go to stderr (`app/cli/acp.py::_configure_logging`). ACP applies no ask-user timeout unless `--ask-user-timeout`. Client-supplied MCP servers: HTTP only, headers literal (never resolve `{{ENV_VAR}}`).
- **Subprocesses**: every non-interactive subprocess — startup, version, Git and platform probes included — sets `stdin=DEVNULL` explicitly on every OS (guard `tests/architecture/test_hygiene_subprocess_stdin.py`): ACP's stdin is the JSON-RPC pipe, and inheriting it can block or eat protocol bytes. Use `PIPE`/`input=` only for a child that intentionally reads stdin (the workflow worker host). Spawn through `foundation/platform/process.py` (`managed_subprocess`, `spawn_managed_stdio_process`; sync `subprocess.run`: `**windows_hidden_subprocess_kwargs()`); never pass `CREATE_NO_WINDOW` on Windows: the child shares, and can reset, the TUI's console.

## Layering DAG (`tests/architecture/test_layering.py`)
```
app → {orchestration, service, kernel, foundation}
orchestration → {service, kernel, foundation}
service → {kernel, foundation}      # includes the src/chrys/workflows.py facade
kernel → {foundation}               # kernel→kernel imports are relative (from .x)
foundation → {}
```
- Same tier is allowed; `if TYPE_CHECKING:` bodies are exempt; string-literal `import_module`/`__import__` count as imports; `import chrys` fails (`from chrys import __version__` or `DISTRIBUTION_NAME` is fine); a new top-level module needs a `TIER_ORDER` entry. `src/chrys/extensions.py` is the authoring API Python extensions import (tier 0, stdlib-only, imports nothing else from chrys; `tests/service/extensions/test_sdk.py`): keep it small and backward compatible.
- Banned even under TYPE_CHECKING: `service/agent_middleware/system_reminder.py`, `service/agent_middleware/reminders/` and `service/context/compaction/last_words_state.py` → orchestration; `orchestration/{invoker,sub_agents}/` → `orchestration/engine/`; `orchestration/invoker/` → `orchestration/sub_agents/`.
- Below `app/`, import the heavy base deps (textual, watchdog, psutil, OTel SDK, doc converters: `_LAZY_BASE_DISTRIBUTIONS`) and dev-group packages only lazily — inside functions or under `TYPE_CHECKING` (`tests/architecture/test_hygiene_lazy_imports.py`); headless and ACP runs load each only when used.

## Source map (`src/chrys/`)
- **foundation/** (tier 0): config, events, models (session_env, workspace, turns, history_markers), i18n, trajectory, platform, patches, tool_kinds.
- **kernel/** (tier 1): flat, no subpackages — agent, loop, client, tools, compaction, exchanges, identity, middleware. Its `_*.py` modules are private: outside `kernel/` import through `chrys.kernel` (exceptions: `_KERNEL_PRIVATE_IMPORT_ALLOWLIST`).
- **service/** (tier 2): llm (`wire_client.py` + one package per wire protocol), profiles, tools (builtins incl. web), mcp, skills, hooks, approval, session, state, context (compaction), mutations, agent_middleware, acp_client, workflows (SDK, graph, scheduler, protocol, worker host).
- **orchestration/** (tier 3): startup, engine (assembly, build, run, state), invoker, sub_agents, session_host, workflows (worker client, agent nodes).
- **app/** (tier 4): cli, tui (screens, widgets, behaviors, terminal), acp, features.
- `service/workflows/sdk/` and `service/workflows/worker_host.py` run in the user's interpreter: stdlib-only, Python 3.9 syntax (`tests/architecture/test_workflow_worker_purity.py`); don't modernize them. `service/workflows/worker_host.py` mirrors protocol constants pinned by `tests/service/workflows/test_protocol.py`.
- `tests/` mirrors the tiers plus `integration/` (offline cross-layer), `architecture/` (guards) and `support/` (shared helpers); kernel tests are flat.

## Conventions
- File header: `# Copyright (c) Huawei Technologies Co., Ltd. 2026. All rights reserved.`, a blank line, then the module docstring. Builtin workflow templates users copy (`service/workflows/builtins/<name>.py`) open with a one-line `#` description instead.
- `from __future__ import annotations`; `X | None`, `list[X]` (Ruff UP).
- Async-first on event/engine/invoker/tool/host paths; `asyncio.get_running_loop()`, never `get_event_loop()`. A cancel-safe close runs as ONE task that every caller drains with `foundation/util/once_close.py::finish_close` (`OnceClose` wraps a close callable); a cancelled waiter never stops the drain.
- No `getattr`/`hasattr` on first-party types — add a typed field or Protocol (getattr only at SDK/external boundaries). Some existing `getattr(x, "a", default)` defaults hold up test doubles that lack the attribute: give the double a real field before converting.
- No `assert` in `src/`, even under `TYPE_CHECKING` (Ruff S101 + source AST guard); its substitute is a raising check or typed accessor, not a `cast`, an ignore comment or a silent return.
- **Tools**: params are `Annotated[T, "description"]` (drives the schema) with `T` importable at runtime, not only under `TYPE_CHECKING`, or schema generation raises. Failures `return tool_error("<error_kind>", message)` (`service/tools/result_metadata.py`; e.g. `"path_not_found"`) — it adds the `Error: ` prefix the UI keys on plus the failure metadata the loop, persistence and ACP read. A raised exception shows the model only the fixed `Error: Function failed.` (its text goes to the failure record); to show a raised failure, raise `kernel/exceptions.py::ModelVisibleToolError(message)` (read as `Error: <message>`) with server-sent or Chrys-written text, never another exception's `str()` (local paths, URLs, tokens). Attach a kind (bare strings in `foundation/tool_kinds.py::TOOL_KINDS`, some dotted, plus each extension's `extension.<id>`, which code that validates kinds accepts via `is_extension_kind`) with `set_tool_kind`/`get_tool_kind`, never `FunctionTool.kind` (`chrys_kind` is the one kind channel; `.kind` stays None). Fuzzy path correction (`foundation/platform/paths.py::resolve_existing_path`) is for read-only tools; write/edit use the exact path given. Import the shell-filter API from `service/tools/builtins/shell_filter.py`, never the `shell_command_filtering/` package.
- Pillow: every `Image.open` passes `formats=`, also when handed on (`to_thread`/`partial`), and `ImageFile.Parser`/`ImageGrab.grabclipboard` (no formats) need an allowlist entry (guard `tests/architecture/test_hygiene_pillow_formats.py`). Attached, viewed and previewed images decode only `foundation/text/images.py::IMAGE_DECODE_FORMATS` (PNG, JPEG, GIF, WebP, BMP); a caller that needs more names its own wider tuple (documents: `doc_converter/parsers/base.py::DOCUMENT_IMAGE_DECODE_FORMATS` adds TIFF and JPEG 2000). Libraries that call Pillow themselves are narrowed too: pypdf through `parsers/pdf.py::_restrict_pypdf_image_decoders`, and the XLSX parser never reads chart sheets (openpyxl decodes their pictures).
- `except A, B:` is valid 3.14 syntax (ruff format writes it) — don't "fix" it. `TimeoutError` (what `foundation/util/lock.py` raises) is an `OSError`: put `except TimeoutError` before `except OSError`. Pass `encoding="utf-8"` to `open`/`read_text`/`write_text` (Windows defaults to the locale code page).
- Comments state the invariant, never this repo's issue/PR numbers. Write visible Unicode literally (`→`); keep `\uXXXX` for invisible/confusable characters and lone surrogates.

### Cross-platform
- Branch behavior on `foundation.platform.get_platform()`. Use raw `sys.platform == "win32"` (the check ty narrows) or `posix_os = cast(Any, os)` only to reach platform-only APIs.
- Every module must import on Windows: POSIX-only names (`fcntl`, `SIGKILL`, `os.killpg`) stay behind a `sys.platform` guard or inside functions.
- Windows: never wait on a handle from an executor thread (`run_in_executor`/`to_thread` + `WaitFor*`): the `min(32, cpus + 4)` pool fills, every `to_thread` queues behind it and the loop blocks. Use `loop._proactor.wait_for_handle(handle)` (IOCP), as `foundation/patches/textual_win_sleep.py` (timers; cancel/close protocol in its docstring) and `foundation/platform/process.py` do. Never close a handle under a registered wait; bound every post-cancel settle wait, or `Runner.close()` wedges. Tests never give a real proactor a made-up handle (fatal `0xC000070A` kills the xdist worker silently): stub the module's `get_running_loop` via a shadow `ModuleType`.

## Subsystems quick-ref
- **Settings** (`foundation/config/`; layers in `spec.py::Source`, names/defaults/clamps in `settings.py`), per key low → high: defaults < `<config_dir>/settings.yaml` (the only file the settings panel writes) < `<project>/.chrys/settings.yaml` (read only when the user's own settings enable `project.config_enabled`; per-key `ProjectMerge` defaults to DENY — only a few keys accept a project value, some in one direction only) < process env (snapshotted at bootstrap; later `os.environ` writes are ignored) < CLI flags < process runtime (e.g. an activated model profile) < session pins < live changes. `SettingsHandle` keeps the load (`base`), the session's own model (`Source.SESSION`: a prompt shortcut's or a restored session's, ended by `close_session`) and live choices apart: re-loads compare against `base` and rebuilds stage `base` plus the session's choices (`AgentLoader.stage`), never `loaded`, which would fold both into the next load. iCode never loads or migrates `.env` files; settings use YAML and the startup environment. `CHRYS_DEBUG_LLM_RAW_HTTP_LOG=1` captures raw provider HTTP (`service/llm/raw_http_log.py`); `CHRYS_ASK_USER_TIMEOUT_SECONDS` defaults to 900 (≤0 = no timeout).
- **Profiles**: builtins `service/profiles/agents/builtins/{Code,QA,Explore,General}.yaml` (fixed ids mirrored in `service/profiles/agents/registry.py::_BUILTIN_IDS`; Code/QA are main-eligible, Explore/General `sub_agent_only`); a user `<config_dir>/agents/<Name>.yaml` shadows the builtin. The profile dir is caseless on macOS/Windows: where file ownership matters (ACP profile mutations) compare the stored `name:` (`service/profiles/agents/serializer.py::stored_profile_name`), not paths. References to the retired `Plan` profile are dropped, never remapped (unless the user owns a `Plan`).
- **ACP sub-agents**: a profile with an `acp:` section is forced `sub_agent_only`. Only spawn/initialize failures auto-retry; failures from `session/new` on pause with `reason="acp_transport"`. Audit/pending artifacts are owner-only; argv values are redacted, the full argv kept only as a keyed HMAC.
- **Approval** (`service/approval/policy.py`): `ApprovalRule` (`auto | require | skip`) is one tool's rule; `ApprovalMode` (manual / auto = LLM judge / bypass) covers a launch. `_resolve_rule`, first match wins: session override (if `user_can_override`) → `kind.tool_name` → bare tool name → kind → the called tool's own declaration (`foundation/tool_approval.py`; local web tools and `run_skill_script` declare it; read from `context.function`, never by name or kind) = require → profile default. Override keys split at the LONGEST known kind prefix, not `rsplit`; a bare key equal to a kind is a kind override; an invalid rule value fails closed to require. The mode lives only in `ActiveSession` (`orchestration/engine/state/active_session.py`) — never in session files, workflow checkpoints or drafts — survives `/new` and restore, and is shared by chat and workflows; `SetApprovalMode` for another session id is ignored; persisting bypass as the default saves `auto`.
- **LLM** (`service/llm/`, `service/profiles/models/`): providers `openai`, `anthropic`, `deepseek-openai`, `glm-openai`, `mock`; `openai` and `deepseek-openai` take `api_style: chat_completions | responses` — add a variant as an `api_style`, never a provider id. Each wire protocol is a package (`chat_completions/`, `openai_responses/`, `anthropic_messages/`) whose client subclasses `wire_client.py::WireClient`, which alone implements the kernel's `_inner_get_response` for them (request reporting: `observer.py`); a protocol implements `_send`/`_open_stream` and builds each request through one method that ends with `_stamp_request_headers`. What an endpoint does differently within a protocol is a field of its `ChatCompletionsVariant`/`ResponsesVariant`, never a subclass overriding codec methods (DeepSeek/GLM subclasses only set the variant and kernel trait ClassVars). Responses wire shape → `service/profiles/models/schema.py::is_responses_wire_dialect`; service-side continuation → `provider == "openai"` only; never conflate them. Build request options only via `service/profiles/models/options.py::effective_chat_options` (Responses defaults to `store: false`: service-side is opt-in). `service_session_id` is reused only under effective service-side storage with matching fingerprints/workspace, and cleared on retry, interrupt and incompatible restore (local history stays authoritative). Protocols that keep no conversation state set `FORCES_STATELESS` (Chat Completions, Anthropic Messages, DeepSeek Responses). The codecs' provider-compatibility repairs (tool-call canonicalization, millisecond `created`, unsigned-thinking drop, Anthropic cache-token fold) are load-bearing: remove one only after a test proves its case can no longer occur.
- **Web tools**: `service/tools/builtins/web/build.py::assemble_web_tools` is the one assembly every build path calls; a web config error drops only the web tools (`web_tools_unavailable` warning), never the agent. All web egress goes through `http.py` beside it (IP-pinned; proxy rules in its docstring).
- **Hooks**: external subprocesses from `<config_dir>/hooks/hooks.{yaml,yml,json}` and project `.chrys/hooks/` (loaded only when `project.hooks_enabled`, default off; project runs first; its block ends the chain). Only `before_tool_call` and `user_prompt_submit` can block; hooks may deny or rewrite args but never grant or bypass approval. `match.tool_kind` is kind-only; `match.args` keys are literal arg names. Slow session switch/restore: check hooks first — in the session's `trajectory/events.jsonl`, join `hook.operation.finished` `duration_ms` to its `hook.operation.started` `hook_key` by `operation_id` and sum.
- **MCP** (profile `tools.mcp`, stdio | http): agents with the same effective config share one connection (`service/mcp/cache.py`) with per-consumer tool clones and per-run progressive-disclosure state and result caps; a field that changes the connection belongs in the cache key. Profile YAML headers resolve `{{ENV_VAR}}` unless `resolve_header_templates: false`. `max_tool_result_tokens` caps remote `tools/call` text (default 8k; `0` disables only this cap — the kernel-wide `CHRYS_TOOL_RESULT_CEILING_TOKENS`, 64k, still applies). `service/mcp/` depends on private `mcp` SDK internals (`_http_transport.py`, `_stdio_transport.py`, `owned.py`; stock fallbacks where possible): after an `mcp` bump keep `tests/service/mcp/test_private_contracts.py` green.
- **Skills**: `<config_dir>/skills` always; `~/.agents/skills` on by default (per-profile opt-out); `<cwd>/.agents/skills` only when `project.skills_enabled` (default off) and the profile's working-folder toggle are both on; inline profile skills. Script results default to 8k tokens and resources to 16k; script/shell/MCP truncation spills the captured text under the session (`tool_results/`); shell/skill capture keeps a bounded head and tail per stream (`foundation/platform/output_capture.py`).
- **Compaction**: triggers at context window − max output tokens − max(5k, 5% of the window), floor-clamped (`service/context/compaction/budgets.py`); 4-phase and turn-aware; the final last-words note runs on the owning agent's model. A strict provider overflow (`is_context_overflow`, never 413 or a 5xx naming the window) is noted on the strategy (`kernel/compaction.py::ContextOverflowSink`, from both loop paths before any retry decision), and the next pass then runs below the trigger, clearing the note only when a pass completes. When the note says compacting can help (not when `context_overflow_limit` names a limit below the strategy's window: the main-turn and sub-agent failures then pass that window to `display_fields`, which says what to set), a run with a wire policy resends once per logical call in place (`RetryMode.CONTEXT_OVERFLOW`, announced like a wire retry; never with a live continuation token or after hosted work blocks replay), so that resend compacts first; a second overflow is terminal; an OUTPUT_TRUNCATED verdict whose usage counts no reasoning tokens only sets that note (still terminal), and a `LastWordsGenerationError` never does.
- **Mutations**: write/edit hooks + shell scan + `GitDiffCalibrator`; the git scope is command cwd ∪ `workspace.primary_cwd`, deliberately not clamped to the workspace (monorepo commands run from the root).
- **User guide** (F8 or `/help`; `app/tui/screens/guides/`): reads `docs/index.yaml` + `docs/<locale>/` at runtime; the wheel bundles `docs/` via `force-include` (CI checks it); `CHRYS_DOCS_ROOT` overrides. A page must be listed in `index.yaml`; say iCode/`icode` (internal names stay); `#anchors` are GitHub heading slugs. Pages are for users, not developers or implementers: in plain words, from the user's side, say what to do and what they will see, and leave out implementation details unless the user needs to know them.
- **`icode serve`** keeps `Referrer-Policy: same-origin`: with `no-referrer`, browsers send `Origin: null` and form POSTs fail the origin check.

## Invariants & gotchas
### Transcript & identity
- **System reminders** (`service/agent_middleware/system_reminder.py`; its module docstring specifies what is sent when): per-turn context rides trailing `<system-reminder>` blocks on user messages of the per-call copy, never the system prompt or a message's own contents. A user message records what its established request carried (`HistoryMarkerKind.SYSTEM_REMINDERS_KEY`) and every later call re-renders it byte-identically, so the cached prefix survives: code that rebuilds a user message carries the record (`copy_reminder_record`), and reminder text never varies per call (no timestamps; only LAST_WORDS is dynamic and unrecorded). The core owns when each reminder is sent, its record and the order; its text and state live in a source under `service/agent_middleware/reminders/`, whose turn transitions only the core drives (outside callers: the allowlist in `tests/architecture/test_hygiene_reminder_sources.py`). `LastWordsState` is built only with its middleware (`orchestration/invoker/runtime.py::create_reminder`) and bound/restored only as that pair. Only user-role text is escaped: reminder-shaped text in tool results is untrusted.
- **Ids are not identity**: `call_id`s recur across exchanges (replayed or provider-limited histories); `message_id` `msg_N` is positional and compaction re-mints ids still present in archived `compressed_msgs`. Occurrence identity is `_chrys_analytics_item_id` (`foundation/trajectory/metadata.py`): minted once, copied verbatim by save/restore/compaction/fork/rollback — never re-mint it on a copy. Before deduping or joining on any id, read its generator's uniqueness scope.
- **Sub-agent audit replay**: the contract is the header of `service/session/sub_agent_transcript.py`. Audits declaring `analytics_item_id_v1` dedup archived/live twins only by `_chrys_analytics_item_id`; older audits get a conservative best-effort content match. Every new removal rule needs a paired test that an equal-content occurrence survives.
- **Final response = the kernel loop's assembled Messages** (`kernel/loop.py::_LoopRun.finalize_stream`). Never re-merge content downstream with `from_updates`: it mints new Contents and drops kernel stamps (`_chrys_tool_invocation_order`, `_chrys_tool_kind`, `_chrys_tool_context`, `_chrys_tool_result_metadata`). Mid-stream consumers see fragments: anchor side effects by role + call_ids + content signature, never identity alone.
- **Invocation order**: only the kernel loop stamps `_chrys_tool_invocation_order`, at response arrival, on every non-informational `function_call` (invalid, unknown and filtered calls consume ordinals too). Never count calls to rebuild order or re-attach result metadata by position; order-matching consumers read the stamp and fail closed without it. Result metadata rides `FunctionInvocationContext.metadata` and is folded into the result Content at construction.
- **Exchange grammar** (spec: `kernel/exchanges.py` header): pair calls↔results only via `iter_exchanges`/`pair_results`, never a global call_id scan. Hand-rolled transcript walks, and `is_result_only_message` outside the grammar, are banned in src (`tests/architecture/test_hygiene_exchange_walkers.py`). Completeness reads `answered_keys` (one result answers every same-id call), never occurrence counts. Any message carrying the `_chrys_kind` marker key is a hard boundary. Reuse `TOOL_CALL_CONTENT_TYPES`/`TOOL_RESULT_CONTENT_TYPES`; a new tool content type also goes into the literal copies in `tests/support/` (parity pin in `tests/kernel/test_exchanges.py`).
- **Share Content objects, copy only wrappers** — shared content identity is the only stable state↔wire link:
  - Outgoing messages are `kernel/client.py::_wire_message_view`s (fresh wrapper and contents list; shared Content objects and `additional_properties`, the sanctioned write-through channel); landed messages are `kernel/_loop_recorder.py::_message_snapshot` copies. Never share a Message wrapper loop↔client or rebuild Contents on a path matched back to state. Every wire→state matcher needs a content-identity tier (injection/exclusion anchors, compaction's `_state_correspondence` — without it prior-turn compaction silently disables).
  - Echo removal drops Content OBJECTS the conversation already holds, by identity only (a new Content reusing an old call_id is fresh work): streamed updates at the final-handler boundary (`_strip_echoed_update`), responses as the loop lands them (`_land_response_contents`), both in `kernel/loop.py`. It never mutates the incoming message (it shallow-copies it), drops echo-emptied streamed shells by per-message `_chrys_echo_content_stripped` provenance (never a call-wide flag), and exempts usage content.
  - id()-keyed memos that outlive a call hold weak identities (`kernel/identity.py::WeakIdentityRegistry` or `weakref.ref`) so a recycled id never false-matches; `_process_update`'s per-pass `seen_contents` is strong on purpose. A new copy site gets a fresh-vs-shared pin in `tests/architecture/test_copy_freshness.py`.
- **Transcript oracle** (`tests/support/transcript_invariants.py`): loop tests build `InvariantCheckedToolLoopLayer`; constructing or subclassing a raw `ToolLoopLayer` is banned (`tests/architecture/test_hygiene_test_source_rules.py`). A firing invariant means the loop broke — never switch to the raw layer or loosen an assertion; a real contract change updates the oracle and its red-path pins (`tests/kernel/test_transcript_invariants.py`) together. The oracle walks independently by design (never import production grammar into it); unanswered calls are legal.

### LLM wire & retry
- **Error classification** (`foundation/errors/`): provider and network errors are judged only by `classify_error` (kind, retryable) and the predicates built on it (`is_retryable`, …) — never a hand-rolled chain walk or phrase table elsewhere. A new rule reads only the explicit graph (`_walk.py::iter_explicit_graph`: `__cause__`, exceptions held in `args`, group members; never `__context__`, which may hold a stale earlier failure); only the frozen legacy layers in `_legacy.py` read the full chain. The window limit an overflow names is read only by `context_overflow_limit`. Socket and resolver leaves are judged by the literal per-OS code tables in `network.py` (`winerror` before `errno`), never message text. Every LLM request carries a `RouteFacts` snapshot in `request.extensions["chrys.route"]` (route hooks run first, `service/llm/route_facts.py`); name-not-found is retried only when that first hop (proxy, else target) answered earlier in this process. A test that needs a direct route sets `NO_PROXY=*`: with no proxy env at all, httpx falls back to the macOS/Windows system proxy.
- **Client lifetime** (`service/llm/clients.py`): `create_client` is an async factory that closes whatever it opened when it fails. Its caller hands the stack to exactly one close owner before its next `await` (`await prepared.own_or_release(client.aclose)`, which closes the client itself if the owner began closing during the factory's `await`; a slot's `OnceClose`; an object whose `aclose` closes it), or makes a one-shot call inside `async with scoped_client(...)`; every call site and its owner is listed in `tests/architecture/test_hygiene_llm_client_owners.py`. Chrys builds every profile's httpx client (`_build_profile_http_client`) to match the SDK default's pool, proxy and TLS setup (`tests/service/llm/test_default_http_client_parity.py`).
- **Retry commit points**: every ANSWERED result slot — arg-invalid, unknown-tool and failed results included, synthetic interrupted fills excluded — is an irrevocable commit; whole-run retry never replays a committed call. Hosted calls bypass the loop recorder, so `ResponseValidationMiddleware` (`service/agent_middleware/response_validation.py`) records them (`hosted_commits`) — an adapter that fails a response after the provider ran hosted work hands it over as `ProviderResponseError.observed_contents`, and wire clients pass that error through unwrapped — and no lane (wire, whole-run) re-sends a request after blocking hosted work unless a live continuation token makes it a poll. Every hosted adapter sets `foundation/hosted_tools.py::HostedRetrySafety`: SIDE_EFFECTFUL/UNKNOWN (MCP, shell, file ops, generic) block; READ_ONLY/SANDBOXED (search, fetch, tool discovery, code, image) don't.
- **Storage mode** (`kernel/client.py::resolve_storage_mode_and_handles`): options are the wire truth (`extra_body` beats the named param; a present `store: null` means the provider default); client kwargs may only escalate to service-side; every caller passes `force_stateless=client.FORCES_STATELESS`, which vetoes service-side. Service-side forbids in-place wire retry; local mode allows it.
- **Response validation** is terminal-only: `ResponseValidationMiddleware` passes a stream through unbuffered and judges the landed response in a result hook; a rejected response fails the pass (`TerminalResponseValidationError`, content filter as `ProviderResponseError`) and is never sampled again, but for a response that showed nothing (no message, empty, blank or reasoning-only; marked `blank_response`, read by `is_blank_response`): a run with a wire policy resends its request once per logical call in place (`RetryMode.VALIDATION`, announced like a wire retry; never after hosted work blocks replay) — except the tool loop's exhaustion tail (`EXHAUSTION_TAIL_KWARG` in its `client_kwargs`), whose blank response is accepted and answered by the loop's fallback text. It sits innermost on every chat-middleware chain but for usage, which counts each landed response before validation may reject it. Every `KernelConversation` build path lists `begin_pass_hosted_baseline` in its start hooks (fired by `PassResources.begin()` inside the pass try); the baseline keeps the hosted observations while the pass polls a background response an earlier pass left running.
- **Chat Completions reasoning** (`service/llm/chat_completions/`): replay is per reasoning format, never per provider (Kimi runs on plain `openai`; api.openai.com ignores unknown message-level fields but strictly validates top-level params): each captured value replays under the field it came from (`reasoning_details`/`reasoning_content`/`reasoning`), and a `ChatCompletionsVariant` only narrows when replay happens (`reasoning.py::replays_reasoning`). An unknown-but-present `openai_reasoning_format` marker replays nothing; a new `protected_data` writer must audit every consumer (chat_completions, openai_responses, anthropic_messages). Within a run, text is rebuilt per segment (`service/text_blocks.py`): tool calls and degraded hosted summaries start a new segment, reasoning never splits one. Tool results directly follow their `tool_calls` carrier and reasoning never moves back across a result (`history.py`: `encode_reasoning_message`, `canonicalize_tool_call_messages`).

### Runtime state
- **Workspace cwd**: resolve relative paths (approvals, hooks, MCP cache keys, mutations, events) from `SessionEnvironment.cwd`/`Workspace.primary_cwd`, never the process cwd, and pass it explicitly: hooks, the MCP cache, the mutation detector and `SessionEnvironment.capture()` silently fall back to `os.getcwd()` when given none.
- **Surrogateescaped paths (POSIX)**: filesystem-derived paths may hold lone `\udcXX`; only the raw `str` round-trips to the real bytes, so keep it raw in `SessionEnvironment`, `Workspace`, `SessionMetadata`, restore state, in-process events and subprocess `cwd`. `foundation/platform/files.py::surrogate_safe_text` names a DIFFERENT path: apply it only to a derived copy right before model/API/display output. Identity keys and hashes encode the raw value injectively (JSON `ensure_ascii=True`, `os.fsencode`), else `\udcXX` aliases a literal `\\udcXX` path. Atomic writers and `tool_error()` already make output safe; the filesystem tool's length-preserving `_replace_surrogate_escapes` must stay separate from `surrogate_safe_text`.
- **History**: new marker/trim/repair/metadata operations on `chrys_history` go into `service/session/history.py::SessionHistoryManager`, not call sites. It is not the only writer — the history provider, child histories (`orchestration/invoker/child_history.py`), turn resume/retry restore, and whole-state swaps (session restore, rebuild, fresh workflow passes) write too — so a history invariant must hold on all of them. Markers are `_chrys_kind` entries in `additional_properties`. A failed or interrupted turn keeps the model text it showed: trim keeps the answer text of a response whose calls all went unanswered, and the finalizer appends what the pass showed that history does not hold (`ContentProjector.take_unlanded_answer` → `keep_partial_answer`, one text content per segment: a stream cut off, or a response landed before history stored it); a bare Continue drops such a trailing answer, and the answer tail of a last exchange message (`remove_trailing_answer`; exchange work stays), and asks for it again, since no request may end with assistant text. Frontends drop exactly what history dropped: the projector stamps every answer text it publishes with its `segment_id` (`ANSWER_SEGMENT_KEY`, never on the wire), the drop returns the stamped ids and its owner publishes `InvocationAnswerWithdrawn` (main turn: the runner via `retry_request(withdraw=)`, right then; sub-agent shell after `InvocationResumed`, where an ACP child names the answer shown after its last tool card, which a retry's new session asks for again; workflow node with the next pass's `InvocationResumed`, each delivered through `finish_close`), and the TUI, nested journals and ACP (`chrys/messages_retracted`) remove those segments' messages, live or replayed; unstamped legacy text is not withdrawn.
- **Persisted state**: a new provider-state key must be in a key table in `service/state/serializers.py` (`_COPY_AS_*`, `_PASS_THROUGH_OPTIONAL_KEYS` — all saved only if truthy — or `_PASS_THROUGH_NULLABLE_KEYS`, saved unless None), or save drops it silently. Old sessions must keep loading and resuming: fixes apply to newly written data, never backfill old records, and compatibility shims stay narrow and read-only.
- **Turn boundaries**: resolve turns only via `foundation/models/turns.py` (`opens_turn`, `turn_slices`, `current_turn_start`, …), never raw `role == "user"` or `"continue"` text. A user message added mid-turn carries `_injected` (set at creation, never sent on the wire) or it opens a turn. Text-dedup user messages only via `user_text_matches(kind=...)`, so an injected note never matches an identically worded opener; injected copies dedup by `_injection_id`. `_continuation` nudges are legacy and read-only: never mint one.
- **Injections** (`service/agent_middleware/injection.py`): one drain = one immutable batch, registered for retry replay before its first `await`; later tool iterations resend clean middleware-owned copies, never the reminder-enriched wire list. An injection that misses the run is drained at finalize as `consumed=False` and returned to the input box — a finished `agent.run()` is terminal; never add a follow-up run to deliver it.
- **Trajectory**: recording never blocks a user-visible path and never precedes the commit it describes. `EventDraft` takes its timestamp at construction but its sequence at emit: build each draft at its emit site.

## Persistence
- Config/data dir (`<config_dir>`): `~/.chrys` (macOS/Linux), `%APPDATA%/chrys` (Windows). Sessions live in `<session_root>/sessions/<short-id>/`; `<session_root>` is `CHRYS_SESSION_ROOT_DIR` / `storage.session_root_dir` (the PARENT of `sessions/`; restart-only, not project-settable), defaulting to `<config_dir>`. Resolve via `resolve_sessions_dir()`. `get_platform().config_dir` and the resolved sessions dir are real paths (links followed, except one whose target is missing, such as an unmounted disk), since the owner-only file helpers refuse a link anywhere on a path; only the uninstaller wants the as-named, possibly linked `conventional_config_dir()`. `session_dir("")` is the sessions ROOT: reject empty ids before any delete or rmtree.
- Per session: `session.json`, `session.json.bak` and the crash sidecar `session.recovery.json`; `<session_root>/sessions/.locks/<short-id>.active.lock` marks the one owning process. Subdirectories are created by their owners.
- The recovery sidecar is written mid-turn, deleted by every primary save and never part of the `.bak`/snapshot heal chain. A reader considers it only with `prefer_recovery=True`, after owning the active lock or finding it unheld; it wins when newer than the primary or when the primary is missing/unreadable.
- Fork copies the whole session dir: a new per-session file that embeds the session id or absolute paths needs handling in `service/state/_fork.py`.
- Startup restore (`-s`) is transactional: it succeeds only after the matching `SessionRestored` is observed (a normal return proves nothing — `publish()` swallows handler errors). On failure, suppress persistence while tearing down partial bindings, workspace, session id and lock, reset to a fresh baseline (`engine.reset_after_failed_startup_restore()`) and clear the TUI's restoring state (`cancel_startup_session_restore()`) before the fallback start.
- `_intermediate_text` (text the model wrote between tool batches) is saved on the message its `batch_id` maps to, never located by position, and skipped when that message already shows it. Replay's shim for old sessions (sidecar shifted one batch) must not cross user/non-tool boundaries.

## TUI
### Structure
- `tests/architecture/test_tui_structure.py`: widgets never define or runtime-import Screens/`screens.*` (TYPE_CHECKING is fine); chat replay/toc models import no Textual or sidebar widgets; `app/tui/terminal/emulator/` runtime-imports no Textual and no `chrys.*` beyond itself; `app/tui/screens/main/` controllers and facades (the files `_main_screen_boundary_checked_files` lists) never import `MainScreen`, keep a back-reference to it or `query_one` — they go through `ports.py` Protocols (no concrete widgets) and `MainScreenViewAdapter`.
- A one-screen package is `<pkg>/screen.py` + `screen.tcss`; dialogs are `<name>.py` (+ `<name>.tcss` when styled); reusable widgets use inline `DEFAULT_CSS`.
- Terminal program input is `str` end to end; a non-text byte rides as a `surrogateescape` lone surrogate that only the POSIX writer turns back into the byte (never `"ignore"` it there; ConPTY drops it).

### Text & styles
- Textual parses a plain `str` as markup: `list[int]` renders as `list`, `[/x]` raises `MarkupError`. Pass dynamic text (system, profile, model, tool, user, file) as `Text(...)`, `Content.from_text(v, markup=False)` (bare `from_text` is guard-rejected under `app/tui/`), `markup=False` on `Static`/`Label`/`notify`, or `textual.markup.escape(...)`. `Content.from_markup` is for hardcoded templates only.
- Textual and Rich pass ESC/control characters through: sanitize external text with `sanitize_legacy_block` (multi-line) / `sanitize_legacy_scalar` (labels, titles) from `foundation/i18n/formatting.py`, or `app/tui/util/source_text.py::sanitize_source_text` (code, output). `app/tui/widgets/chat/tool_view_builders.py::build_code_view` sanitizes; any renderer bypassing it must call these itself. Copy keeps the raw text.
- Never put Textual color tokens (`ansi_*`, `auto 60%`, alpha colors, `app.theme_variables`) in Rich style strings: convert plain colors with `app/tui/util/rich_style.py::rich_style_from_textual_color`; resolve composite/alpha values through a component class and non-partial `get_component_rich_style()` (see `ToolCardHeader._zone_style` in `app/tui/widgets/chat/tool_call.py`).

### Performance — restyle and layout cost grows with the mounted transcript
- Any App-wide stylesheet update, restyle, recompose or layout is O(mounted transcript) and GC tuning cannot fix it. Focus/blur, overlay open/close, binding changes and small-panel toggles must not restyle, recompose or relayout MainScreen; setters are idempotent and emit nothing for unchanged values. Modal first-open work stays screen-local, with heavy I/O after the loading shell paints; covered MainScreen widgets never recompose behind overlays.
- Hide with `widget.display = False/True`, not `-hidden` classes, `visibility` or shadow flags. Hot fixed chrome uses `app/tui/util/visibility.py::set_widget(s)_visibility_without_layout` (syncs compositor maps, moves focus out). Labels whose text changes often: fixed width + `update(..., layout=False)`.
- Keep the version-gated `ChrysApp._load_screen_css` (parses new rules, restyles only the new Screen) and scoped Screen selectors; add no dynamic/global CSS loading without a populated-transcript regression test. A theme change is the one global pass: fold class changes into it with `update_classes(..., update=False)`; a theme flip repaints, never recomposes.
- Never call `refresh_bindings()` unconditionally. `ChrysFooter` recomposes only on a real signature change while its owning Screen is current; that Screen calls `sync_bindings()` in `on_screen_resume()`.
- Large-history replay plans detached, precomposes the widget forest and mounts in bounded batches, never per-entry mount/layout. `ChatPanel.mount_transcript_widgets` returns once the newest ~3 viewports are mounted (the loading UI counts those, once per batch); `app/tui/widgets/chat/replay_mount.py` then prepends older entries in the background, holding a scrolled-up view on its content until the last batch has laid out (after the prepend ends). Pending entries sit directly above `ChatPanel.transcript_entry_after(<last pending>)` (entries mounted before the replay stay on top), and transcript readers splice `pending_transcript_widgets()` in there; a TOC jump to a pending turn, or into a prepended batch before the refresh after it mounted (a child from registration, no geometry yet), waits for that refresh, and a user scroll intent drops it; a TOC jump fences the settle re-pin (`reanchor_after_settle`) and the replay's final scroll to the bottom already queued; one GC pause spans the replay (young passes between batches free its cycles) and one full collection ends it. Tests await `ChatPanel.wait_replay_complete()` before reading the whole transcript.
- Periodic timers on always-mounted widgets `pause()` on Hide and `resume()` on Show; a widget mounted inside a hidden container never gets Show, so its first tick pauses the timer (templates `ChrysLoadingIndicator`, `BuddyPanel`; add a parked-while-hidden test). Stock Textual also drops Show (and the first Resize) when a geometry read between a display flip and the next reflow rebuilds the full map lazily; `foundation/patches/textual_reflow_reuse.py` reports Show against the previous reflow's map instead. Out-of-process polling (buddy reload) may keep ticking. Paint gates use `is_widget_shown_on_active_screen()`, never `is_on_screen` (it re-arranges the screen whenever the compositor map was invalidated).
- A retained thread object pins the App (`Thread.__init__` keeps `sys.stderr`, the App's print capture) — see `foundation/patches/watchdog_fsevents.py`. Find leaks with per-test `len(gc.get_objects())` after `gc.collect()`; Textual's bounded caches plateau.
- Streaming is per-delta work and must stay throttled: a streamed answer hands its text to markdown at most every `messages.py::_STREAMED_BODY_INTERVAL_SECONDS` (a final update at once), its height change lays the transcript out once (`StreamedMarkdownMessage._size_updated` passes `layout=False`), and the status bar refreshes at most every `_STATUS_MIN_INTERVAL_SECONDS` while always landing the last state.
- The chat panel's one-shot pull to the bottom when terminal content lands (final answer, error/interrupt/retry banner) is deliberate even after the user scrolled up (`app/tui/widgets/chat/scroll_controller.py`).

### Textual traps (Textual pinned at 8.2.7)
- Dispatch runs one named handler (plus `@on` handlers) per MRO class — private `_on_x` beats `on_x` — and checks `prevent_default()` only between classes; `event.stop()` only stops bubbling. Overriding a handler and calling same-name `super()` runs the base twice unless you `prevent_default()` first — also when you perform the base action by hand (`super().press()`). Click-consuming pseudo-buttons call `prevent_default()` and `stop()` (use `ClickAffordance`). Watchers differ: plain attribute lookup, and both `_watch_x` and `watch_x` run.
- Code any cancellable task can run (workers, spawned tasks, EventBus handlers — which run inside the publishing engine task an interrupt cancels) removes widgets via `app/tui/util/removal.py` (`remove_shielded`, `remove_children_shielded`, `finish_shielded`): a cancelled removal leaves zombie widgets and kills the App's message loop.
- Rebuilds: async handler, await the removal, then one `await mount(*widgets)`; in a scroll container wrap both in `app.batch_update()` or `scroll_y` clamps to 0. Pruning parents drop mounts silently: return the real attachment; recheck prerequisites after taking structural locks. During Screen removal or App shutdown `is_mounted` (and `is_attached` before `exit()`) stay True while `mount()` no-ops: deferred callbacks bail on `not app.is_running`/`_closing`/`_pruning`. Before removing a focused subtree, `set_focus(stable, scroll_visible=False)`, or Textual's refocus animation overrides your scroll.
- `widget.prevent(...)` shares one App-wide stack: held across an `await` it drops that message type everywhere — use `app/tui/util/message_gate.py::messages_disabled`.
- `call_later`/`call_after_refresh` return False when rejected (release pending state); `call_after_refresh` runs on the TOP screen once it idles, possibly before a just-shown widget has a size. Unsubscribing a Signal doesn't cancel queued deliveries: fence stale callbacks with a generation, or unsubscribe, enqueue a same-pump barrier with no `await` in between, check it was accepted, then await it.
- `dismiss()` resolves the future, queues the result callback, then pops whatever screen is on TOP: guard with `screen is app.screen`; cleanup follows resource ownership, not callback timing.
- A live TextArea owns its draft: never write back a draft snapshot taken before an `await` (it clobbers newer input, whitespace included); `load_text()` resets the cursor.
- CSS: scoped `DEFAULT_CSS` rules that don't start with the defining class match only its descendants; non-default stylesheets beat `DEFAULT_CSS` even with `!important`; Screen `CSS` is scoped, `CSS_PATH` is not. Never define `_running` on a widget (it's `MessagePump`'s).
- `foundation/patches/` patches Textual: file patches rewrite the dev venv's site-packages at bootstrap, while CI runs stock Textual plus only the runtime patches `tests/conftest.py` applies — tests never import patch-added symbols. A Textual bump re-verifies every patch and every adapter over Textual privates (`app/tui/app.py`, `toasts.py`, `themes/preview.py`, `screens/main/screen.py`, `util/visibility.py`, `widgets/chrome/input_bar.py`'s undo/redo field replay, …; some silently no-op off the pinned version).

### GC freeze
- The TUI `gc.freeze()`s stable objects at idle points (`app/tui/support/gc_freeze.py`) so collections skip them. UI completion is not backend completion: freeze actions are hard-gated while `AgentEngine.is_turn_lifecycle_active` (covers session save and after-turn hooks) — never substitute the earlier FSM/UI idle flags. To wait for one turn's save, keep that turn's `turn_lifecycle_task`.
- A renderer that mounts substantial stable content after the turn's UI completes posts `GcAbsorbRequested(STABLE_CONTENT_MOUNTED)` after its final update; removing a large stable subtree posts idle `GcReclaimRequested(STABLE_CONTENT_REMOVED)` after the awaited removal; a real theme change requests an idle reclaim (`THEME_UPDATED`).
- Cache-heavy permanent surfaces implement `GcFreezeParticipant` and register in `MainScreen._gc_freeze_participants`; transcript widgets with cyclic LRUs join `ChatPanel._gc_freeze_render_cache_surfaces`; anything else must fit the retained-byte budget `scripts/calibrate_gc_freeze.py` measures.

## Testing rules
A rule that names a guard fails CI; the rest are review-only. A guard that can't go red is worse than none — it is believed. Check `tests/support/` before writing any wait, fake, fixture or path helper.

### Guards
- A new AST hygiene rule goes in a `tests/architecture/test_hygiene_*.py` family module (meta-guards in `test_test_hygiene.py` enforce registration and allowlist liveness pins); focused non-AST guards are standalone `tests/architecture/test_*.py`. Prove each new guard goes red under the real `-n 8` addopts, not only pytester `-n0`. Guards target what ordinary code would slip past, not deliberately adversarial code.
- `tests/architecture/test_hygiene_test_source_rules.py` also bans local wait helpers named `_wait_until`/`_wait_for`/`_poll_until`/`_wait_for_ui`/`_eventually` and `integration` marks under `tests/integration/`. Every `tests/**/*.py` is capped at 2,000 lines (`tests/architecture/test_test_file_size.py`; split by subject, never just to fit).

### Waits (`tests/support/waiting.py`)
- Positive waits use `wait_for(...)`. `wait_until` only when its bool is asserted or branched on (the AST guard catches only a bare `await wait_until(...)` statement); a bounded absence check is `assert not await wait_until(...)`; `wait_until_quiet(description=...)` shows stability, not drained work. No fixed sleeps or `range(...)`/`pilot.pause()` polling, even with `break`; `asyncio.sleep(0)` may force a known interleaving, never signal readiness.
- A producer that can fail early: wait for `ready.is_set() or task.done()`, await a finished task to surface its error, then assert readiness.
- Race tests: waiting for the event can close the very window under test — start A as a task, assert `not task.done()`, then release B; judge background work by its task handle, not a bool. Mid-run signal tests (interrupt/inject/approval) first prove the run is in flight: a tool the test holds (awaiting an `asyncio.Event` it releases later) plus a call-count gate — `slow_echo_tool` only sleeps `delay` (default 0).
- Budgets: engine turns, and any wait whose window cold-starts a process (interpreter probe, workflow preview or run worker, hook command), pass `ENGINE_TURN_TIMEOUT` (15 s) — a loaded Windows runner spends seconds per start; a wait whose window builds the TUI's main screen passes `MAIN_SCREEN_BUILD_TIMEOUT` (10 s), the one exception to the no-raise rule at the end of this bullet: that build is CPU-bound with no single slow step, and takes up to 5 s on a slow macOS runner; pytest-timeout kills a test at 60 s (`thread`), and `faulthandler_timeout = 55` dumps every stack first. Serial waits share one budget via `@with_wait_deadline(ENGINE_TEST_WAIT_TIMEOUT)` (45 s from test-body entry, excluding fixture setup/teardown; bounds `wait_for`/`wait_until_quiet`/`await_run_task_chain`, not `wait_until` or raw `asyncio.wait_for`), otherwise a module `pytest.mark.timeout` with a reason. Default budgets stay strictly below the per-test timeout; count production fixed sleeps inside the path (ACP connect backoff starts at 3 s); never platform-scale a budget or raise one to fix a flake.
- Fake time or sleep by stubbing the module under test's own `asyncio`/`time` name through a shadow `ModuleType`, never the stdlib module: a non-yielding global `asyncio.sleep` starves `waiting.py`, and the event loop reads `time.monotonic`.
- A task that can't finish cancelling hangs pytest-asyncio's `Runner.close()` in teardown, possibly with no usable timeout output: `kill -ABRT <pid>` gets the stacks. A 55 s dump whose loop thread is busy computing (e.g. `refresh_css`) is CPU slowness, not deadlock — split the scenario.

### Completion & ownership
- Build engines with the `agent_engine` fixture (AST bans `assemble_agent_engine(...)` + `.start()` elsewhere). Read post-run engine state only after `await await_run_task_chain(engine, turn_state=engine.turns.turn_state)` (`tests/support/waiting.py`; a cancelled run comes back in its outcome — pass `propagate_inner_cancel=True` only when that cancel is the expected signal): model call counts mark request START, and final frontend events may precede persistence.
- Everything a test starts — task, thread, worker, timer, signal subscription, subprocess — has an owner and deterministic teardown; never go green by globally quiescing or detaching the production path under test. Prove a child was reaped with a `psutil.Process` captured while alive (`not proc.is_running()`), never `pid_exists`.
- Keep ≥1 engine-driven test per kernel↔middleware contract (tool-loop reminder enrichment, profile switch); porting one to direct middleware calls under the same name deletes coverage.

### Textual
- The autouse `_settled_pilot_waits` (`tests/support/pilot_barrier.py`, Textual 8.2.7 only) makes `pause`/`press`/`click` drain handler-posted messages. Workers, tasks, timers and update-timer layout are not messages: `wait_for` the asserted state (after `push_screen`, wait for `isinstance(app.screen, X) and app.screen.is_mounted`). Click with `tests/support/tui_helpers.py::click_when_settled` (Pilot reads pre-reflow geometry) and resize with `resize_when_settled` (resize is debounced).
- Arm no-layout/no-restyle spies only after `screen_is_settled(app, screen)`, not `_layout_required`. Performance regressions need a real `run_test()` (`tests/support/tui_app_harness.py::make_chrys_app`) with a populated transcript and real events; spies prove MainScreen `update_node_styles`/`_refresh_layout` and Footer recompose are not called (example: `tests/app/tui/screens/test_editor_dialog.py::test_populated_main_screen_editor_overlay_does_not_restyle_recompose_or_relayout`). Handler-direct unit tests don't count.
- Handler plans are cached per class on first dispatch and reset only between tests: patch a handler through a fresh local subclass before dispatch (instance spies are bypassed), and pair negative handler assertions with a positive control.
- `Static.render()` returns a Visual: use `rich_plain`/`rich_segment_lines`. Under `run_test()` stdout looks like a tty, so assertion consoles need `Console(force_terminal=False, _environ={})`; `rstrip()` style-padded cell text before `(text, style)` compares. Windows CI detects 256 colors: pin `app.console._color_system` in color assertions (`TEXTUAL_COLOR_SYSTEM=256` reproduces). `Input` selects all on focus: set the selection explicitly in typing tests.
- Harness Apps outside `tests/app/tui` need `TuiVariableDefaultsMixin` (`app/tui/theme.py`); a harness overriding theme variable defaults merges the mixin's, never replaces them. For recoverable workers use `exit_on_error=False` and own `worker.wait()` errors (a default worker failure exits the App).

### Isolation (installed by `tests/conftest.py` — don't redo or undo it)
- Every test starts in its own empty cwd (reach repo files via `__file__`); the session root is always per-test temp, and so is the config/data dir unless `@pytest.mark.real_config_dir`; exported Chrys setting env vars are stripped; the locale is English. A test that spawns a subprocess must also point `HOME`/`USERPROFILE`/`APPDATA` at temp, or the child writes the real `~/.chrys`.
- Env via `monkeypatch.setenv`/`monkeypatch.context()`, never raw `os.environ[...]` writes (runtime guard) or mid-test `.undo()` on the shared fixture. `delenv` on an absent var records nothing: `setenv` it first so teardown removes whatever the code under test sets. Outside fixture lifetime, own a `pytest.MonkeyPatch()` and undo it in teardown. When a constant or helper moves modules, re-point every `monkeypatch.setattr(old_module, ...)` (if the old module still re-exports the name, patching it there silently does nothing).
- Non-loopback egress fails at runtime unless `@pytest.mark.integration` (a tripwire: subprocesses, reverse DNS and Windows proactor connects are not caught). `tests/integration/` holds OFFLINE cross-layer tests and is never marked integration.
- Git: `git_repo_factory` (hand-rolled repos race `git maintenance`). Servers bind port 0 and hand over the listening socket or a polled port file; a stopped-server test keeps a bound, non-listening socket; never probe a free port and reconnect.
- Plant files the product opens owner-verified with `tests/support/secure_files.py` (`Path.write_bytes` on an elevated Windows runner makes Administrators the owner). Probe filesystem semantics (case, symlinks via `symlink_or_skip`, separators, newlines) instead of assuming them, and decide whether a path value is raw filesystem identity, Git POSIX path, serialized identity or display text before comparing.
- A root fixture widens `RUN_RECORD_WRITE_ACK_TIMEOUT_SECONDS` (CI disks stall under fsync pressure); tests of that bound pass `write_ack_timeout=` to `WorkflowRunStore.open`.
- xdist: parametrize values and ids must be identical on every worker (no pid, random, time or set order). Ruff ASYNC covers tests: run blocking setup through `asyncio.to_thread`.

### Evidence
- Flake fix = the causal mechanism plus a deterministic reproducer (scheduling or fault injection) that fails before and passes after; without a seam, record platform, worker topology, seed and stress runs (oversubscribed xdist — more workers than cores — reproduces CI-load races). Scan and report same-shape sites. CI prints a stall report for failed or ≥25 s tests (`CHRYS_TEST_STALL_DIAGNOSTICS=1` locally) — read it first.
- `@pytest.mark.quarantine(reason="<owner/issue>: <failure signature>", expires="YYYY-MM-DD")` only for confirmed flakes, never repeated deterministic failures (reason and expiry are AST-checked, since deselected tests never reach setup, and re-checked at runtime); it is a non-strict xfail that hides new failure modes, so review its results.
- Doubles: `autospec`, a typed Protocol or an explicit signature; no catch-all `**kwargs`. When merging fakes or parametrizing, keep absent attributes and omitted args absent and comparisons exact (`is True`, whole dict): the absence is what's tested.
- A symbol grep or a green helper test is not coverage: trace the production path and test the boundary the data actually crosses. Fix an invariant as a class — enumerate every site that writes the protected state, not only the reported one. Mutation proofs use scoped in-memory patches or isolated checkouts, never whole-file restores over concurrent edits.
- Check trajectory files with the `tests/support/trajectory_invariants.py` helpers (direct `verify_accounted_prefix` is AST-banned).
