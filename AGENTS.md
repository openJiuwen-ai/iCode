# AGENTS.md

<!-- AIxCoding branding: development entry facts -->
Chrys is a Python 3.14+ agent platform: Textual TUI, headless CLI and ACP server. Users see it as **AIxCoding** / `aixcoding-cli` (`foundation/branding.py`; `msg()` fallbacks write `{app}`, bound with `app=APP_DISPLAY_NAME`); the PyPI distribution is **iCode-TUI** (`__init__.py::DISTRIBUTION_NAME`, wheel `icode_tui-*.whl`), whose only command is `aixcoding-cli`; the import package, `~/.chrys`, `CHRYS_*`, wire/header names and data keys keep `chrys`. `pyproject.toml` is the source of truth for version and deps. Paths are under `src/chrys/` unless they start with `tests/`, `scripts/`, `docs/`, `locales/`, `.github/` or name a root file; a bare file name continues the directory named just before it.

## AIxCoding customization

All customization work in this fork — everything under `src/chrys/*/aixcoding/` (tier placement, ADR-0011) and `aixcoding/` — is
governed by `aixcoding/docs/standards/DEVELOPMENT.md` (hard rules + the human-AI workflow).
Read it (and `DIRECTORY.md`) before adding or changing anything beyond pure upstream files —
and before reviewing any diff or PR. AI agents must stop and ask for approval before editing any upstream
file (R2) or adding a third-party dependency (R11). Customization points are registered point-level
in each batch's design.md and reconciled by `uv run python aixcoding/tools/gen_customizations.py`
(`--strict` is the CI gate; `--report` prints the live registry view — ADR-0015).

AI agent conduct (ADR-0012; full protocol in DEVELOPMENT.md §4.2 and §6):

- Before starting any task outside the pre-defined exemption-free list (living-doc appends,
  read-only operations, implementation work already covered by a signed design), present an
  opening assessment — situation + recommendation with rationale + all path options — and STOP
  for the owner's decision; the owner may overturn any of the AI's judgments. The AI never
  self-approves a pipeline exemption and never classifies a task into the list on its own.
- Chat acknowledgment is discussion feedback, not approval; the only signal to start
  implementing is a signed-off design.md.
- Git write operations are authorized one by one: after each command the AI stops and reports,
  waiting for the next explicit instruction.
- Upstream upgrades (merging new iCode releases) follow
  `aixcoding/docs/standards/UPGRADE-RUNBOOK.md`; read it before starting any upgrade.

## Verification, gates & commits
- Smart Test `--paths` = only the files this task changed, including deleted paths and both sides of a rename (without `--paths` it takes every branch and dirty-tree change); don't hand-compute the affected scope. Read its closing `Summary:` block (exit code, each suite's counts), not a `tail`: in `a && gate | tail` the exit status is tail's.
- Smart Test is a local optimization only: its pass is never a full-suite pass, so say which suite ran. CI/CD keeps its direct complete PR gates and must never use Smart Test to select or skip tests.
- A test that reads repo files without importing them (subprocess fixture, file scan) needs a `REGULAR_RULES`/`ARCHITECTURE_RULES` watch in `scripts/chrys_test.py`, or Smart Test may never select it.
- Ruff, format, ty, i18n and `uv build` are separate gates; packaging changes also run `uv run python scripts/check_wheel.py dist/icode_tui-*.whl` (installs and probes the wheel as PyPI users get it). Python-3.9 workflow-worker cases skip without a 3.9 interpreter (`CHRYS_PY39_INTERPRETER`, PATH or Homebrew keg); Linux/Windows CI runs them.
- CI (`.github/workflows/ci.yml`) runs `-m "not integration and not gc_calibration"` on Linux, macOS and Windows, `tests/architecture` on Linux only: decorate OS-independent whole-repo scans elsewhere with `@CI_LINUX_ONLY` (`tests/support/ci.py`).
- Refresh generated artifacts in the same change: i18n catalogs (see i18n), the builtin workflow manifests and `tests/architecture/trajectory_wait_manifest.json` (their guards print the command). A wait-manifest refresh lists every wait it reopened (new, edited, or in a function whose wait count changed) with the rule it had, if any, and resets each to its default rule (fail-closed `unresolved` unless a `sleep(0)` yield): review each one, re-applying a listed rule where it still fits — CI passes `unresolved` rows.
- User-visible change → update the affected `docs/en/` and `docs/zh-Hans/` pages in the same change (see User guide).
- Other agents may be editing this tree: run both ruff commands yourself, stage explicit paths (never `git add -A`) and commit with `--no-verify` (pre-commit stashes unstaged edits and can lose theirs). Undo a probe with an inverse edit, never `git checkout -- <file>`/`git restore`, `git stash` or a whole-file snapshot restore (each wipes others' unstaged edits); to run HEAD, `git archive HEAD src/chrys | tar -x -C <scratch>` + `PYTHONPATH`.

## Supply chain & version pinning
Pin third-party code to immutable ids so every bump is a reviewed diff; never loosen a pin to unblock something.
- **Actions** (guard `tests/architecture/test_workflow_action_pins.py`): a selector-branch action (`dtolnay/rust-toolchain@stable`, `taiki-e/install-action@cross`) defaults an input to its ref name; once SHA-pinned, pass it explicitly (`toolchain: stable`, `tool: cross`) or `cd.yml`'s build-binaries job fails.
- **Python**: `[project]` deps use exact `==` (wheel installs re-resolve ranges; our lock doesn't apply there); only the in-file-commented exceptions take ranges. The Linux offline binaries' `pillow` comes from `.github/workflows/pillow-manylinux2014.yml`, whose publish run tags GitHub only: create the same tag on GitCode right after, or the GitCode→GitHub sync deletes it and the release's wheels 404 (recovery in the workflow's header).
- **Interpreter**: `.python-version` pins the full CPython version for uv, CI and the release binaries (guard `tests/architecture/test_python_pin.py`). The binaries take it from the python-build-standalone release `PYTHON_BUILD_STANDALONE_RELEASE` in `cd.yml` (mirrored in `scripts/build.sh`/`build.ps1`), not PyApp's default: bump that release with the version, to one carrying it for every CD target.
- `uv.lock` pins and hashes the whole closure: commit it with any dep change and check with `uv lock --check` (PR CI's `uv sync` re-resolves drift silently; only the offline-dist `uv export --locked` fails).
- Bump paired pins together: Ruff in `pyproject.toml` and `.pre-commit-config.yaml` (`rev:`); `babel` in `[build-system].requires` and the dev group. Version bump: `pyproject.toml` → `uv sync` (rewrites chrys's own version in `uv.lock`; commit both) → full i18n pipeline (stamps the installed `__version__` into `Project-Id-Version`).

## Architecture & control flow
- **Bootstrap**: every runtime entrypoint (not `serve`/`install`/`uninstall`) calls `orchestration/startup.py::bootstrap_runtime()` (guard `tests/architecture/test_entrypoint_bootstrap.py`); never duplicate its steps. Production reads settings via `load_settings()`, never the `Settings.from_env()` compat shim.
- **CLI**: `app/cli/app.py::main` dispatches by hand on `argv[0]` (unmatched → TUI). Noun commands are singular, with plurals mapped in `_PLURAL_ALIASES`; a listing group given no subcommand runs `list` (an optional action defaulting to `list`, or `app/parsing.py::default_to_list` for subparser groups).
- **EventBus** (`foundation/events/bus.py`), the only frontend↔backend channel: `publish()` awaits `subscribe()` handlers inline (exact-type match; never fire-and-forget) and logs and swallows their errors unless `raise_handler_errors=True`; `stream(*types)` matches by isinstance and sees only events published after its `async with` is entered.
- **AgentEngine** (`orchestration/engine/engine.py`) is built only by `orchestration/engine/assembly.py::assemble_agent_engine`. Every rebuild replaces `engine.current.loaded` (None after shutdown): call `current.require_loaded()` per use, never hold it across an `await`.
- **Invoker** (`orchestration/invoker/`): one contract, `contracts.py::InvocationConversation.run(RunRequest) → Ok | Failed | Aborted`; two backends, `kernel.py::KernelConversation` and `acp.py::AcpConversation`; three caller shells: the main turn (`orchestration/engine/run/`), `orchestration/sub_agents/shell.py::SubAgentToolShell`, `orchestration/workflows/agent_node.py::WorkflowAgentShell`. Backends never validate structured output; that is caller policy.
- **Three build paths** — main `orchestration/engine/build/builder.py::build_agent`, sub-agent `orchestration/sub_agents/tools.py`, workflow node `orchestration/workflows/agent_node_build.py::build_kernel_node`. Tool, MCP, skill, memory, web, start-hook and extension (tools, contexts, tool hooks) wiring must land in all three. Local tools come only from `service/tools/packs.py` (`assemble_tools`, then `assemble_extensions`; order and name-clash rules in its docstrings; tests stub the packs with `tests/support/tool_packs.py::install_tools`). A pack's `create` takes the host objects its tools need from `ToolBuild`, and the tool does its own work (`todo_write` validates, replaces and publishes) — never a function middleware that intercepts a tool by kind.
- **ExecutionLease** (`orchestration/engine/execution.py`) owns a turn's run task from admission to final save; a workflow run holds it exclusively, refusing turn admission and rebuilds (see its docstring).
- **Turn pass** (`orchestration/engine/run/`): replace backend history only via `KernelConversation.history_state = …` or `restore()`, which invalidate continuation tickets (a retry reuses a `Failed` pass's ticket only while `continuation_is_live()`, else continues from history). Admission errors fail the turn through normal finalize/save/release and never replay.
- **Retry lanes** (N = effective `CHRYS_MAX_TRANSIENT_RETRIES`: 10 interactive / 18 headless, max 50; backoff 3/7/15/30/60/120/240/600 s, capped at 600; commit-point rules under LLM wire & retry):
  - main turn, local storage: the kernel `WireRetryPolicy` retries each wire call in place; after stream-stall exhaustion the same `agent.run()` falls back to a non-streaming request with a fresh N; a context overflow (see Compaction) and a response that showed nothing (see Response validation) each add one resend outside N and the stall budget — up to 3N+4 provider calls per logical call.
  - main turn, service-side storage: no wire policy; `AttemptRunner` runs the whole-run `StreamRetryLoop`, and only on stall exhaustion ONE non-streaming `agent.run()` attempt with no new budget (its tool loop may still make several provider calls). Whole-run semantics own this path — don't add a wire lane.
  - sub-agents raise on stall exhaustion (no non-streaming fallback) into the shell's pause/abort path. Kernel workflow nodes take the main turn's lanes; how the scheduler's next attempt resumes is in `orchestration/workflows/agent_node.py`.
  - every lane: an Anthropic thinking-binding refusal is resent once inside the adapter without the replayed thinking (not under `prefix_mismatch_behavior: error`; `service/llm/anthropic_messages/client.py::_create`), outside N and with no retry event, so each provider call the lanes count can be two requests.
  - every lane: once a pass has shown answer text, nothing sends it again (reasoning may stream again) — wire retry, stall fallback, overflow and blank resends (the kernel's `delivered_text` veto, or `WireRetryPolicy.answer_shown`) and whole-run retry (`ContentProjector.exposed`) all stop; the shown text is kept and the error reported. Text counts as shown only where a frontend shows it: a main turn's on TUI and ACP but not `icode run`, which holds it (`TurnBindings(shows_answer_text=)`); a kernel sub-agent's only in TUI chat, and only once its segment completes (`SubAgentTools(shows_answer_text=)`, `shows_whole_segments`); a workflow node's own text on every surface. A workflow node's next attempt is no resend (its own origin): a resumed kernel attempt asks again for the trailing answer (`ChildHistory.retry_input`; see History).
- **Sub-agent shell**: `SubAgentToolShell` is the child's sole `OperationBinding` and the only pause/Retry/Abort loop, free of ACP protocol code; `KernelSubAgentPolicy`/`AcpSubAgentPolicy` add only result, audit and cancel policy. Pending records are removed only after the parent save succeeds. With `human_failure_decisions=False` (headless chat, an ACP client that didn't declare `clientCapabilities._meta.chrys.subAgentPause`, every workflow node) a failed child ends at once, returning `Error: sub-agent 'X' failed — …` to the caller's model; only TUI chat and declaring ACP clients pause for the Retry/Abort card (`pause_failed_sub_agents`, fixed per session). Kernel children return only the text after their last tool/hosted output (`service/agent_middleware/events/hosted_tools.py::FinalSegment.of`; all text if that is empty) — a settled decision; don't return `response.text`.
- **Invocation events**: execution/presentation facts are immutable `Invocation*` events with a required `InvocationOrigin` (`foundation/models/invocations.py`: kind plus parent chain; a workflow node's `attempt` counts for equality, so admission and tickets compare with `same_invocation`). Bind a `BoundEmitter` (`orchestration/invoker/origin.py`) before the first `await`; never derive origin from ambient context. Chat/ACP/headless consumers skip workflow traffic by `origin.root.kind == "workflow_node"` (ACP and headless also skip `side_question`).
- **Model text** reaches frontends only as `InvocationContentDelta`/`InvocationContentFinished` (`answer | reasoning | reasoning_summary` channels, keyed by `segment_id`), published by the caller's per-pass `orchestration/invoker/content_projection.py::ContentProjector` (its docstring: landing order, hosted cards, retry boundaries); external ACP agents feed it through `AcpUpdateTranslator`. `InvocationContentAbandoned` names a given-up response's segments: `icode run` progress drops their held text, the TUI main chat removes their thinking. The final `InvocationMessage(is_final=True)` is a completion snapshot frontends never append. The TUI main chat streams answer and readable reasoning; nested views (sub-agent cards and details, workflow node transcripts) show each answer segment whole once it completes (`AnswerSegments`); the ACP server maps answer → `agent_message_chunk`, reasoning and summaries → `agent_thought_chunk`.
- **ChrysSessionHost** (`orchestration/session_host.py`): one bus + engine + session per `icode run`, `icode workflow run` or ACP session. Headless runs `ApprovalMode.BYPASS` with `allow_user_interaction=False` (no `ask_user`; a stray `QuestionToUser` fails fast); ACP passes True. Headless/ACP streams forward only `_HEADLESS_RUN_EVENT_TYPES` events carrying a `session_id`: register a new turn event there and publish it with `session_id=`, or only the TUI sees it.
- **ACP server** (`app/acp/server.py`; non-standard caps via `ext_method`; spec and gaps in `app/acp/doc/frontend-api.md`): stdout is JSON-RPC only, logs go to stderr (`app/cli/acp.py::_configure_logging`). ACP applies no ask-user timeout unless `--ask-user-timeout`. Client-supplied MCP servers: HTTP only, headers literal (never resolve `{{ENV_VAR}}`).
- **Subprocesses**: every non-interactive subprocess sets stdin explicitly (guard `tests/architecture/test_hygiene_subprocess_stdin.py`), since ACP's stdin is the JSON-RPC pipe: `stdin=DEVNULL`, or `PIPE`/`input=` only for a child that reads it (the workflow worker host). Spawn through `foundation/platform/process.py` (`managed_subprocess`, `spawn_managed_stdio_process`; sync `subprocess.run`: `**windows_hidden_subprocess_kwargs()`); never `CREATE_NO_WINDOW` on Windows: the child shares, and can reset, the TUI's console.

```

orchestration → {service, kernel, foundation}
service → {kernel, foundation}      # includes the src/chrys/workflows.py facade
```

## Conventions
- File header: `# Copyright (c) Huawei Technologies Co., Ltd. 2026. All rights reserved.`, a blank line, then the module docstring. Builtin workflow templates users copy (`service/workflows/builtins/<name>.py`) open with a one-line `#` description instead.
- `from __future__ import annotations`.
- Async-first on event/engine/invoker/tool/host paths; `asyncio.get_running_loop()`, never `get_event_loop()`. Cancel-safe closes go through `foundation/util/once_close.py` (`OnceClose`, `finish_close`).
- No `getattr`/`hasattr` on first-party types — add a typed field or Protocol (getattr only at SDK/external boundaries). Some existing `getattr(x, "a", default)` defaults hold up test doubles that lack the attribute: give the double a real field before converting.
- No `assert` in `src/` (AST-guarded); replace one with a raising check or typed accessor, never a `cast`, an ignore comment or a silent return.
- **Tools**: params are `Annotated[T, "description"]` (drives the schema) with `T` importable at runtime, not only under `TYPE_CHECKING`, or schema generation raises. Failures `return tool_error("<error_kind>", message)` (`service/tools/result_metadata.py`): it adds the `Error: ` prefix the UI keys on plus the failure metadata the loop, persistence and ACP read. A raised exception shows the model only `Error: Function failed.`; to show text, raise `kernel/exceptions.py::ModelVisibleToolError` (its docstring says which text is safe). Kinds are `foundation/tool_kinds.py::TOOL_KINDS` plus `extension.<id>` (kind validators accept it via `is_extension_kind`); set and read them with `set_tool_kind`/`get_tool_kind`, never `FunctionTool.kind` (stays None). Fuzzy path correction (`foundation/platform/paths.py::resolve_existing_path`) is for read-only tools; write/edit use the exact path given. Import the shell-filter API from `service/tools/builtins/shell_filter.py`, never the `shell_command_filtering/` package.
- Pillow decodes only the formats each caller names (guard `tests/architecture/test_hygiene_pillow_formats.py`), but the guard can't see libraries that call Pillow themselves: narrow those too (pypdf via `service/tools/builtins/doc_converter/parsers/pdf.py::_restrict_pypdf_image_decoders`; the XLSX parser skips chart sheets, whose pictures openpyxl decodes).
- `except A, B:` is valid 3.14 syntax (ruff format writes it) — don't "fix" it. `TimeoutError` (what `foundation/util/lock.py` raises) is an `OSError`: put `except TimeoutError` before `except OSError`. Pass `encoding="utf-8"` to `open`/`read_text`/`write_text` (Windows defaults to the locale code page).
- Comments state the invariant, never this repo's issue/PR numbers. Write visible Unicode literally (`→`); keep `\uXXXX` for invisible/confusable characters and lone surrogates.

### Cross-platform
- Branch behavior on `foundation.platform.get_platform()`. Use raw `sys.platform == "win32"` (the check ty narrows) or `posix_os = cast(Any, os)` only to reach platform-only APIs.
- Every module must import on Windows: POSIX-only names (`fcntl`, `SIGKILL`, `os.killpg`) stay behind a `sys.platform` guard or inside functions.
- Windows: never wait on a handle from an executor thread (`run_in_executor`/`to_thread` + `WaitFor*`): the waits fill the small default pool and block the loop. Use `loop._proactor.wait_for_handle(handle)` (IOCP), as `foundation/patches/textual_win_sleep.py` (cancel/close protocol in its docstring) and `foundation/platform/process.py` do. Never close a handle under a registered wait; bound every post-cancel settle wait, or `Runner.close()` wedges. Tests never give a real proactor a made-up handle (fatal `0xC000070A` kills the xdist worker silently): stub the module's `get_running_loop` via a shadow `ModuleType`.

### i18n
- Localize user-facing display prose only. Model/tool/protocol/MCP text (including `Error: ` results), persisted marker literals, logs/traces, debug surfaces, ACP output and CLI entry-point output stay English.
- Define `NAME = msg("area.dotted_key", fallback="Exact English text")` at module level after `from chrys.foundation.i18n import msg` (AST-guarded; `msg()` validates key, `{slot}`s and markup at import); a plural adds `plural_fallback=` and binds `count=`.
- TUI: render through `app/tui/i18n.py` (`render_text`/`render_content`/`render_str`); live chrome implements `refresh_localization()` and registers with `locale_controller.register_surface()`; `Content.from_markup` templates take prose only through `$name` substitutions.
- After adding, changing, removing or moving a `msg()` (the POT records its file, not line): `scripts/i18n.py extract` → `update` → translate every new or `#, fuzzy` entry in `locales/zh-Hans/LC_MESSAGES/chrys.po` and drop the flag → `check`. A second run must leave `git status` unchanged. Never run it concurrently with pytest.
- The runtime MO (`foundation/i18n/_catalogs/zh-Hans/LC_MESSAGES/chrys.mo`) is generated from the PO and gitignored: never commit it. `uv run` rebuilds it when the PO changes; `scripts/i18n.py compile` refreshes it by hand (e.g. after `git clean`).
- `tests/foundation/i18n/test_catalog_oracle.py` pins the id set and requires every entry translated: add/remove ids in `_catalog_oracle_ids.py` or its per-area `_<area>_catalog_oracle_ids.py` sibling (a new area gets a new sibling) in the same commit.

## Subsystems quick-ref
- **Settings** (`foundation/config/`; precedence in `spec.py::Source`, fields in `settings.py`): the settings panel writes only `<config_dir>/settings.yaml`; env is snapshotted at bootstrap (later `os.environ` writes are ignored); `.env` files are never loaded or migrated. These repo sources load only when the user's own switch is on (default off; a project can't set it): `.chrys/settings.yaml` (`project.config_enabled`; then only keys whose `ProjectMerge` allows it, default DENY), `.chrys/hooks/` (`project.hooks_enabled`), `<cwd>/.agents/skills` (`project.skills_enabled`). Re-loads compare against `SettingsHandle.base`, and rebuilds stage `base` plus the session's own model and live choices (`AgentLoader.stage`), never `loaded`, which would fold those into the next load. `CHRYS_DEBUG_LLM_RAW_HTTP_LOG=1` captures raw provider HTTP (`service/llm/raw_http_log.py`).
- **Profiles**: builtins in `service/profiles/agents/builtins/`; a user `<config_dir>/agents/<Name>.yaml` shadows one. The profile dir is caseless on macOS/Windows: where file ownership matters (ACP profile mutations) compare the stored `name:` (`service/profiles/agents/serializer.py::stored_profile_name`), not paths.
- **ACP sub-agents**: only spawn/initialize failures auto-retry; failures from `session/new` on pause with `reason="acp_transport"` where pausing is on (else end at once). Audit/pending artifacts are owner-only; argv values are redacted, the full argv kept only as a keyed HMAC.
- **Approval** (`service/approval/policy.py`; resolution order in the `ApprovalPolicy` docstring): `ApprovalRule` (`auto | require | skip`) is one tool's rule; `ApprovalMode` (manual / auto = LLM judge / bypass) covers a launch. The mode lives only in `ActiveSession` (`orchestration/engine/state/active_session.py`) — never in session files, workflow checkpoints or drafts — survives `/new` and restore, and is shared by chat and workflows.
- **LLM** (`service/llm/`, `service/profiles/models/`): a wire-style variant is an `api_style` (`chat_completions | responses`), never a new provider id; within a wire protocol, endpoint differences are fields of its `ChatCompletionsVariant`/`ResponsesVariant`, never a subclass overriding codec methods. Responses wire shape → `schema.py::is_responses_wire_dialect`; service-side continuation → `provider == "openai"` only; never conflate them. Build request options only via `options.py::effective_chat_options` (Responses defaults to `store: false`: service-side is opt-in). `service_session_id` is reused only under effective service-side storage with matching fingerprints/workspace, and cleared on retry, interrupt and incompatible restore (local history stays authoritative). A client whose endpoint keeps no conversation state sets the `FORCES_STATELESS` ClassVar (Chat Completions, Anthropic Messages, DeepSeek Responses): the kernel's storage veto reads it, never a variant's `stateless`. The codecs' provider-compatibility repairs (tool-call canonicalization, millisecond `created`, unsigned-thinking drop, Anthropic cache-token fold) are load-bearing: remove one only after a test proves its case can no longer occur.
- **Web tools**: a web config error drops only the web tools (`web_tools_unavailable` warning), never the agent. All web egress goes through `service/tools/builtins/web/http.py` (IP-pinned; proxy rules in its docstring).
- **Hooks** (external subprocesses; spec in `service/hooks/docs/`): only `before_tool_call` and `user_prompt_submit` hooks may block or ask the user, only `before_tool_call` rewrites args, and none grants or bypasses tool approval. Slow session switch/restore: check hooks first — in the session's `trajectory/events.jsonl`, join `hook.operation.finished` `duration_ms` to its `hook.operation.started` `hook_key` by `operation_id` and sum.
- **MCP** (profile `tools.mcp`, stdio | http): agents with the same effective config share one connection (`service/mcp/cache.py`) with per-consumer tool clones and per-run progressive-disclosure state and result caps; a field that changes the connection belongs in the cache key.
- **Compaction** (`service/context/compaction/`; trigger in `budgets.py`): a strict provider overflow (`is_context_overflow`; never 413 or a 5xx) that is no thinking-binding refusal goes to the strategy (`kernel/compaction.py::ContextOverflowSink`) before any retry decision. Unless compaction is off or the failure is compaction's own last-words call, `note_context_overflow` notes it, so the next pass compacts even below the trigger, and returns whether a resend can help: not when the provider names a window smaller than the strategy's (main-turn and sub-agent failures then pass `max_context_tokens=` to `display_fields`, which says what to set). If it can, a run with a wire policy resends once per logical call in place (`RetryMode.CONTEXT_OVERFLOW`), compacting first, unless a continuation token is live or hosted work blocks replay; a second overflow is terminal. An `OUTPUT_TRUNCATED` verdict with no reasoning tokens only sets the note (still terminal).
- **Mutations**: the shell git-calibration scope is command cwd ∪ `workspace.primary_cwd`, deliberately not clamped to the workspace (monorepo commands run from the root).
- **User guide** (F8 or `/help`; `app/tui/screens/guides/`): reads `docs/index.yaml` + `docs/<locale>/` at runtime. A page must be listed in `index.yaml`; say iCode/`icode` (internal names stay); `#anchors` are GitHub heading slugs. Write for users, in plain words: what to do and what they will see; leave out implementation details they don't need.
- **`icode serve`** keeps `Referrer-Policy: same-origin`: with `no-referrer`, browsers send `Origin: null` and form POSTs fail the origin check.

## Invariants & gotchas
### Transcript & identity
- **System reminders** (`service/agent_middleware/system_reminder.py`; its module docstring specifies what is sent when, the source/core split and escaping): per-turn context rides trailing `<system-reminder>` blocks on user messages of the per-call copy, never the system prompt or a message's own contents. A user message records what its established request carried (`HistoryMarkerKind.SYSTEM_REMINDERS_KEY`) and every later call re-renders it byte-identically, so the cached prefix survives: code that rebuilds a user message carries the record (`copy_reminder_record`), and reminder text never varies per call (no timestamps; only LAST_WORDS is dynamic and unrecorded).
- **Ids are not identity**: `call_id`s recur across exchanges, and `message_id` (`msg_N`) is positional and can repeat one in an archived `compressed_msgs` block. Occurrence identity is `_chrys_analytics_item_id` (`foundation/trajectory/metadata.py`), copied verbatim by every copy — never re-mint it. Before deduping or joining on any id, read its generator's uniqueness scope; sub-agent audit replay follows the contract in the header of `service/session/sub_agent_transcript.py`.
- **Final response = the kernel loop's assembled Messages** (`kernel/loop.py::_LoopRun.finalize_stream`). Never re-merge content downstream with `from_updates`: it mints new Contents and drops the kernel's stamps (invocation order, tool kind/context, result metadata). Mid-stream consumers see fragments: anchor side effects by role + call_ids + content signature, never identity alone.
- **Invocation order**: only the kernel loop stamps `_chrys_tool_invocation_order` (`foundation/tool_invocation_order.py`). Never count calls to rebuild order or re-attach result metadata by position: consumers read the stamp and fail closed without it; result metadata rides `FunctionInvocationContext.metadata` and is folded into the result at construction.
- **Exchange grammar** (spec: `kernel/exchanges.py` header): pair calls↔results only through `iter_exchanges`/`pair_results`, never a global call_id scan; completeness reads `answered_keys` (one result answers every same-id call), never occurrence counts. Reuse `TOOL_CALL_CONTENT_TYPES`/`TOOL_RESULT_CONTENT_TYPES`.
- **Share Content objects, copy only wrappers** — shared content identity is the only stable state↔wire link:
  - Outgoing messages are `kernel/client.py::_wire_message_view`s and landed ones `kernel/_loop_recorder.py::_message_snapshot` copies. Never share a Message wrapper loop↔client or rebuild Contents on a path matched back to state. Every wire→state matcher needs a content-identity tier (injection/exclusion anchors, compaction's `_state_correspondence` — without it prior-turn compaction silently disables).
  - Echo removal (`kernel/loop.py`) drops Content objects the conversation already holds, by identity only: a new Content reusing an old call_id is fresh work.
  - id()-keyed memos that outlive a call hold weak identities (`kernel/identity.py::WeakIdentityRegistry` or `weakref.ref`) so a recycled id never false-matches. A new copy site gets a fresh-vs-shared pin in `tests/architecture/test_copy_freshness.py`.
- **Transcript oracle** (`tests/support/transcript_invariants.py`): a firing invariant means the loop broke — never switch to the raw `ToolLoopLayer` or loosen an assertion; a real contract change updates the oracle and its red-path pins (`tests/kernel/test_transcript_invariants.py`) together.

### LLM wire & retry
- **Error classification** (`foundation/errors/`): provider and network errors are judged only by `classify_error` (kind, retryable) and the predicates built on it (`is_retryable`, `context_overflow_limit`, …) — never a hand-rolled chain walk or phrase table elsewhere. A new rule reads only `_walk.py::iter_explicit_graph`, never `__context__` (it may hold a stale earlier failure); only the frozen legacy layers in `_legacy.py` read the full chain. DNS name-not-found is retried only when its first hop (proxy, else target) answered earlier in this process (`service/llm/route_facts.py`). A test that needs a direct route sets `NO_PROXY=*` (`direct_route` fixture): with no proxy env at all, httpx falls back to the macOS/Windows system proxy.
- **Retry commit points**: every ANSWERED result slot — arg-invalid, unknown-tool and failed results included, synthetic interrupted fills excluded — is an irrevocable commit; whole-run retry never replays a committed call. Hosted calls bypass the loop recorder, so `ResponseValidationMiddleware` records them; an adapter that fails a response after the provider ran hosted work hands that work over as `ProviderResponseError.observed_contents`, which wire clients re-raise unwrapped. No lane (wire, whole-run) re-sends a request after blocking hosted work unless a live continuation token makes it a poll. Blocking follows `foundation/hosted_tools.py::HostedRetrySafety` (the adapter's value, else its family default, else UNKNOWN): SIDE_EFFECTFUL/UNKNOWN block, READ_ONLY/SANDBOXED don't.
- **Storage mode** (`kernel/client.py::resolve_storage_mode_and_handles`; precedence rules in its docstring): every caller passes `force_stateless=client.FORCES_STATELESS`, which vetoes service-side.
- **Response validation** (`service/agent_middleware/response_validation.py`; its module docstring specifies the verdicts, the exhaustion-tail exception and the chain position) is terminal-only: a rejected response fails the pass and is never sampled again; only a response that showed nothing (`is_blank_response`) is resent, once per logical call in place, by a run with a wire policy (`RetryMode.VALIDATION`). Every `KernelConversation` build path lists `begin_pass_hosted_baseline` in its start hooks.
- **Chat Completions reasoning** (`service/llm/chat_completions/reasoning.py`; replay and wire-ordering rules in its and `history.py`'s docstrings): replay is per reasoning format, never per provider (Kimi runs on plain `openai`) — each captured value replays only under the field it came from, and a `ChatCompletionsVariant` only narrows when replay happens. A new `protected_data` writer must audit every consumer (chat_completions, openai_responses, anthropic_messages).

### Runtime state
- **Workspace cwd**: resolve relative paths (approvals, hooks, MCP cache keys, mutations, events) from `SessionEnvironment.cwd`/`Workspace.primary_cwd`, never the process cwd, and pass it explicitly: hooks, the MCP cache, the mutation detector and `SessionEnvironment.capture()` silently fall back to `os.getcwd()` when given none.
- **Surrogateescaped paths (POSIX)**: filesystem-derived paths may hold lone `\udcXX`, and only the raw `str` round-trips to the real bytes: keep it raw in `SessionEnvironment`, `Workspace`, session metadata, restore state, in-process events and subprocess `cwd`. `foundation/platform/files.py::surrogate_safe_text` names a DIFFERENT path: apply it only to a derived output copy (its docstring has the identity-key and write-sink rules).
- **History**: new marker/trim/repair/metadata operations on `chrys_history` go into `service/session/history.py::SessionHistoryManager`, not call sites. It is not the only writer — the history provider, child histories (`orchestration/invoker/child_history.py`), turn resume/retry restore, and whole-state swaps (session restore, rebuild, fresh workflow passes) write too — so a history invariant must hold on all of them. A failed or interrupted turn keeps the answer text it showed (trim keeps it; the finalizer adds what history lacks via `keep_partial_answer`); a Continue (bare or with a note) and a steer drop that trailing answer (`remove_trailing_answer`; exchange work stays), since no request may end with assistant text: a bare Continue asks for it again, a note or steer goes on from the user's message. Frontends drop exactly what history dropped: the drop returns the answer's stamped segment ids (`ANSWER_SEGMENT_KEY`, never on the wire), its owner (main runner, sub-agent shell, workflow node) publishes `InvocationAnswerWithdrawn` through `finish_close`, and the TUI, nested journals and ACP (`chrys/messages_retracted`) remove those segments, live or replayed.
- **Persisted state**: a new provider-state key must join a key table in `service/state/serializers.py` (`_PASS_THROUGH_NULLABLE_KEYS` saves all but None, the others only truthy values), or save drops it silently. Old sessions must keep loading and resuming: fixes apply to newly written data, never backfill old records, and compatibility shims stay narrow and read-only.
- **Turn boundaries**: resolve turns only via `foundation/models/turns.py` (`opens_turn`, `turn_slices`, `current_turn_start`, …), never raw `role == "user"` or `"continue"` text. A user message added mid-turn carries `_injected` (set at creation, never sent on the wire) or it opens a turn; dedup user text only via `user_text_matches(kind=...)` (injected copies by `_injection_id`). `_continuation` nudges are legacy and read-only: never mint one.
- **Injections** (`service/agent_middleware/injection.py`; drain/retry-replay contract in its docstring): an injection that misses the run is drained at finalize as `consumed=False` and returned to the input box — a finished `agent.run()` is terminal; never add a follow-up run to deliver it. A steer (`UserMessage`/`UserInject` `steer=True`; the default queues before the next call) queues the message and aborts its pass while that pass is steerable — from the attempt's start until a final answer with no tool call lands (`KernelConversation.steer`/`answer_landed`); otherwise it is only queued. Acceptance latches `AbortCause.STEER` before the sub-agent cascade, with no `await` after the check, and the cause stands: a later cancel only keeps the message unsent, a Stop ends the turn once the pass settled. The runner's pass loop (`runner.py::_run_passes`) settles the pass inside the turn (`finalizer.py::settle_steered_pass`: repair, drop and withdraw the trailing answer, retire the recorder, persist barrier) and, unless stopped or shutting down since, runs a `CONTINUE` pass whose first call drains the message — no marker, FSM step, save, hook or `TurnStarted` between; the bindings publish `InvocationSteered` instead of finishing the content `interrupted`, and the TUI and ACP bridge end the pass's tool calls still open on it (no result follows them).
- **Trajectory**: recording never blocks a user-visible path and never precedes the commit it describes. `EventDraft` takes its timestamp at construction but its sequence at emit: build each draft at its emit site.

## Persistence
- Config/data dir (`<config_dir>`): `~/.chrys` (macOS/Linux), `%APPDATA%/chrys` (Windows). Sessions live in `<session_root>/sessions/<short-id>/`; `<session_root>` is `CHRYS_SESSION_ROOT_DIR` / `storage.session_root_dir` (the PARENT of `sessions/`; restart-only, not project-settable), defaulting to `<config_dir>`. Open files under `get_platform().config_dir` and `resolve_sessions_dir()` (real paths: the owner-only file helpers refuse a link anywhere on a path), never the as-named `conventional_config_dir()` (only code acting on the entry itself, like the uninstaller, wants it). `session_dir("")` is the sessions ROOT: reject empty ids before any delete or rmtree.
- Per session: `session.json`, `session.json.bak` and the crash sidecar `session.recovery.json`; `<session_root>/sessions/.locks/<short-id>.active.lock` marks the one owning process. The sidecar is written mid-turn, deleted by every primary save and never part of the `.bak`/snapshot heal chain; a reader considers it only with `prefer_recovery=True`, after owning the active lock or finding it unheld, and it wins when newer than the primary or when the primary is missing/unreadable.
- Fork copies the whole session dir: a new per-session file that embeds the session id or absolute paths needs handling in `service/state/_fork.py`.
- Startup restore (`-s`) is transactional: it succeeds only once the matching `SessionRestored` is observed (a normal return proves nothing; see EventBus). On failure run `engine.reset_after_failed_startup_restore()` (tears down with saves suppressed) and the screen's `cancel_startup_session_restore()` before the fallback start.

### Structure

### Text & styles

### Performance — restyle and layout cost grows with the mounted transcript
- GC tuning cannot fix that cost. Focus/blur, overlay open/close, binding changes and small-panel toggles must not restyle, recompose or relayout MainScreen; setters are idempotent and emit nothing for unchanged values. Modal first-open work stays screen-local, with heavy I/O after the loading shell paints; covered MainScreen widgets never recompose behind overlays.
- Hide with `widget.display = False/True`, not `-hidden` classes, `visibility` or shadow flags; hot fixed chrome uses `app/tui/util/visibility.py::set_widget(s)_visibility_without_layout`. Labels whose text changes often: fixed width + `update(..., layout=False)`.
- Keep the version-gated `ChrysApp._load_screen_css` and scoped Screen selectors; add no dynamic/global CSS loading without a populated-transcript regression test. A theme change is the one global pass: fold class changes into it with `update_classes(..., update=False)`; a theme flip repaints, never recomposes.
- Never call `refresh_bindings()` unconditionally. `ChrysFooter` recomposes only on a real signature change while its owning Screen is current; that Screen calls `sync_bindings()` in `on_screen_resume()`.
- Large-history replay plans detached, precomposes the widget forest and mounts in bounded batches, never per-entry mount/layout. `ChatPanel.mount_transcript_widgets` returns once the newest ~3 viewports are mounted; `app/tui/widgets/chat/replay_mount.py` then prepends older entries in the background (invariants in its docstring): transcript readers splice in `pending_transcript_widgets()` directly above `transcript_entry_after(<last pending>)`, and tests await `ChatPanel.wait_replay_complete()` before reading the whole transcript.
- Periodic timers on always-mounted widgets `pause()` on Hide and `resume()` on Show; a widget mounted inside a hidden container never gets Show, so its first tick pauses the timer (templates `ChrysLoadingIndicator`, `BuddyPanel`; add a parked-while-hidden test). Out-of-process polling (buddy reload) may keep ticking. Paint gates use `is_widget_shown_on_active_screen()`, never `is_on_screen` (it re-arranges the screen whenever the compositor map was invalidated).
- A retained `Thread` object pins the App (`Thread.__init__` keeps `sys.stderr`, the App's print capture).
- Streaming is per-delta work and must stay throttled while always landing the last state, as `StreamedMarkdownMessage` (`app/tui/widgets/chat/messages.py`) and the status bar are.
- The chat panel's one-shot pull to the bottom when terminal content lands (final answer, error/interrupt/retry banner) is deliberate even after the user scrolled up (`app/tui/widgets/chat/scroll_controller.py`).

### Textual traps (Textual pinned at 8.2.7)
- Dispatch runs one named handler (plus `@on` handlers) per MRO class — private `_on_x` beats `on_x` — and checks `prevent_default()` only between classes; `event.stop()` only stops bubbling. Overriding a handler and calling same-name `super()` runs the base twice unless you `prevent_default()` first — also when you perform the base action by hand (`super().press()`). Click-consuming pseudo-buttons call `prevent_default()` and `stop()` (use `ClickAffordance`). Watchers differ: plain attribute lookup, and both `_watch_x` and `watch_x` run.
- Code any cancellable task can run (workers, spawned tasks, EventBus handlers, which run inside the publishing engine task) removes widgets via `app/tui/util/removal.py`: a cancelled removal leaves zombie widgets and kills the App's message loop.
- Rebuilds: async handler, await the removal, then one `await mount(*widgets)`; in a scroll container wrap both in `app.batch_update()` or `scroll_y` clamps to 0. Pruning parents drop mounts silently: return the real attachment; recheck prerequisites after taking structural locks. During Screen removal or App shutdown `is_mounted` (and `is_attached` before `exit()`) stay True while `mount()` no-ops: deferred callbacks bail on `not app.is_running`/`_closing`/`_pruning`. Before removing a focused subtree, `set_focus(stable, scroll_visible=False)`, or Textual's refocus animation overrides your scroll.
- `widget.prevent(...)` shares one App-wide stack: held across an `await` it drops that message type everywhere — use `app/tui/util/message_gate.py::messages_disabled`.
- `call_later`/`call_after_refresh` return False when rejected (release pending state); `call_after_refresh` runs on the TOP screen once it idles, possibly before a just-shown widget has a size. Unsubscribing a Signal doesn't cancel queued deliveries: fence stale callbacks with a generation, or unsubscribe, enqueue a same-pump barrier with no `await` in between, check it was accepted, then await it.
- `dismiss()` resolves the future, queues the result callback, then pops whatever screen is on TOP: guard with `screen is app.screen`; cleanup follows resource ownership, not callback timing.
- A live TextArea owns its draft: never write back a draft snapshot taken before an `await` (it clobbers newer input, whitespace included); `load_text()` resets the cursor.
- CSS: scoped `DEFAULT_CSS` rules that don't start with the defining class match only its descendants; non-default stylesheets beat `DEFAULT_CSS` even with `!important`; Screen `CSS` is scoped, `CSS_PATH` is not. Never define `_running` on a widget (it's `MessagePump`'s).
- `foundation/patches/` patches Textual: file patches rewrite the dev venv's site-packages at bootstrap, while CI runs stock Textual plus only the runtime patches `tests/conftest.py` applies — tests never import patch-added symbols. A Textual bump re-verifies every patch and every adapter over Textual privates (`app/tui/app.py`, `toasts.py`, `themes/preview.py`, `screens/main/screen.py`, `util/visibility.py`, `widgets/chrome/draft_text_area.py`'s undo/redo field replay, …; some silently no-op off the pinned version).

### GC freeze
- The TUI `gc.freeze()`s stable objects at idle points (`app/tui/support/gc_freeze.py`). Freeze actions are hard-gated on `AgentEngine.is_turn_lifecycle_active` (through session save and after-turn hooks), never the earlier FSM/UI idle flags; to wait for one turn's save, keep that turn's `turn_lifecycle_task`.
- A renderer that mounts substantial stable content after the turn's UI completes posts `GcAbsorbRequested(STABLE_CONTENT_MOUNTED)` after its final update; removing a large stable subtree posts idle `GcReclaimRequested(STABLE_CONTENT_REMOVED)` after the awaited removal.
- Cache-heavy permanent surfaces implement `GcFreezeParticipant` and register in `MainScreen._gc_freeze_participants`; transcript widgets with cyclic LRUs join `ChatPanel._gc_freeze_render_cache_surfaces`; anything else must fit the retained-byte budget `scripts/calibrate_gc_freeze.py` measures.

## Testing rules
A guard that can't go red is worse than none — it is believed. Check `tests/support/` before writing any wait, fake, fixture or path helper.

### Guards
- A new AST hygiene rule goes in a `tests/architecture/test_hygiene_*.py` family module; focused non-AST guards are standalone `tests/architecture/test_*.py`. Prove each new guard goes red under the real `-n 8` addopts, not only pytester `-n0`. Guards target what ordinary code would slip past, not deliberately adversarial code.

### Waits (`tests/support/waiting.py`)
- Positive waits use `wait_for(...)`; `wait_until` only when its bool is asserted or branched on (the AST guard catches only a bare `await wait_until(...)` statement), e.g. a bounded absence check `assert not await wait_until(...)`. No fixed sleeps or `range(...)`/`pilot.pause()` polling, even with `break`; `asyncio.sleep(0)` may force a known interleaving, never signal readiness.
- A producer that can fail early: wait for `ready.is_set() or task.done()`, await a finished task to surface its error, then assert readiness.
- Race tests: waiting for the event can close the very window under test — start A as a task, assert `not task.done()`, then release B; judge background work by its task handle, not a bool. Mid-run signal tests (interrupt/inject/approval) first prove the run is in flight: a tool the test holds (awaiting an `asyncio.Event` it releases later) plus a call-count gate — `slow_echo_tool` only sleeps `delay` (default 0).
- Budgets: engine turns and any wait whose window cold-starts a process (interpreter probe, workflow preview or run worker, hook command) pass `ENGINE_TURN_TIMEOUT` (15 s; a loaded Windows runner spends seconds per start); a wait whose window builds the TUI main screen passes `MAIN_SCREEN_BUILD_TIMEOUT` (10 s). pytest-timeout kills a test at 60 s, after `faulthandler_timeout` (55 s) dumps every stack. Serial waits share one budget via `@with_wait_deadline(ENGINE_TEST_WAIT_TIMEOUT)` (45 s from test-body entry; bounds `wait_for`/`wait_until_quiet`/`await_run_task_chain`, not `wait_until` or raw `asyncio.wait_for`), otherwise a module `pytest.mark.timeout` with a reason. Default budgets stay strictly below the per-test timeout; count production fixed sleeps inside the path (ACP connect backoff starts at 3 s); never platform-scale a budget or raise one to fix a flake.
- Fake time or sleep by stubbing the module under test's own `asyncio`/`time` name through a shadow `ModuleType`, never the stdlib module: a non-yielding global `asyncio.sleep` starves `waiting.py`, and the event loop reads `time.monotonic`.
- A task that can't finish cancelling hangs pytest-asyncio's `Runner.close()` in teardown, possibly with no usable timeout output: `kill -ABRT <pid>` gets the stacks. A 55 s dump whose loop thread is busy computing (e.g. `refresh_css`) is CPU slowness, not deadlock — split the scenario.

### Completion & ownership
- Read post-run engine state only after `await await_run_task_chain(engine, turn_state=engine.turns.turn_state)` (`tests/support/waiting.py`): model call counts mark request START, and final frontend events may precede persistence.
- Everything a test starts — task, thread, worker, timer, signal subscription, subprocess — has an owner and deterministic teardown; never go green by globally quiescing or detaching the production path under test. Prove a child was reaped with a `psutil.Process` captured while alive (`not proc.is_running()`), never `pid_exists`.
- Keep ≥1 engine-driven test per kernel↔middleware contract (tool-loop reminder enrichment, profile switch); porting one to direct middleware calls under the same name deletes coverage.

### Textual
- Pilot `pause`/`press`/`click` drain handler-posted messages (autouse `_settled_pilot_waits`, `tests/support/pilot_barrier.py`), not workers, tasks, timers or update-timer layout: `wait_for` the asserted state (after `push_screen`, `isinstance(app.screen, X) and app.screen.is_mounted`). Click with `tests/support/tui_helpers.py::click_when_settled` and resize with `resize_when_settled`.
- Arm no-layout/no-restyle spies only after `screen_is_settled(app, screen)`, not `_layout_required`. Performance regressions need a real `run_test()` (`tests/support/tui_app_harness.py::make_chrys_app`) with a populated transcript and real events; spies prove MainScreen `update_node_styles`/`_refresh_layout` and Footer recompose are not called (example: `tests/app/tui/screens/test_editor_dialog.py::test_populated_main_screen_editor_overlay_does_not_restyle_recompose_or_relayout`). Handler-direct unit tests don't count.
- Handler plans are cached per class on first dispatch and reset only between tests: patch a handler through a fresh local subclass before dispatch (instance spies are bypassed), and pair negative handler assertions with a positive control.
- `Static.render()` returns a Visual: use `rich_plain`/`rich_segment_lines`. Under `run_test()` stdout looks like a tty, so assertion consoles need `Console(force_terminal=False, _environ={})`; `rstrip()` style-padded cell text before `(text, style)` compares. Windows CI detects 256 colors: pin `app.console._color_system` in color assertions (`TEXTUAL_COLOR_SYSTEM=256` reproduces). `Input` selects all on focus: set the selection explicitly in typing tests.
- Harness Apps outside `tests/app/tui` need `TuiVariableDefaultsMixin` (`app/tui/theme.py`); a harness overriding theme variable defaults merges the mixin's, never replaces them. For recoverable workers use `exit_on_error=False` and own `worker.wait()` errors (a default worker failure exits the App).

### Isolation (installed by `tests/conftest.py` — don't redo or undo it)
- Every test starts in its own empty cwd (reach repo files via `__file__`); the session root is always per-test temp, and so is the config/data dir unless `@pytest.mark.real_config_dir`; exported Chrys setting env vars are stripped; the locale is English. A test that spawns a subprocess must also point `HOME`/`USERPROFILE`/`APPDATA` at temp, or the child writes the real `~/.chrys`.
- Env via `monkeypatch.setenv`/`monkeypatch.context()`, never raw `os.environ[...]` writes (runtime guard) or mid-test `.undo()` on the shared fixture. `delenv` on an absent var records nothing: `setenv` it first so teardown removes whatever the code under test sets. Outside fixture lifetime, own a `pytest.MonkeyPatch()` and undo it in teardown. When a constant or helper moves modules, re-point every `monkeypatch.setattr(old_module, ...)` (if the old module still re-exports the name, patching it there silently does nothing).
- Non-loopback egress needs `@pytest.mark.integration`; the runtime guard misses subprocesses, reverse DNS and Windows proactor connects.
- Git: `git_repo_factory` (hand-rolled repos race `git maintenance`). Servers bind port 0 and hand over the listening socket or a polled port file; a stopped-server test keeps a bound, non-listening socket; never probe a free port and reconnect.
- Plant files the product opens owner-verified with `tests/support/secure_files.py`, never `Path.write_bytes`. Probe filesystem semantics (case, symlinks via `symlink_or_skip`, separators, newlines) instead of assuming them, and decide whether a path value is raw filesystem identity, Git POSIX path, serialized identity or display text before comparing.
- xdist: parametrize values and ids must be identical on every worker (no pid, random, time or set order). Ruff ASYNC covers tests: run blocking setup through `asyncio.to_thread`.

### Evidence
- Flake fix = the causal mechanism plus a deterministic reproducer (scheduling or fault injection) that fails before and passes after; without a seam, record platform, worker topology, seed and stress runs (oversubscribed xdist reproduces CI-load races). Scan and report same-shape sites. CI prints a stall report for failed or ≥25 s tests (`CHRYS_TEST_STALL_DIAGNOSTICS=1` locally) — read it first.
- `@pytest.mark.quarantine(reason="<owner/issue>: <failure signature>", expires="YYYY-MM-DD")` only for confirmed flakes, never repeated deterministic failures; it is a non-strict xfail that hides new failure modes, so review its results.
- Doubles: `autospec`, a typed Protocol or an explicit signature; no catch-all `**kwargs`. When merging fakes or parametrizing, keep absent attributes and omitted args absent and comparisons exact (`is True`, whole dict): the absence is what's tested.
- A symbol grep or a green helper test is not coverage: trace the production path and test the boundary the data actually crosses. Fix an invariant as a class — enumerate every site that writes the protected state, not only the reported one.
